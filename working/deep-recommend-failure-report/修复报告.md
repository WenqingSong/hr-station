## 一、修复摘要（TL;DR）

**根因**（来自定位报告）：`.env` 中 `LLM_PROVIDER=hy3` 且 `LLM_BASE_URL`/`LLM_HY3_BASE_URL` 指向 LKEAP，而实际 token 属于 TokenHub，导致「TokenHub token + LKEAP 端点」鉴权失败（401），三条深度推荐 LLM 链路全部失败，叠加 `ENABLE_MOCK_AGENT=false` + `LLM_FALLBACK_ENABLE=false` 的「不兜底」配置，最终返回 500。

**本次修复分两层：**

1. **配置层（根因修复，必须）**：`LLM_PROVIDER` 由 `hy3` → `tokenhub`，`LLM_BASE_URL` 指向 `https://tokenhub.tencentmaas.com/v1/chat/completions`，使 token 平台与调用地址匹配。
2. **代码层（防误判，值得一并修复）**：把 401/403 的错误码从 `LLM_API_KEY_MISSING`（「Key 缺失」）纠正为新增的 `LLM_AUTH_FAILED`（「鉴权失败」），避免日志与告警再次把「平台不匹配」误判为「Key 无效」——这正是定位报告「第一版误判为 API Key 失效」的直接诱因。

## 三、为什么这样修改（逻辑）

### 3.1 配置修复逻辑

依据 `main.go#newLLMClient`：

```go
switch provider {
case "hy3":
    c, _ := llm.NewHy3Client(cfg, nil)   // LKEAP 专用客户端
default:
    c, _ := llm.NewHunyuanClient(cfg, nil) // OpenAI 兼容客户端
}
```

- `hy3` 走 `Hy3Client`，使用 `LLM_HY3_BASE_URL`（LKEAP 地址），并向请求体注入 LKEAP 特有的 `extra_body.chat_template_kwargs.reasoning_effort`。
- `tokenhub` 走 `HunyuanClient`（OpenAI 兼容），使用 `LLM_BASE_URL`，发送标准 OpenAI 请求体。

定位报告实测：同一 token 在 `tokenhub.tencentmaas.com` 返回 200，在 LKEAP 返回 401；且 `Hy3Client` 向 TokenHub 发送 `reasoning_effort=high` 会触发超长 reasoning 导致超时。因此**首选切换为 `tokenhub`**（而非把 hy3 地址指向 TokenHub），既修正了端点又规避了 reasoning_effort 超时问题。

### 3.2 错误码修复逻辑

原 `errorFromHTTPStatus`/`HunyuanClient` 把 401/403 映射为 `LLM_API_KEY_MISSING`，语义是「Key 缺失/为空」。但本次事故中 Key 是**存在且有效**的，只是「Key 平台 ≠ 端点平台」。错误的命名会让运维/告警把「鉴权失败」误读为「忘记配 Key」，延误排障（第一版报告即因此误判）。

修复方式：
- 新增独立错误码 `LLM_AUTH_FAILED`，语义为「已提供 Key 但鉴权被拒（无效/过期/平台不匹配）」。
- 401/403 统一映射到 `LLM_AUTH_FAILED`。
- `LLM_API_KEY_MISSING` 保留（向后兼容），语义回归「Key 为空」。

错误码在 fallback 决策链中的流转已同步：

```
llm 包(401/403) → ErrLLMAuthFailed
    → agent/pipeline/types.go#mapLLMErrorCodeToPipeline   → pipeline.ErrLLMAuthFailed
    → agent/pipeline/types.go#mapLLMErrorCodeToFallbackReason → pipeline.FallbackLLMAuthFailed
    → IsDirectMockFallback(ErrLLMAuthFailed) = true（直接走兜底，不触发 JSON repair）
```

```bash

  -H 'Content-Type: application/json' \
  -d '{"model":"hy4-preview","messages":[{"role":"user","content":"hi"}],"stream":false}'
```

或在后端日志确认不再出现 `[LLM-Hy3] http 401` / `LLM_API_KEY_MISSING`，改由 `HunyuanClient` 路径正常返回。
