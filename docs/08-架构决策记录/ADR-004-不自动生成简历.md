# ADR-004 不自动生成简历

## 状态

已接受

## 背景

在 AI 辅助求职场景中，一个核心问题是：AI 是否应该替用户生成或重写优化版简历？

两种选择：

1. AI 生成优化版简历：系统根据分析结果，自动生成一份优化后的简历文本
2. AI 只给分析和建议：系统指出问题和改进方向，用户手动修改

## 决策

系统**不提供自动生成优化版简历**的能力。系统只提供：

1. 匹配度评分
2. 初筛判断（是否可能通过初筛）
3. JD-简历证据链（逐条对照）
4. 表达风险提示（模糊描述、空洞经历）
5. P0 / P1 优化建议（具体到原文位置）
6. 下一步行动建议

用户根据建议手动修改简历，通过"添加新版本"提交修改后的内容。

## 原因

1. **保护求职真实性**：AI 生成的简历可能虚构或夸大经历，违反求职诚信原则
2. **避免 AI 虚构经历**：AI 可能生成看似合理但实际不存在的经历描述，误导招聘方，损害用户长期利益
3. **更符合真实求职伦理**：求职者应对简历内容的真实性负责，AI 辅助应该是"诊断"而非"代写"
4. **更突出产品核心价值**：强调"诊断 + 迭代"而不是"代写"，差异化更明显
5. **降低法律风险**：AI 代写简历可能涉及虚假陈述的法律风险

## 产品表现

### 系统会做的

| 行为 | 说明 |
|------|------|
| 指出简历中模糊/空洞的描述 | "该项目经历缺少量化成果" |
| 建议如何更具体地描述经历 | "建议补充项目人数、使用技术、量化指标" |
| 提供表达优化方向 | "将'参与了xxx'改为更具体的角色描述" |
| 识别 JD 中未覆盖的要求 | "岗位要求 Spring Boot，简历未提及" |
| 标注 P0/P1 优先级 | "P0：补充量化成果；P1：调整技能排序" |

### 系统不会做的

| 行为 | 说明 |
|------|------|
| 直接生成优化版简历文本 | 不输出改写后的完整段落 |
| 替用户编造不存在的经历 | 不建议添加用户未提及的经历 |
| 润色或美化用户的表达 | 不改变用户的原始措辞 |
| 自动填充缺失字段 | 不代写用户未填写的部分 |

## 技术影响

- **匹配分析 Agent**：输出结构为建议列表，不包含改写后的文本
- **优化建议格式**：必须包含原文位置、问题描述、改进方向，不包含改写结果
- **版本对比**：展示用户手动修改的内容，而非 AI 生成的内容
- **Prompt 设计**：明确禁止生成具体改写文本，只允许分析问题

## 风险控制

| 风险 | 控制措施 |
|------|---------|
| LLM 偶尔输出改写文本 | Prompt 中明确禁止，输出格式校验 |
| 用户期望一键优化 | 产品文案明确"诊断不代写"，引导手动修改 |
| 建议过于笼统 | 要求建议具体到原文位置，给出改进方向 |

## 后续可扩展方向

- 提供"表达优化示例"（非用户简历内容，而是通用示例）
- 支持"参考表达"（给出同类型的优秀表达参考，但不直接替换）
- A/B 测试：对比"仅建议"与"提供示例"的用户满意度
