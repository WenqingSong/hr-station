# ADR-002 单主简历设计

## 状态

已接受

## 背景

在求职场景中，用户可能需要针对不同岗位方向准备不同版本的简历。常见做法有：

1. 多简历并行管理：用户可创建多份独立简历
2. 单主简历 + 版本迭代：用户维护一份主简历，通过版本记录优化过程

## 决策

采用**单主简历 + 版本迭代**设计：

- 用户只有一份主简历
- 版本通过 V1 → V2 → V3 管理
- 历史版本只读，不可编辑、不可删除
- 新版本通过"添加新版本"操作创建

## 原因

1. **降低复杂度**：多简历管理增加 UI（简历列表、切换、删除）和数据模型（简历分组、标签）复杂度
2. **主线更清晰**：用户只关注一条优化主线，不会在多份简历间迷失
3. **更容易展示持续迭代**：版本时间线直观展示优化历程，匹配度变化趋势一目了然
4. **有利于版本对比**：单主线对比 V1 vs V2 vs V3，无需处理跨简历对比
5. **MVP 简化**：Demo 阶段聚焦核心闭环，避免功能蔓延

## 影响

- **数据模型简化**：不需要简历分组、标签、切换逻辑
- **用户路径更清晰**：不需要选择"当前编辑哪份简历"
- **版本对比更自然**：同一简历的 V1 vs V2，语义清晰
- **前端状态管理简化**：不需要维护多简历选择状态

## 不做事项

| 不做 | 说明 |
|------|------|
| 多份简历并行管理 | 不支持创建/切换多份简历 |
| 删除历史版本 | 版本一旦创建，不可删除 |
| 编辑历史版本 | 历史版本只读，只能创建新版本 |
| 覆盖旧版本 | 每次修改产生新版本号，不覆盖 |

## 后续可扩展方向

- 通过版本标签实现"多方向简历"：给 V1 标记"后端方向"，V2 标记"前端方向"
- 支持从某个历史版本派生新版本
- 多简历管理（如产品迭代需要）
