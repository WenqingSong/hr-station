# ADR-002 单主简历设计

## 当前状态

已决策

## 决策

用户只维护一份主简历，支持多版本迭代，但不支持同时维护多份不同简历。

## 原因

1. **降低复杂度**：多简历管理增加 UI 和数据模型复杂度
2. **聚焦核心路径**：校招场景下，用户通常针对一个方向准备简历
3. **版本迭代替代**：通过版本管理实现不同方向的简历变体
4. **MVP 简化**：先做核心闭环，后续可根据需求扩展

## 影响

- 数据模型简化，不需要简历分组/标签
- 用户路径更清晰
- 后续如需支持多简历，可通过版本标签实现
