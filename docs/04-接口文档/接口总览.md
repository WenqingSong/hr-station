## API 基础信息

- **Base URL**：`/api/v1`
- **认证方式**：JWT Bearer Token（阶段 3 实现）
- **响应格式**：JSON
- **统一响应结构**：阶段 2-3 ✅ 已确立

## 统一响应格式（阶段 2-3 ✅ 已确立）

### 成功响应

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

### 错误响应

```json
{
  "code": 40001,
  "message": "invalid parameter",
  "data": null
}
```

### 当前 /healthz 响应示例

数据库正常时：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "service": "offer-catcher",
    "env": "local",
    "app": "ok",
    "database": "ok"
  }
}
```

数据库不可用时：

```json
{
  "code": 0,
  "message": "degraded",
  "data": {
    "service": "offer-catcher",
    "env": "local",
    "app": "ok",
    "database": "unavailable"
  }
}
```

说明：

1. 当前仍只有 `/healthz` 接口
2. `app` 表示 Go 服务自身是否正常
3. `database` 表示 MySQL Ping 是否正常
4. 数据库正常时 `message=ok`，数据库不可用时 `message=degraded`
5. 开发阶段数据库不可用时仍返回 HTTP 200
6. 不暴露数据库底层错误给前端
7. 阶段 3 才新增业务接口

阶段 3 后所有业务接口都必须返回统一响应格式。
