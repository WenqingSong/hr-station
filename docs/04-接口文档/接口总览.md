# 接口总览

> 最后更新：2026-05-28（阶段 2-3 实现统一响应结构与错误处理基础）

## 当前状态

阶段 2 已实现 `/healthz` 健康检查接口，且已使用统一响应格式。阶段 2 不新增业务接口。阶段 3 才实现认证、简历、岗位、推荐、匹配接口。

## 阶段 2 接口范围

| 接口 | 方法 | 说明 | 阶段 |
|------|------|------|------|
| `/healthz` | GET | 健康检查（阶段 1 已实现，2-3 已使用统一响应，2-6 增强） | 阶段 1/2 |

阶段 2 不新增业务接口。

## API 基础信息

- **Base URL**：`/api/v1`
- **认证方式**：JWT Bearer Token（阶段 3 实现）
- **响应格式**：JSON
- **统一响应结构**：阶段 2-3 ✅ 已确立

## 统一响应格式（阶段 2-3 ✅ 已确立）

### 成功响应

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

### 错误响应

```json
{
  "code": 40001,
  "message": "invalid parameter",
  "data": null
}
```

### 当前 /healthz 响应示例

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "status": "ok",
    "service": "offer-catcher-server"
  }
}
```

阶段 3 后所有业务接口都必须返回统一响应格式。
