## 9. 4-5.1 模拟 LLM / 异常场景验收矩阵

| 场景 | 验收方式 | 预期状态 | 预期 meta |
|------|---------|---------|----------|
| LLM success | fake pipeline success | 正常结果 | generated_by=llm_agent, agent_status=success |
| JSON repair success | malformed 可修复 | 正常结果 | agent_status=repaired, repair_applied=true |
| JSON repair failed | malformed 不可修复 | fallback 结果 | agent_status=fallback, fallback_reason=json_repair_failed |
| schema invalid | fake schema invalid | fallback 结果 | agent_status=fallback, fallback_reason=schema_invalid |
| LLM error | fake LLM error | fallback 结果 | agent_status=fallback, fallback_reason=llm_error |
| LLM disabled | llmEnabled=false | mock 结果 | agent_status=mock_success, generated_by=mock_agent |
| pipeline error | fake pipeline error | fallback 结果 | agent_status=fallback, fallback_reason=pipeline_error |

说明：
- 4-5.1 所有验收使用 fake/mock 测试，**不需要真实 LLM**
- 三类 Agent 均需覆盖上述 7 种场景
- 已有 `agent_pipeline_integration_test.go` 覆盖部分场景，4-5.1 需补齐 schema invalid 和 pipeline error 场景

## 10. 4-5.2 真实 LLM 最小 Smoke 规则

**4-5.2 默认不调用真实 LLM。只有用户明确确认后，才允许执行 `RUN_REAL_LLM_SMOKE=1 make llm-smoke`。**

冻结规则：

1. 不读取或输出 `.env`
2. 不输出 API Key
3. 不大规模调用
4. 只做最小 smoke
5. 优先只调用 LLM Client health / 最小 MatchAnalysis
6. 调用结果只记录成功 / 失败 / 错误类型，不记录敏感响应
7. 若未配置 Key，4-5.2 可记录为 **skipped**，不阻塞进入前端 Mock 演示，但要标记"真实 LLM 未现场验证"
