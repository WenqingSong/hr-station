# 接口接入说明

## 1. 接入目标

- 创建统一 API Client，所有接口调用经过统一封装
- 环境变量管理 API 地址，便于切换开发/生产环境
- 页面先按真实接口结构接入，后端未就绪时使用 Mock 兜底
- 统一 Loading / Error / Empty 状态处理

## 2. API Client 设计

### 目录结构

```
web/src/api/
├── client.ts       # axios 实例，baseURL 从环境变量读取，含拦截器
├── types.ts        # 通用响应类型（ApiResponse<T>、PageResult<T>）
└── modules/
    ├── auth.ts     # 认证接口
    ├── resume.ts   # 简历接口
    ├── jobs.ts     # 岗位接口
    ├── recommendation.ts  # 推荐接口
    └── match.ts    # 匹配分析接口
```

### client.ts 核心设计

```typescript
// 统一响应格式
interface ApiResponse<T> {
  code: number;
  message: string;
  data: T;
}

// axios 实例
const client = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL,
  timeout: 10000,
});

// 请求拦截器：自动添加 Token
client.interceptors.request.use((config) => {
  const token = localStorage.getItem('token');
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

// 响应拦截器：统一错误处理
client.interceptors.response.use(
  (res) => res.data,
  (error) => {
    if (error.response?.status === 401) {
      // 跳转登录
    }
    return Promise.reject(error);
  }
);
```

## 3. 环境变量

### 开发环境 `.env.development`

```env
VITE_API_BASE_URL=http://localhost:8080/api
```

### 生产环境 `.env.production`

```env
VITE_API_BASE_URL=/api
```

### 使用方式

```typescript
const baseURL = import.meta.env.VITE_API_BASE_URL;
```

## 5. Mock 数据策略

### 策略：先按真实接口结构接入

1. **定义 TypeScript 类型**：按照后端规划的接口结构定义类型
2. **创建 API 函数**：函数签名和返回类型与真实接口一致
3. **Mock 兜底**：后端未就绪时，API 函数内部返回 Mock 数据
4. **无缝切换**：后端就绪后，只需删除 Mock 逻辑，不需要改页面代码

### Mock 实现方式

```typescript
// web/src/api/modules/resume.ts
import { client } from '../client';
import type { Resume, ResumeDetail, VersionList } from '../types';

const USE_MOCK = !import.meta.env.VITE_API_BASE_URL;

export async function getCurrentResume(): Promise<ApiResponse<Resume>> {
  if (USE_MOCK) {
    return { code: 0, message: 'success', data: MOCK_RESUME };
  }
  return client.get('/resumes/current');
}
```

### Mock 数据来源

- 从现有页面组件中提取硬编码数据
- 统一放入 `web/src/api/mocks/` 目录
- 数据结构需与后端规划一致

## 6. Loading / Error / Empty 状态

每个有数据请求的页面都需要处理三种状态：

| 状态 | 组件 | 触发条件 | 展示内容 |
|------|------|---------|---------|
| Loading | LoadingState | API 请求中 | Spinner / Skeleton |
| Error | ErrorState | API 返回错误 | 错误信息 + 重试按钮 |
| Empty | EmptyState | 数据为空 | 引导文案 + 操作按钮 |

### 页面状态处理模式

```tsx
function ResumePage() {
  const { data, loading, error } = useApi(getCurrentResume);

  if (loading) return <LoadingState />;
  if (error) return <ErrorState message={error.message} onRetry={refetch} />;
  if (!data) return <EmptyState title="暂无简历" action="添加简历" onClick={...} />;

  return <ResumeContent data={data} />;
}
```

## 7. 鉴权处理

### Token 管理

| 操作 | 实现 |
|------|------|
| 存储 | 登录成功后将 JWT 存入 `localStorage` |
| 携带 | axios 请求拦截器自动添加 `Authorization: Bearer <token>` |
| 过期 | 响应拦截器检测 401，跳转登录页 |
| 清除 | 退出登录时清除 localStorage |

### Demo 阶段鉴权

- 提供示例账号（前端硬编码或后端种子数据）
- 登录页展示"使用示例账号"按钮
- 后端不做过复杂鉴权，JWT 有效期适当延长

## 8. 后续实现顺序

1. 安装 axios
2. 创建 `web/src/api/client.ts`
3. 定义 TypeScript 类型（`web/src/api/types.ts`）
4. 创建各模块 API 函数
5. 从页面组件中提取 Mock 数据到 `web/src/api/mocks/`
6. 页面中替换硬编码为 API 调用
7. 添加 Loading / Error / Empty 状态
8. 后端就绪后关闭 Mock 开关
