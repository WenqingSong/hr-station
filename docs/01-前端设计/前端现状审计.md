# 前端现状审计

> 基于 2026-05-28 阶段 0-1 只读审计结果，阶段 0-4 补充完善

## 1. 审计结论

前端页面已经具备**原型基础**，但当前不是工程化完成态。

- ✅ 页面组件齐全，覆盖产品规划中的所有核心页面
- ✅ 视觉风格已接近腾讯校招岗位内页风格
- ✅ 已有 Token 系统和基础组件封装
- ❌ 无真实路由，页面通过 useState 切换
- ❌ 无 API Client，所有数据硬编码在组件中
- ❌ 无全局类型定义，数据结构与组件耦合
- ❌ 无 Loading / Error / Empty 统一状态处理
- ❌ 无 tsconfig.json、无 lock 文件

**核心判断**：不需要重写视觉和页面，需要补路由、API Client、类型定义和状态管理。

## 5. 样式现状

| 维度 | 判断 |
|------|------|
| 设计风格 | ✅ 接近腾讯校招岗位内页风格（浅灰背景 `#F5F7FA`、白底卡片、蓝色主色 `#1D6FFF`） |
| Token 系统 | ✅ `tokens.ts` 定义完整，注释明确"风格基底：腾讯校招岗位内页" |
| 大 Banner / 营销首页 | ❌ 不存在，首页为功能入口卡片 |
| 卡片/按钮/导航统一性 | ✅ 统一使用封装组件 |

**样式问题**：

1. inline style 比重过大，不利于主题切换和响应式
2. shadcn CSS 变量与 `tokens.ts` JS 常量并存，颜色体系可能冲突
3. MUI 依赖冗余（已安装但未使用），增加包体积
4. `fonts.css` 和 `globals.css` 为空文件

**结论**：视觉风格已达标，后续改造要保持腾讯校招岗位内页风格，不建议重做视觉。

## 10. 后续改造方向

1. **不重写视觉**：保持腾讯校招岗位内页风格
2. **不重做页面**：在现有页面组件基础上改造
3. **优先补路由**：接入 react-router，实现真实 URL
4. **创建 API Client**：统一 axios 封装 + 环境变量
5. **定义类型**：统一 TypeScript 接口类型
6. **服务 Demo 主链路**：改造以"添加简历 → 推荐 → 匹配 → 迭代"闭环为优先
7. **Mock 兜底**：后端未就绪时使用 Mock 数据，前端先按真实接口结构接入
