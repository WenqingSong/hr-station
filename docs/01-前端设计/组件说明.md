# 组件说明

## 1. 组件拆分原则

1. **不为了组件化而组件化**：当前阶段不过度抽象
2. **优先抽取重复出现的模式**：卡片、标签、按钮、表格等多次使用的 UI 模式
3. **逐步整理**：Figma Make 生成代码结构混乱时，可逐步整理
4. **保持视觉一致**：统一使用 tokens.ts 中的设计 Token

## 7. 状态组件

| 组件 | 说明 | 使用场景 |
|------|------|---------|
| EmptyState | 空状态占位（图标 + 文案 + 操作按钮） | 无简历、无岗位、无分析记录 |
| LoadingState | 加载状态（Spinner / Skeleton） | API 请求中 |
| ErrorState | 错误状态（图标 + 错误信息 + 重试按钮） | API 请求失败 |

这三个状态组件是当前最缺的通用组件，每个有数据请求的页面都需要。

## 8. 后续改造建议

1. **先补状态组件**：EmptyState / LoadingState / ErrorState，优先级最高
2. **统一 Button/Card**：保留自定义版本，移除未使用的 shadcn 版本，避免导入混乱
3. **业务组件暂不提取**：当前阶段页面组件已可用，优先保证功能跑通
4. **逐步提取**：当多个页面出现相同 UI 模式时再提取
5. **移除 MUI**：确认未使用后从 dependencies 中移除
