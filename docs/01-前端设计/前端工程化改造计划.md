# 前端工程化改造计划

## 1. 改造目标

将 Figma Make 生成的前端页面改造成可运行、可路由、可接后端 API、可演示的正式前端工程。

```
Figma Make 原型页面
→ 工程化 React 前端
→ 有真实路由
→ 有统一 Layout
→ 有统一 API Client
→ 有统一类型定义
→ 有 Loading / Error / Empty 状态
→ 可连接 Go 后端
→ 可使用 Mock 数据兜底
→ 可完整演示 Demo 主链路
```

**核心原则**：不是重写全部前端，而是在尽量保留现有视觉和页面结构的基础上，完成工程化改造。

## 2. 当前问题

| 问题 | 严重度 | 说明 |
|------|--------|------|
| 无真实路由 | 🔴 高 | useState 切换页面，URL 不变，无法刷新/分享 |
| 无 API Client | 🔴 高 | 所有数据硬编码在组件中 |
| 无类型定义 | 🔴 高 | 数据结构与组件耦合，无独立 TypeScript 类型 |
| inline style 比重过大 | 🔴 高 | 不利于主题切换和响应式 |
| 无 Loading/Error/Empty | 🟡 中 | 页面缺少加载/错误/空状态处理 |
| 无统一 Layout | 🟡 中 | 无与路由绑定的布局组件 |
| 组件冗余 | 🟡 中 | Button/Card 自定义版与 shadcn 版并存，MUI 未使用 |
| 无 tsconfig.json | 🟡 中 | TypeScript 编译配置缺失 |
| 无 lock 文件 | 🟡 中 | 依赖版本不确定 |

## 3. 改造原则

1. **不重写页面**：保留现有页面组件和视觉
2. **不重做视觉**：保持腾讯校招岗位内页风格
3. **不改产品边界**：不增加新页面和新功能
4. **先跑通再优化**：优先保证 Demo 主链路可演示
5. **Mock 兜底**：后端未就绪时使用 Mock 数据
6. **渐进式改造**：按阶段推进，每阶段可验收

## 4. 改造阶段

```
第一阶段：路由与页面挂载
  ↓
第二阶段：统一 API Client
  ↓
第三阶段：类型定义与数据结构
  ↓
第四阶段：页面接入真实数据
  ↓
第五阶段：状态处理
  ↓
第六阶段：视觉与交互收敛
```

## 5. 第一阶段：路由与页面挂载

**目标**：实现真实 URL 路由，每个页面有独立 URL。

### 具体工作

| 序号 | 工作项 | 说明 |
|------|--------|------|
| 1 | 添加 tsconfig.json | TypeScript 编译配置 |
| 2 | 创建 AppLayout | 统一布局（顶部导航 + 内容区） |
| 3 | 配置 react-router | createBrowserRouter + RouterProvider |
| 4 | 页面组件挂载到路由 | 将现有页面组件挂到规划路由 |
| 5 | 创建 AuthGuard | 登录态保护组件 |
| 6 | 移除 useState 切换 | 删除 App.tsx 中的 useState 页面切换逻辑 |
| 7 | 移除底部浮动按钮 | 删除 Demo 预览用的浮动切换按钮 |
| 8 | 使用 useNavigate/Link | 替代手动页面切换 |

### 路由表

| 路由 | 页面组件 | 需登录 |
|------|---------|--------|
| `/login` | LoginPage | ❌ |
| `/` | HomeContent | ✅ |
| `/resume` | ResumePage | ✅ |
| `/resume/add` | AddResumePage | ✅ |
| `/resume/detail` | ResumeDetailPage | ✅ |
| `/resume/versions` | VersionsPage | ✅ |
| `/jobs` | JobsPage | ✅ |
| `/jobs/recommend` | RecommendPage | ✅ |
| `/jobs/match/:jobId` | MatchPage | ✅ |

### 验收标准

- 每个页面有独立 URL
- 刷新后保持当前页面
- 浏览器前进后退正常
- 未登录访问受保护页面跳转 `/login`

## 6. 第二阶段：统一 API Client

**目标**：创建统一 API 调用层，支持环境变量和 Mock 兜底。

### 具体工作

| 序号 | 工作项 | 说明 |
|------|--------|------|
| 1 | 安装 axios | 如未安装 |
| 2 | 创建 client.ts | axios 实例 + 拦截器 |
| 3 | 创建 types.ts | 通用响应类型 |
| 4 | 创建环境变量文件 | .env.development / .env.production |
| 5 | 创建各模块 API 函数 | auth.ts / resume.ts / jobs.ts / recommendation.ts / match.ts |
| 6 | 创建 Mock 数据目录 | 从页面组件中提取硬编码数据 |

### 验收标准

- 所有 API 调用经过统一 client
- 环境变量可配置 API 地址
- Mock 模式可切换

## 7. 第三阶段：类型定义与数据结构

**目标**：定义统一的 TypeScript 类型，与后端接口结构对齐。

### 具体工作

| 序号 | 工作项 | 说明 |
|------|--------|------|
| 1 | 定义简历相关类型 | Resume / ResumeDetail / ResumeVersion / Education / Work / Project |
| 2 | 定义岗位相关类型 | Job / JobDetail / Recommendation / MatchResult |
| 3 | 定义分析相关类型 | EvidenceItem / RiskItem / Suggestion / VersionCompare |
| 4 | 定义通用类型 | ApiResponse / PageResult / AuthToken / User |
| 5 | API 函数添加类型标注 | 返回值和参数使用定义的类型 |

### 验收标准

- 所有 API 函数有完整的 TypeScript 类型
- 页面组件使用类型定义替代 any

## 8. 第四阶段：页面接入真实数据

**目标**：将页面中硬编码的 Mock 数据替换为 API 调用。

### 具体工作

| 序号 | 页面 | 接入接口 |
|------|------|---------|
| 1 | 登录页 | login / register |
| 2 | 首页 | getCurrentResume / getLatestMatch |
| 3 | 我的简历页 | getCurrentResume |
| 4 | 添加简历页 | createResume |
| 5 | 简历详情页 | getResumeDetail |
| 6 | 版本迭代页 | getVersions / compareVersions |
| 7 | 岗位列表页 | getJobs / getJobDetail |
| 8 | 岗位推荐页 | getRecommendations |
| 9 | 匹配分析页 | matchJob |

### 验收标准

- 页面数据来自 API 调用（或 Mock 兜底）
- 无硬编码数据残留
- 接口字段与类型定义一致

## 9. 第五阶段：状态处理

**目标**：每个有数据请求的页面都有 Loading / Error / Empty 状态。

### 具体工作

| 序号 | 工作项 | 说明 |
|------|--------|------|
| 1 | 创建 EmptyState 组件 | 空状态占位（图标 + 文案 + 操作按钮） |
| 2 | 创建 LoadingState 组件 | 加载状态（Spinner / Skeleton） |
| 3 | 创建 ErrorState 组件 | 错误状态（错误信息 + 重试按钮） |
| 4 | 各页面添加状态处理 | 替换无数据时的硬编码展示 |
| 5 | 创建 useApi Hook | 统一封装 loading/error/data 状态 |

### 各页面空状态

| 页面 | 空状态触发 | 展示内容 |
|------|-----------|---------|
| 首页 | 无简历 | 引导添加简历 |
| 首页 | 无分析记录 | "暂无分析记录" |
| 简历页 | 无简历 | 引导添加简历 |
| 详情页 | 无简历 | 引导添加简历 |
| 版本页 | 只有 1 个版本 | "添加新版本后可对比" |
| 推荐页 | 无简历 | "先添加简历才能获得推荐" |
| 匹配页 | 无简历 | "先添加简历才能进行匹配" |
| 匹配页 | 无岗位 | "请先选择岗位" |

### 验收标准

- 所有页面有 Loading 状态
- 所有页面有 Error 状态（含重试）
- 所有页面有 Empty 状态（含引导操作）

## 10. 第六阶段：视觉与交互收敛

**目标**：修正样式一致性问题，优化演示链路。

### 具体工作

| 序号 | 工作项 | 说明 |
|------|--------|------|
| 1 | 移除 MUI 依赖 | 从 package.json 中移除 @mui/material 和 @mui/icons-material |
| 2 | 统一 Button/Card | 保留自定义版本，移除未使用的 shadcn 版本 |
| 3 | 收敛 inline style | 逐步迁移到 TailwindCSS 类或 tokens |
| 4 | 生成 lock 文件 | pnpm install 生成 pnpm-lock.yaml |
| 5 | 添加 ESLint + Prettier | 代码风格统一 |
| 6 | 优化 Demo 演示链路 | 确保主链路流畅，示例账号可用 |

### 验收标准

- 无冗余依赖
- 代码风格统一
- Demo 主链路可流畅演示

## 11. 不做事项

| 不做 | 说明 |
|------|------|
| 不重做 UI | 保持现有视觉风格 |
| 不改产品边界 | 不增加新功能 |
| 不增加新页面 | 不在规划之外新增页面 |
| 不增加岗位收藏 | 超出本期范围 |
| 不增加导出报告 | 超出本期范围 |
| 不增加投递追踪 | 超出本期范围 |
| 不增加面试模拟 | 超出本期范围 |
| 不做移动端优先适配 | 聚焦桌面端演示 |

## 12. 验收标准

### Demo 主链路验收

| 步骤 | 验收内容 |
|------|---------|
| 1 | 登录（示例账号） |
| 2 | 添加简历（部分字段填写） |
| 3 | 查看简历详情（AI 提取 + 风险） |
| 4 | 查看岗位推荐 |
| 5 | 选择岗位进入匹配分析 |
| 6 | 查看证据链 + 优化建议 |
| 7 | 修改简历，添加新版本 |
| 8 | 再次匹配，对比版本变化 |

### 工程验收

| 项目 | 验收标准 |
|------|---------|
| 路由 | 每个页面有独立 URL，刷新不丢状态 |
| API | 统一 API Client，Mock 可切换 |
| 类型 | 完整 TypeScript 类型定义 |
| 状态 | Loading / Error / Empty 统一处理 |
| 依赖 | 无冗余依赖，有 lock 文件 |
| 代码 | ESLint + Prettier 配置 |
