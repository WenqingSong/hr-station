# 版本对比 Agent

> 最后更新：2026-05-29（阶段 3-8 实现简历版本对比 Mock 接口）

## 1. 当前实现状态

阶段 3-8 已完成，简历版本对比 Mock Agent 已实现（`server/internal/agent/version_compare_mock.go`）。Mock Agent 使用简单规则生成结构化版本对比结果。不调用真实 LLM。阶段 4 才接真实 Agent / LLM。

## 2. 阶段 3 Mock Agent 目标

- 对比用户两个简历版本的差异
- 生成分数变化分析
- 生成字段变化列表
- 生成风险变化趋势
- 生成建议完成情况
- 生成关键改进和剩余风险
- 生成总结和真实性提示
- 不调用真实模型
- 不读取 LLM_API_KEY
- 不自动生成优化版简历
- 不修改用户简历

## 3. 输入数据

| 字段 | 类型 | 说明 |
|------|------|------|
| from_version | *model.ResumeVersion | 旧版本简历数据 |
| to_version | *model.ResumeVersion | 新版本简历数据 |

## 4. 输出结构

```json
{
  "from_version_no": 1,
  "to_version_no": 2,
  "score_before": 65,
  "score_after": 78,
  "score_change": 13,
  "field_changes": [...],
  "risk_changes": [...],
  "suggestion_completion": [...],
  "key_improvements": [...],
  "remaining_risks": [...],
  "summary": "...",
  "authenticity_notice": "..."
}
```

## 5. Mock 对比规则

### 分数计算

简历完整度评分（0-100）基于以下规则：

| 规则 | 加分 | 说明 |
|------|------|------|
| target_role 已填写 | +8 | 目标岗位明确 |
| target_city 已填写 | +5 | 目标城市明确 |
| 技能数量（每项） | +3 | 最大 18 |
| 关键后端技能 | +2/项 | Go/MySQL/Redis/Docker/K8s/云/分布式/微服务 |
| 项目描述详细（每项） | +3 | 描述 > 20 字 |
| 经历描述详细（每项） | +3 | 描述 > 10 字 |
| 自我评价充实 | +4 | > 10 字 |
| 原始文本长度 | +3 | > 100 字 |

分数变化 = score_after - score_before

### 字段变化类型

| 类型 | 值 | 说明 |
|------|---|------|
| 新增 | `added` | 新增了字段内容 |
| 修改 | `modified` | 修改了字段内容 |
| 删除 | `removed` | 删除了字段内容 |
| 未变 | `unchanged` | 字段未发生变化 |

### 风险变化趋势

| 趋势 | 值 | 说明 |
|------|---|------|
| 降低 | `reduced` | 风险已降低 |
| 不变 | `unchanged` / `stable` | 风险未改善 |
| 新增 | `increased` | 出现新风险 |

### 建议完成状态

| 状态 | 值 | 说明 |
|------|---|------|
| 已完成 | `completed` | 已完成该建议 |
| 部分完成 | `partially_completed` | 部分完成 |
| 未开始 | `not_started` | 未开始 |

## 6. 字段变化设计

对比以下字段的差异：

1. **target_role**：目标岗位表达变化
2. **skills**：技能列表变化（新增/移除）
3. **project**：项目经历描述变化
4. **self_evaluation**：自我评价变化

每条字段变化包含：
- `field`：字段名
- `before`：变化前描述
- `after`：变化后描述
- `change_type`：变化类型
- `impact`：影响说明

## 7. 风险变化设计

跟踪以下风险的改善情况：

1. **后端项目证据不足**：基于技能列表和项目描述判断
2. **核心后端技术覆盖不全**：基于 Redis/K8s/分布式/微服务等关键词
3. **量化指标不足**：基于是否有数字/性能相关描述

每条风险变化包含：
- `risk`：风险描述
- `before`：变化前严重度
- `after`：变化后严重度
- `trend`：趋势

## 8. 建议完成情况设计

跟踪以下建议的完成情况：

1. **补充项目中的后端职责和技术栈**：检查后端技术关键词
2. **在项目描述中增加量化指标**：检查项目描述详细程度
3. **补充缓存与并发场景表达**：检查 Redis/缓存/并发相关关键词

每条建议完成情况包含：
- `suggestion`：建议内容
- `status`：完成状态
- `evidence`：判断依据

## 9. 真实性提示

每条版本对比结果都包含 `authenticity_notice` 字段：

> 版本对比仅用于呈现表达变化，请只补充真实经历，不要虚构项目或能力。

## 10. 当前不调用真实模型

- Mock Agent 不调用真实 LLM
- 不读取 LLM_API_KEY
- 不使用真实 Prompt
- 不生成新简历内容
- 不修改用户简历
- 阶段 4 才替换为真实 Agent

## 11. 后续真实 Agent 设计方向

阶段 4 将替换为：

1. 真实 LLM API 调用
2. 基于 Prompt 的深度对比
3. 更精准的变化语义分析（理解"增加了什么"而非简单字符串比较）
4. 更个性化的改进建议
5. 支持多次迭代追踪
