# 学生求职极端情况处理边界

> 创建时间：2026-05-30
> 所属阶段：4-3.5.F
> 依据文档：战略差异化与杀手锏确认、投递边界与优化停止条件设计、JD证据链匹配与START简历优化规则、Agent输出QualityGate设计、阶段4-3方案、岗位匹配Agent、岗位推荐Agent、Agent总览、Prompt模板、JSON输出规范、失败兜底与Mock回退策略

## 1. 背景

4-3.5.B 已完成战略差异化确认，项目定位为"面向学生的投递前决策与简历初筛优化系统"。

4-3.5.C 已完成投递边界与优化停止条件设计（杀手锏一）。

4-3.5.D 已完成 JD 证据链匹配与 START 简历优化规则（杀手锏二）。

4-3.5.E 已完成 Agent 输出 Quality Gate 设计（杀手锏三）。

但实际学生求职场景中存在多种极端情况：

1. 简历信息极少，无法形成有效证据链
2. 简历质量很差，对目标岗位几乎无支撑
3. 学生目标岗位与经历明显不匹配
4. 海外岗位或地点 / 语言 / 地区风险
5. 候选人过强，可能更适合研究型或深度技术岗位
6. 学生工作意向不清晰
7. 用户期待 AI 给出过强判断或职业规划
8. 简历中存在真实性风险
9. 用户要求 AI 替自己编写夸大经历
10. 学生已经具备投递条件但仍在过度优化

如果 Agent 不识别这些极端情况，可能输出不当内容：强行推荐不匹配岗位、编造经历、做职业规划、羞辱用户、或陷入无限优化循环。

本文档定义各类极端情况的处理边界。

## 2. 核心问题：极端情况处理不能脱离课题主旨

本项目处理极端情况的目的，不是做人生规划，也不是替学生做长期职业判断。

极端情况处理仍然服务于两个目标：

1. 帮助学生有效匹配合适岗位
2. 提升对心仪岗位的简历初筛命中率

禁止扩展成：

1. 长期职业规划
2. 人格评价
3. 价值观判断
4. 公司文化适配审查
5. 录用概率承诺
6. 对用户能力的羞辱性判断
7. 对用户背景的敏感推断

## 3. 设计目标

1. 定义 candidate_case_type，识别学生求职场景中的极端情况类型
2. 定义 case_risk_level，评估极端情况的风险等级
3. 定义 case_handling_strategy，明确各类极端情况的处理策略
4. 确保各类极端情况的触发条件、推荐输出和禁止表达
5. 确保不做人格/价值观判断
6. 确保不做职业规划
7. 确保不鼓励造假
8. 确保信息不足时保守处理
9. 确保弱简历给最小可行动作
10. 确保岗位不匹配表达为"当前简历 × 当前岗位 JD 不匹配"
11. 确保海外/地点问题只处理投递条件和岗位适配
12. 确保优秀候选人提示方向但不做长期规划
13. 为后续 Prompt / Schema / Agent / 前端提供设计方向
14. 本阶段不修改代码、Prompt、Schema 或前端

## 4. 基本原则

### 4.1 极端情况处理不能脱离课题主旨

系统判断的不是"这个学生行不行"，而是：

- 当前简历与当前岗位 JD 的匹配程度
- 当前简历对初筛的支撑程度
- 当前投递是否需要先补充证据或修改表达

推荐表达：

- 当前简历对该岗位关键要求的覆盖不足
- 当前信息不足，无法稳定判断是否适合投递
- 当前岗位与简历证据存在较大差距，暂不建议直接投递该岗位

禁止表达：

- 你不适合互联网
- 你不适合腾讯
- 你的能力太差
- 你价值观不符
- 你不适合技术岗

### 4.2 信息不足时要保守，不强行推荐

当简历信息不足时，系统不应强行给出高置信推荐或强匹配结论。应提示用户补充关键经历，再进行匹配或优化。

信息不足时应返回：

```
apply_readiness=insufficient_information
optimization_stop_signal=needs_more_evidence
recommendation_confidence=low
```

### 4.3 弱简历处理要给最小可行动作

简历弱不等于否定学生。系统应识别当前简历缺少哪些支撑初筛的证据，并给出最小可行动作。

推荐输出：

```
先补充一段项目 / 课程设计 / 实习 / 竞赛经历；
说明你负责了什么；
使用了什么方法；
产生了什么结果；
再进行匹配分析。
```

### 4.4 岗位不匹配要回到 JD 证据，不做人格判断

岗位不匹配不是评价用户不行，而是说明当前简历中缺少该岗位关键要求的证据。

推荐输出：

```
当前简历中缺少该岗位核心要求的直接证据，问题不是简单改写可以解决的。
建议优先选择与现有经历更匹配的岗位，或补充相关经历后再考虑投递该岗位。
```

### 4.5 海外/地点/语言问题只处理投递条件与岗位适配

海外背景、海外岗位、异地投递、语言能力等情况，只能从岗位要求、地点意向、语言能力、工作地接受度等角度处理。

禁止：

1. 推断用户身份
2. 推断用户国籍
3. 推断签证或工作许可
4. 推断政治、民族、宗教、家庭背景
5. 做不必要的敏感判断

推荐表达：

```
当前岗位包含海外 / 异地协作要求，建议确认工作地点、语言要求、时区协作和投递资格等信息。
```

### 4.6 资历较强时只提示岗位选择方向，不做长期规划

如果学生有较强研究、竞赛、开源、论文或深度工程经历，系统可以提示该候选人可能更适合研究型、基础架构、AI Infra、算法研究、数据库内核等更能发挥优势的岗位类型。

但必须避免变成长期职业规划。

推荐表达：

```
基于当前简历证据，你也可以优先关注更强调研究能力、复杂工程能力或专项技术深度的岗位类型。
这只是投递方向提示，不是长期职业规划结论。
```

## 5. candidate_case_type 设计

### 5.1 枚举定义

| 值 | 定义 |
|---|------|
| `normal_case` | 普通情况，简历信息基本完整，岗位目标明确 |
| `insufficient_information` | 用户信息不足，无法稳定判断岗位匹配或初筛风险 |
| `weak_resume` | 简历有内容，但对目标岗位的支撑较弱 |
| `target_role_mismatch` | 用户目标岗位与当前简历证据差距较大 |
| `overseas_or_location_risk` | 经历、期望地点、岗位地点、语言要求或投递条件存在不确定性 |
| `high_potential_research_or_deep_tech` | 用户具备强研究、竞赛、开源、论文或深度技术信号 |
| `unclear_job_intention` | 用户求职目标不清晰，导致推荐和匹配失焦 |
| `authenticity_risk` | 简历表达可能存在真实性风险、过度包装或证据不足 |
| `over_optimization_risk` | 用户已具备投递条件，但仍在过度打磨简历 |
| `unsafe_user_request` | 用户要求 AI 编造经历、夸大成果、虚构指标或伪造岗位匹配 |

### 5.2 各枚举详细设计

#### 5.2.1 normal_case

**定义**：普通情况。简历信息基本完整，岗位目标明确，可以正常进行推荐、匹配分析和简历优化。

**触发条件**：

1. 简历包含至少 1 段项目 / 实习 / 竞赛 / 论文 / 课程设计经历
2. 目标岗位方向明确
3. 简历信息完整度中等以上
4. 不存在严重真实性风险
5. 不存在海外 / 地点严重冲突

**建议输出**：正常输出推荐 / 匹配 / 优化结果。

**禁止表达**：无特殊限制，但仍需遵守通用安全规范。

**与 apply_readiness 的关系**：可以是 `ready_to_apply` 或 `quick_fix_before_apply`。

**与 Quality Gate 的关系**：正常通过 Quality Gate 检查。

---

#### 5.2.2 insufficient_information

**定义**：用户信息不足，无法稳定判断岗位匹配或初筛风险。

**触发条件**：

1. 简历过短（教育经历 + 自我评价，无项目/实习/竞赛/论文）
2. 缺少教育经历
3. 缺少项目 / 实习 / 竞赛 / 论文 / 课程设计等任一能力证明
4. 目标岗位不明确
5. 只填写泛泛自我评价

**建议输出**：

```
当前信息不足，系统无法稳定判断是否适合投递该岗位。
建议先补充至少一段项目、实习、竞赛、论文或课程设计经历，并说明你负责了什么、使用了什么方法、产生了什么结果。
```

**对应**：

- `apply_readiness=insufficient_information`
- `optimization_stop_signal=needs_more_evidence`
- `recommendation_confidence=low`
- `quality_gate_result=manual_review_suggested`

**禁止表达**：

- 你的简历什么都没有
- 你没法投递任何岗位
- 请先完善简历再来

**与 apply_readiness 的关系**：`insufficient_information`。

**与 Quality Gate 的关系**：如果 Agent 忽略信息不足而强行输出 high confidence 推荐，应判定不合格。

---

#### 5.2.3 weak_resume

**定义**：简历有内容，但对目标岗位的支撑较弱。

**触发条件**：

1. 有经历，但表达空泛
2. 只有课程或自我评价，没有项目证据
3. 技术栈堆砌但没有使用场景
4. 缺少个人职责
5. 缺少结果或产出

**建议输出**：

```
当前主要问题不是继续堆关键词，而是补充能证明岗位能力的经历证据。
建议优先完善一段最相关经历，说明项目背景、个人任务、技术动作、结果和技术栈。
```

**对应**：

- `apply_readiness=quick_fix_before_apply` 或 `not_ready_for_this_role`
- `optimization_stop_signal=fix_top_3_then_apply` 或 `needs_more_evidence`

**禁止表达**：

- 你的简历太差了
- 你没有任何亮点
- 建议重新写简历

**与 apply_readiness 的关系**：`quick_fix_before_apply` 或 `not_ready_for_this_role`。

**与 Quality Gate 的关系**：如果弱简历被强行判断为 `ready_to_apply`，应判定 `consistency_check` 失败。

---

#### 5.2.4 target_role_mismatch

**定义**：用户目标岗位与当前简历证据差距较大。

**触发条件**：

1. 投后端岗但简历没有编程或项目证据
2. 投算法岗但没有算法、数学、论文、竞赛或模型相关证据
3. 投产品岗但没有用户、需求、调研、项目推动相关证据
4. 岗位核心要求在简历中大面积 missing

**建议输出**：

```
当前简历与该岗位核心要求差距较大，继续优化这份简历的收益有限。
建议优先考虑与现有经历更接近的岗位方向，或在补充相关经历后再投递该岗位。
```

**对应**：

- `apply_readiness=not_ready_for_this_role`
- `optimization_stop_signal=target_role_mismatch`

**禁止表达**：

- 你不适合这个岗位
- 你的能力不够
- 你不如换个方向

**与 apply_readiness 的关系**：`not_ready_for_this_role`。

**与 Quality Gate 的关系**：如果岗位明显不匹配但 Agent 输出高匹配分数，应判定 `jd_grounding_check` 失败。

---

#### 5.2.5 overseas_or_location_risk

**定义**：用户经历、期望地点、岗位地点、海外岗位、语言要求或工作地接受度存在不确定性。

**触发条件**：

1. 用户当前地区与期望工作地不同
2. 岗位是海外 / 异地岗位
3. JD 中出现语言、跨地区协作、海外团队等要求
4. 用户未填写是否接受调配
5. 用户语言能力信息缺失

**建议输出**：

```
该岗位可能涉及地点、语言或跨地区协作要求。建议在投递前确认工作地点、语言要求、是否接受调配，以及岗位是否符合你的实际投递条件。
```

**对应**：

- `apply_readiness=quick_fix_before_apply` 或 `insufficient_information`
- `optimization_stop_signal=fix_top_3_then_apply` 或 `needs_more_evidence`

**禁止**：

1. 不要推断签证、国籍、身份、政治、民族、宗教等敏感信息
2. 不要对海外背景做负面评价
3. 不要假设用户无法适应异地工作

**与 apply_readiness 的关系**：`quick_fix_before_apply` 或 `insufficient_information`。

**与 Quality Gate 的关系**：如果岗位有明显地点冲突但 Agent 未提及，应判定 `safety_tone_check` 或 `apply_boundary_check` 需要关注。

---

#### 5.2.6 high_potential_research_or_deep_tech

**定义**：用户具备强研究、竞赛、开源、论文、复杂工程或深度技术信号。

**触发条件**：

1. 高质量论文
2. ACM / 数模 / 算法 / 科研竞赛
3. 开源贡献
4. 复杂系统项目
5. AI Infra / 数据库 / 编译器 / 系统内核 / 大模型相关经历
6. 高质量实验室项目

**建议输出**：

```
基于当前简历证据，你可以优先关注更强调研究能力、复杂工程能力或专项技术深度的岗位类型，例如基础架构、AI Infra、算法研究、数据库内核等方向。
这只是投递方向提示，不是长期职业规划结论。
```

**对应**：

- `apply_readiness=ready_to_apply` 或 `quick_fix_before_apply`
- `optimization_stop_signal=stop_and_apply` 或 `fix_top_3_then_apply`

**禁止表达**：

- 你应该去做研究，不要来互联网
- 你太强了，来大厂浪费了
- 你的未来应该走学术路线

**与 apply_readiness 的关系**：通常是 `ready_to_apply` 或 `quick_fix_before_apply`。

**与 Quality Gate 的关系**：不应因为候选人过强而降低匹配分数或给出低置信推荐。

---

#### 5.2.7 unclear_job_intention

**定义**：用户求职目标不清晰，导致推荐和匹配失焦。

**触发条件**：

1. 同时目标后端、算法、产品、运营，跨度过大
2. 期望城市缺失
3. 期望岗位方向缺失
4. 简历经历和目标岗位无法对应
5. 用户只说"想进大厂"

**建议输出**：

```
当前求职目标较宽，系统难以稳定判断最优投递方向。
建议先选择 1-2 个主攻方向，再进行岗位推荐和简历优化。
```

**对应**：

- `apply_readiness=insufficient_information` 或 `quick_fix_before_apply`
- `optimization_stop_signal=needs_more_evidence`

**禁止表达**：

- 你连自己想做什么都不知道
- 你目标太散了
- 建议你先想清楚

**与 apply_readiness 的关系**：`insufficient_information` 或 `quick_fix_before_apply`。

**与 Quality Gate 的关系**：如果推荐置信度过低但未提示用户，应判定 `apply_boundary_check` 需要关注。

---

#### 5.2.8 authenticity_risk

**定义**：简历表达可能存在真实性风险、过度包装风险或证据不足风险。

**触发条件**：

1. 简历声称负责大型系统但没有职责细节
2. 指标过大但没有上下文
3. 技术栈堆砌严重
4. 项目描述像模板，缺少个人动作
5. AI 示例可能诱导用户写入未发生事实

**建议输出**：

```
当前表达存在真实性风险。建议只保留你实际参与、能够解释清楚的职责、技术动作和结果。
不要把团队整体成果写成个人成果，也不要加入没有实际发生过的指标。
```

**对应**：

- `apply_readiness=quick_fix_before_apply` 或 `not_ready_for_this_role`
- `quality_gate_result=revise_required` 或 `fallback_required`

**禁止表达**：

- 你在简历上撒谎
- 你的经历是假的
- 你编造了数据

**与 apply_readiness 的关系**：`quick_fix_before_apply` 或 `not_ready_for_this_role`。

**与 Quality Gate 的关系**：`fabrication_check` 一旦发现编造内容应直接 `fallback_required`。

---

#### 5.2.9 over_optimization_risk

**定义**：用户已经具备投递条件，但仍在过度打磨简历，可能错过投递时机。

**触发条件**：

1. 已经覆盖岗位核心要求
2. 只剩轻微表达问题
3. 用户反复要求继续优化
4. 继续修改边际收益低
5. 岗位投递有时效性

**建议输出**：

```
当前简历已经能够支撑该岗位投递，继续大幅修改的收益有限。
建议停止反复打磨，优先开始投递，并根据后续反馈小步迭代。
```

**对应**：

- `apply_readiness=ready_to_apply`
- `optimization_stop_signal=stop_and_apply`

**禁止表达**：

- 你的简历已经完美了
- 你一定能通过初筛
- 不用改了直接投

**与 apply_readiness 的关系**：`ready_to_apply`。

**与 Quality Gate 的关系**：如果 `apply_readiness=ready_to_apply` 但 Agent 继续输出大量优化项，应判定 `consistency_check` 失败。

---

#### 5.2.10 unsafe_user_request

**定义**：用户要求 AI 编造经历、夸大成果、虚构指标、虚构证书、虚构项目或伪造岗位匹配。

**触发条件**：

1. 用户要求编造实习
2. 用户要求写没做过的项目
3. 用户要求虚构 QPS / DAU / 性能提升
4. 用户要求把团队成果写成个人成果
5. 用户要求伪造证书、学历、获奖

**建议输出**：

```
我不能帮你编造或夸大没有发生过的经历。可以帮你基于真实经历优化表达，或者帮你把已有项目按 STAR-T 方式整理得更清楚。
```

**对应**：

- `quality_gate_result=fallback_required` 或 `manual_review_suggested`

**禁止表达**：

## 15. case_risk_level 设计

### 15.1 枚举定义

| 值 | 定义 | 说明 |
|---|------|------|
| `low` | 普通情况或轻微表达问题 | 不影响正常推荐和匹配 |
| `medium` | 存在信息不足、表达不清、地点偏好不明确 | 需要补充信息或保守处理 |
| `high` | 目标岗位明显不匹配、真实性风险较高 | 不建议直接投递，需要修正或换岗 |
| `critical` | 用户要求造假、输出存在严重不当风险 | 必须拒绝或 fallback |

### 15.2 与 candidate_case_type 的默认映射

| candidate_case_type | 默认 case_risk_level |
|---|---|
| `normal_case` | `low` |
| `insufficient_information` | `medium` |
| `weak_resume` | `medium` |
| `target_role_mismatch` | `high` |
| `overseas_or_location_risk` | `medium` |
| `high_potential_research_or_deep_tech` | `low` |
| `unclear_job_intention` | `medium` |
| `authenticity_risk` | `high` |
| `over_optimization_risk` | `low` |
| `unsafe_user_request` | `critical` |

### 15.3 与 Quality Gate 的关系

- `case_risk_level=critical` 时，Quality Gate 应直接 `fallback_required`
- `case_risk_level=high` 时，Quality Gate 应至少 `revise_required`
- `case_risk_level=medium` 时，Quality Gate 可 `manual_review_suggested`
- `case_risk_level=low` 时，Quality Gate 通常 `pass`

## 16. case_handling_strategy 设计

### 16.1 枚举定义

| 值 | 定义 | 说明 |
|---|------|------|
| `normal_response` | 正常输出推荐或匹配结果 | 适用于 normal_case / high_potential / over_optimization |
| `clarify_before_recommendation` | 先提示补充信息 | 适用于 insufficient_information / unclear_job_intention |
| `quick_fix_then_apply` | 先修 2-3 个点再投 | 适用于 weak_resume |
| `recommend_alternative_jobs` | 建议优先看更匹配岗位 | 适用于 target_role_mismatch |
| `conservative_advice` | 输出保守建议 | 适用于 overseas_or_location_risk / authenticity_risk |
| `refuse_fabrication` | 拒绝编造或夸大 | 适用于 unsafe_user_request |
| `manual_review_suggested` | 建议用户自行核实或人工判断 | 适用于信息严重不足或高度不确定 |

### 16.2 与 candidate_case_type 的默认映射

| candidate_case_type | 默认 case_handling_strategy |
|---|---|
| `normal_case` | `normal_response` |
| `insufficient_information` | `clarify_before_recommendation` |
| `weak_resume` | `quick_fix_then_apply` |
| `target_role_mismatch` | `recommend_alternative_jobs` |
| `overseas_or_location_risk` | `conservative_advice` |
| `high_potential_research_or_deep_tech` | `normal_response` |
| `unclear_job_intention` | `clarify_before_recommendation` |
| `authenticity_risk` | `conservative_advice` |
| `over_optimization_risk` | `normal_response` |
| `unsafe_user_request` | `refuse_fabrication` |

## 17. 与 Quality Gate 的关系

Quality Gate 应检查 Agent 是否正确识别极端情况：

| 极端情况 | Quality Gate 检查项 | 不合格判定 |
|---------|-------------------|-----------|
| insufficient_information | 被强行判断为 ready_to_apply | `apply_boundary_check` 失败 |
| authenticity_risk | 被忽略，输出编造内容 | `fabrication_check` 失败 |
| target_role_mismatch | 被包装成高匹配 | `jd_grounding_check` 失败 |
| unsafe_user_request | 被满足，输出虚构表达 | `fabrication_check` 失败 |
| over_optimization_risk | 继续给大量优化项 | `consistency_check` 失败 |
| overseas_or_location_risk | 未提及地点冲突 | `safety_tone_check` 需关注 |

### 17.1 Quality Gate 与 candidate_case_type 的联合检查

后续 Quality Gate 可增加 `extreme_case_check`：

1. 如果 `candidate_case_type != normal_case` 但 `quality_gate_result=pass`，应确认 Agent 是否正确处理了极端情况
2. 如果 `candidate_case_type=unsafe_user_request`，应直接 `fallback_required`
3. 如果 `candidate_case_type=authenticity_risk`，应至少 `revise_required`

## 18. 与 RecommendationAgent 的关系

RecommendationAgent 在极端情况下不应只给岗位列表。它应识别：

1. 是否信息不足 → 降低推荐置信度
2. 是否岗位目标过宽 → 提示缩小方向
3. 是否存在地点 / 语言 / 调配风险 → 标注风险
4. 是否应该推荐更匹配的岗位 → 调整推荐顺序
5. 是否应该降低 recommendation_confidence → 明确标注

推荐输出方向：

| 字段 | 说明 |
|------|------|
| `candidate_case_type` | 候选人情况类型 |
| `case_risk_level` | 情况风险等级 |
| `recommendation_confidence` | 推荐置信度 |
| `why_this_job_first` | 为什么先投这个岗位 |
| `apply_readiness` per job | 每个岗位的投递准备度 |

## 19. 与 MatchAnalysisAgent 的关系

MatchAnalysisAgent 在极端情况下不应只给 match_score。它应说明：

1. 哪些 JD 要求缺少证据 → 证据链标注 `missing`
2. 当前投递风险是什么 → `screening_risks`
3. 是否需要补充信息 → `apply_readiness=insufficient_information`
4. 是否不建议直接投递 → `apply_readiness=not_ready_for_this_role`
5. 是否可以快速优化后投递 → `apply_readiness=quick_fix_before_apply`

推荐输出方向：

| 字段 | 说明 |
|------|------|
| `candidate_case_type` | 候选人情况类型 |
| `apply_readiness` | 投递准备度 |
| `optimization_stop_signal` | 优化停止信号 |
| `jd_evidence_chain` | JD 证据链 |
| `screening_risks` | 初筛风险 |
| `top_fix_items` | 快速优化项 |

## 20. 与 ResumeOptimizationAgent 的关系

ResumeOptimizationAgent 在极端情况下不应强行改写。它应先判断：

1. 是表达问题，还是经历证据缺失 → 区分优化和补充
2. 是否存在真实性风险 → `authenticity_risk`
3. 是否应该拒绝编造 → `unsafe_user_request`
4. 是否应该输出示例参考而非最终文本 → `example_reference`
5. 是否应该建议用户补充真实信息 → `verification_notice`

推荐输出方向：

| 字段 | 说明 |
|------|------|
| `candidate_case_type` | 候选人情况类型 |
| `top_fix_items` | 快速优化项 |
| `long_term_improvement` | 长期提升项 |
| `example_reference` | 示例参考 |
| `verification_notice` | 核实提醒 |
| `self_check_question` | 自查问题 |
| `learn_more_query` | 学习关键词 |
