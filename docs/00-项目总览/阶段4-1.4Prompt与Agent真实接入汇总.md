## 8. 失败兜底与 Mock 回退策略汇总

完整链路：

```
业务 Agent 输出
→ JSON parse
→ Schema validate
→ JSONRepairAgent 尝试一次
→ repair 后重新 parse + validate
→ 仍失败则 Mock fallback
```

核心约束：

- **JSON repair 只尝试一次**
- **Repair 成功后 generated_by 仍为 llm_agent**
- **Repair 失败后 Mock fallback**
- **Mock fallback 的 generated_by 为 mock_agent**
- **用户侧不暴露底层错误**
- **不使用 llm_agent_fallback 作为业务 Schema 内 generated_by**
- **日志记录 error_code / fallback_reason / repair_applied**

错误码设计：20 种错误码，6 种直接 Mock 场景，6 种先 repair 场景。
