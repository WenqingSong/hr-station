## 4. 产品决策

| 决策 | 要点 | 对应 ADR |
|------|------|---------|
| 单主简历 | 用户只有一份主简历，V1→V2→V3 迭代，历史版本只读 | ADR-002 |
| 所有字段可选填 | 降低填写压力，允许用部分信息快速体验 | — |
| 不上传 PDF/DOC | 只支持结构化表单录入 | — |
| 不自动生成简历 | 只给诊断和建议，用户手动修改，避免 AI 虚构经历 | ADR-004 |
| 先 Mock 后接模型 | 阶段 3 Mock Agent 跑通闭环，阶段 4 接真实 LLM | ADR-003 |

## 5. 工程规则

| 规则 | 要点 | 对应文档 |
|------|------|---------|
| 任务颗粒度 | 一个 Prompt 只做一个任务，不跨阶段 | 工程执行规范 |
| 执行前必读 | 说明书→项目状态→下一步任务→变更记录→最近日志 | CodeBuddy 工作规则 |
| 执行后必更新 | 项目状态→下一步任务→变更记录→开发日志 | 文档更新规范 |
| 中文命名 | docs 下 Markdown 用中文，代码文件用英文 | 中文命名规范 |
| 越权禁止 | 15 项绝对禁止 | CodeBuddy 工作规则 |
| 不确定先记录 | 遇到不确定事项先记录风险或提问 | CodeBuddy 工作规则 |
| 8 阶段划分 | 0→1→2→3→4→5→6→7 | 工程执行规范 |

## 7. 下一阶段入口条件

阶段 1 开始前需确认：

1. ✅ CodeBuddy 每次任务必须先读文档
2. ✅ 每次任务必须小颗粒度
3. ✅ 每次任务必须更新项目状态、下一步任务、变更记录、开发日志
4. ✅ 阶段 1 只做工程初始化，不做业务功能
5. ✅ 阶段 1 不接模型
6. ✅ 阶段 1 不改前端页面业务逻辑
7. ✅ 阶段 1 不写业务接口
