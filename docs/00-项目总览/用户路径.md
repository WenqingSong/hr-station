# 用户路径

## 1. 总体路径

```
登录 → 工作台 → 添加简历 → 岗位推荐/岗位搜索 → 匹配分析 → 根据建议修改 → 添加新版本 → 再次匹配
```

核心循环：**分析 → 修改 → 再分析**，通过版本迭代持续优化匹配度。

## 2. 路径 A：用户不知道投什么岗位

适用于：有简历但对岗位方向不明确的用户。

```
登录
→ 首页
→ 添加简历（V1）
→ 岗位推荐
→ 查看推荐岗位列表
→ 选择某个推荐岗位
→ 进入岗位匹配分析
→ 查看 JD-简历证据链
→ 查看初筛风险与 P0/P1 优化建议
→ 手动修改简历
→ 添加新版本（V2）
→ 查看版本迭代
```

关键节点：
- 岗位推荐基于简历内容自动生成
- 推荐等级：强推荐 / 推荐 / 可尝试

## 3. 路径 B：用户已有目标岗位

适用于：已有明确目标岗位，想评估匹配度的用户。

```
登录
→ 我的简历（确认简历已存在）
→ 岗位列表
→ 搜索/浏览目标岗位
→ 选择目标岗位
→ 岗位匹配分析
→ 查看匹配度评分
→ 查看 JD-简历证据链
→ 查看初筛风险与优化建议
→ 手动修改简历
→ 添加新版本（V2）
→ 再次匹配
→ 查看版本变化（匹配度提升情况）
```

关键节点：
- 用户可主动搜索岗位关键词
- 匹配分析后可再次匹配同一岗位，对比匹配度变化

## 4. 路径 C：用户迭代简历

适用于：已获得匹配分析结果，正在根据建议优化简历的用户。

```
查看匹配分析结果
→ 根据 P0 建议手动修改简历
→ 根据 P1 建议补充内容
→ 添加新版本（系统保存为 Vn+1）
→ 再次进行岗位匹配
→ 对比 Vn 和 Vn+1 的匹配度变化
→ 查看版本迭代（变化原因、仍需改进）
```

关键节点：
- 版本只能添加，不能删除或编辑历史版本
- 版本对比展示字段级差异和改进评价

## 5. 页面流转关系

```
登录页 (/login)
  ↓ 登录成功
首页/工作台 (/)
  ├→ 我的简历 (/resume)
  │   ├→ 添加简历 (/resume/add)
  │   ├→ 简历详情 (/resume/detail)
  │   └→ 版本迭代 (/resume/versions)
  ├→ 岗位列表 (/jobs)
  │   └→ 岗位推荐 (/jobs/recommend)
  └→ 匹配分析 (/jobs/match/:jobId)
```

## 6. 数据流转关系

```
用户填写简历 → 结构化数据存入数据库
                    ↓
              简历提取 Agent → 提取关键信息标签
                    ↓
              岗位推荐 Agent → 生成推荐列表
                    ↓
用户选择岗位 → 岗位匹配 Agent → 生成匹配度 + 证据链 + 建议
                    ↓
用户手动修改 → 创建新版本 → 版本对比 Agent → 生成差异和改进评价
                    ↓
              再次匹配 → 对比匹配度变化
```

## 7. 当前版本路径边界

| 边界 | 说明 |
|------|------|
| 单主简历 | 只有当前一份简历，版本通过 V1/V2/V3 管理 |
| 历史版本只读 | 不能编辑或删除历史版本 |
| 岗位数据为预设 | 当前不爬取真实岗位，使用预置岗位数据 |
| Agent 先 Mock | 阶段 3 使用 Mock Agent，阶段 4 接入真实模型 |
| 无投递功能 | 不提供向企业投递简历的能力 |
| 无离线缓存 | 刷新页面需重新请求 |
