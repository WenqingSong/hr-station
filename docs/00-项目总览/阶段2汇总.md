# 阶段2汇总

## 1. 阶段目标

阶段 2 的目标是建设后端基础设施，使 Go 后端从"只具备 `/healthz` 的最小服务"升级为具备完整配置读取、统一响应、错误处理、中间件链、数据库连接、健康检查的基础设施平台。

阶段 2 不是业务开发阶段，不写业务接口、不写 JWT、不接 Agent、不接模型。

## 3. 后端基础设施交付物

|| 基础设施 | 文件 | 说明 |
||----------|------|------|
|| 配置读取 | `internal/config/config.go` | 7 组分组配置，保留兼容字段 |
|| 统一响应 | `internal/response/response.go` | OK / OKWithMessage / Error / JSON 函数 |
|| 应用错误 | `internal/errors/error.go` | AppError 类型，基础错误码，包名 apperror |
|| RequestLogger | `internal/middleware/logger.go` | 记录 method/path/status/duration |
|| CORS | `internal/middleware/cors.go` | 允许 localhost:5173，OPTIONS 返回 204 |
|| Recover | `internal/middleware/recover.go` | 捕获 panic，返回统一错误 |
|| MySQL 连接 | `internal/database/mysql.go` | database/sql + MySQL Driver，连接池 |
|| 健康检查 | `internal/health/service.go` | 聚合 app/database 状态 |
|| HTTP 路由 | `internal/http/router.go` | /healthz + 中间件链 |
|| 程序入口 | `cmd/server/main.go` | 配置加载 + MySQL + health + HTTP Server |

## 4. 当前运行能力

1. `make up` 可启动 MySQL 容器
2. `make dev-server` 可启动 Go 后端 HTTP Server
3. `/healthz` 返回 app/database 状态
4. 所有请求经过 Recover → CORS → RequestLogger 中间件链
5. 统一响应格式 `{code, message, data}`
6. 错误响应格式 `{code, message, data:null}`
7. 数据库连接启动时 Ping 验证
8. 数据库不可用时 `/healthz` 返回 degraded

## 6. 风险与注意事项

|| 风险 | 严重度 | 说明 |
||------|--------|------|
|| 前端无真实路由 | 🔴 高 | Figma Make 生成代码，需阶段 5-6 改造 |
|| 前端无 API 对接层 | 🔴 高 | 全部硬编码 Mock，需阶段 5 接入 |
|| CORS 策略宽松 | 🟡 中 | 开发环境允许所有 localhost 端口，生产需收紧 |
|| 健康检查 degraded 返回 200 | 🟡 中 | 开发阶段避免误判，生产环境需考虑 503 |
