## 一、页面定位冻结

```
/resumes = 简历管理 + Demo 体验中控台
```

**设计理念**：评委登录后，此页面是"第一站"。需要一眼看到：(1) 有哪些示范简历可用 (2) 每份简历适合体验哪些 AI 功能 (3) 如何一键进入对应功能。

**不做的事**：不替换岗位列表页（首页）、不替换岗位详情页、不新增路由页面。

## 四、四核心 AI 入口冻结

| 功能 | 入口设计 | 跳转路由 | 传递参数 | 是否需要默认 jobId |
|------|---------|---------|---------|:---:|
| 岗位智能推荐 | 列表区 [推荐岗位] 按钮 / 顶部 [智能推荐] 卡片 | `/recommend` | `?resumeVersionNo=X` | 不需要 |
| 岗位匹配分析 | 列表区 [去匹配岗位] 按钮 / 顶部 [匹配分析] 卡片 | `/match` | `?jobId=Y&resumeVersionNo=X` | **需要** |
| 简历优化建议 | 列表区 [优化简历] 按钮 / 顶部 [简历优化] 卡片 | `/resume-optimization` | `?jobId=Y&resumeVersionNo=X` | **需要** |
| 简历版本对比 | 列表区 [开始对比] 按钮 / 顶部 [版本对比] 卡片 | `/resumes/compare` | 页面内自动选 06/07 | 不需要 |

### 入口设计策略

**顶部 AI 概览区**（始终可见）：
- 4 个小卡片水平排列（移动端 2×2）
- 每卡片标题 + 一句说明 + 示例版本提示
- 点击跳转到对应功能页，带默认参数
- 这是"功能介绍"区，不随简历选中变化

**列表区主操作按钮**（每行右侧）：
- 每份简历只显示 1 个核心操作按钮
- 操作类型由分组决定
- 按钮文案清晰直接："去匹配岗位"、"推荐岗位"、"开始对比"、"优化简历"

**编辑入口**：
- 保留在原位置（每行右侧或 hover 显示）
- 降级为 ghost 按钮或文字链接
- 不喧宾夺主

| 01 算法研究生 | 匹配分析 | 算法-自然语言处理方向 | 10003 | NLP/ML/算法相关，匹配度最直接 |
| 02 211后台开发 | 匹配分析 | 软件开发-后台开发方向 | 10001 | 命名"后台开发"，10001 最匹配 |
| 03 二本产品经理 | 匹配分析 | 产品策划 | 10016 | 16 个岗位中唯一的产品岗位 |
| 04 职业探索型 | 推荐 | — | — | 推荐不需要 jobId |
| 05 跨界推荐 | 推荐 | — | — | 推荐不需要 jobId |
| 06 版本对比A | 对比 | — | — | 对比不需要 jobId |
| 07 版本对比B | 对比 | — | — | 对比不需要 jobId |
| 08 接近投递版 | 优化 | 软件开发-后台开发方向 | 10001 | 命名"后台开发"，10001 最匹配 |
| 09 基础薄弱版 | 优化 | 软件开发-后台开发方向 | 10001 | 命名"后台开发"，10001 最匹配 |

**默认岗位选择原则**：
1. 优先匹配简历名称中的方向关键词
2. 后台开发 → 10001（8 个 demo jobs 中仅有 1 个后台开发岗位）
3. 算法研究 → 10003（NLP，比 10002 多模态更通用）
4. 产品经理 → 10016（唯一产品策划岗位）
5. 岗位列表总共 8 个 demo 岗位（seed 中的 01-08），足够覆盖所有匹配/优化场景

## 六、视觉规范冻结

### 6.1 布局

| 属性 | 值 |
|------|-----|
| 页面最大宽度 | `max-w-[1040px]`（从 640px 提升） |

| 标题区间距 | `mb-8` |
| AI 概览区下方间距 | `mb-10` |
| 组间距 | `mb-8`（组之间） |
| 组内部间距 | 组标题 `mb-4` + 列表项 `space-y-0` |

### 6.2 卡片

| 用途 | 样式 |
|------|------|

| 简历行 | `px-5 py-4` + `hover:bg-gray-50` + `divide-y divide-gray-100` |

### 6.3 字体

| 层级 | 字号 | 字重 | 颜色 |
|------|------|------|------|
| H1 页面标题 | `text-[22px]` | `font-semibold` | `text-gray-900` |
| 副标题 | `text-sm` | `font-normal` | `text-gray-500` |
| 组标题 | `text-[15px]` | `font-semibold` | `text-gray-800` |
| AI 概览卡片标题 | `text-[14px]` | `font-semibold` | `text-gray-800` |
| AI 概览卡片说明 | `text-xs` | `font-normal` | `text-gray-500` |
| 简历名称 | `text-sm` | `font-medium` | `text-gray-900` |
| 用途标签 | `text-[11px]` | `font-medium` | 低饱和色 |
| 按钮文字 | `text-sm` | `font-medium` | — |

### 6.4 颜色

| 用途 | 颜色 |
|------|------|
| 主品牌色 | `#0052D9`（所有主按钮、链接、选中态） |
| 主品牌 hover | `#003DA5` |
| 页面背景 | `#F5F7FB`（ContentPageShell 提供） |
| 卡片背景 | `white` |
| 卡边框 | `ring-1 ring-gray-100` |
| 组标题左侧色条 | `w-1 h-5 rounded-full`：匹配 `#0052D9` / 推荐 `#059669` / 对比 `#7C3AED` / 优化 `#EA580C` |
| 用途标签 | 匹配 `bg-blue-50 text-blue-700` / 推荐 `bg-emerald-50 text-emerald-700` / 对比 `bg-violet-50 text-violet-700` / 优化 `bg-orange-50 text-orange-700` |

### 6.5 按钮

| 类型 | 样式 |
|------|------|
| 主操作（[去匹配岗位]等） | `bg-[#0052D9] text-white text-sm font-medium rounded-lg px-4 py-2 hover:bg-[#003DA5] transition-colors` |
| 添加简历 | `bg-[#0052D9] text-white text-sm font-medium rounded-lg px-4 py-2 hover:bg-[#003DA5]` + Plus icon |
| 编辑（次操作） | `text-gray-400 text-xs hover:text-[#0052D9] transition-colors`（文字链接） |
| AI 概览卡片（整卡可点击） | `cursor-pointer hover:shadow-[0_2px_12px_rgba(0,82,217,0.08)] transition-shadow` |

### 6.6 间距与对齐

- 标题区：`flex items-start justify-between`
- AI 概览 4 卡片：`grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-4 gap-4`
- 简历组：每个组是独立白色卡片容器
- 简历行：`flex items-center justify-between`
- 用途标签在组内：置于组标题右侧 `inline-flex items-center gap-2`

## 七、状态设计冻结

### 7.1 Loading 状态

```
使用 PageLoading（ContentPageShell 包裹）
- Loader2 spinner + "正在加载简历列表…"
- 保持与全站一致
```

### 7.2 Error 状态

```
使用 PageError（ContentPageShell 包裹）
- AlertCircle 图标 + "简历数据加载失败，请稍后重试"
- 下方 Link "去创建简历" → /resumes/edit
- 保持与全站一致
```

### 7.3 Empty 状态

```
居中白色卡片
- FileText 灰色大图标
- H2 "你还没有创建简历"
- P "添加一份简历后，这里会展示你的简历列表和 AI 功能入口。"
- [添加简历] 主按钮 → /resumes/edit
```

### 7.4 操作反馈

| 操作 | 行为 |
|------|------|
| 点击 [去匹配岗位] | `navigate(/match?jobId=10001&resumeVersionNo=X)`，浏览器跳转，无弹窗 |
| 点击 [推荐岗位] | `navigate(/recommend?resumeVersionNo=X)`，浏览器跳转 |
| 点击 [开始对比] | `navigate(/resumes/compare)`，对比页自动默认选 06/07 |
| 点击 [优化简历] | `navigate(/resume-optimization?jobId=10001&resumeVersionNo=X)` |
| 点击 AI 概览卡片 | 同上述，带默认参数（最新版本 + 默认 jobId） |
| 点击 [编辑] | `navigate(/resumes/edit)`，现有流程不变 |

### 7.5 Mobile 降级

| 桌面 | 移动端（sm 以下） |
|------|------------------|
| 4 卡片横排 | `grid-cols-1` → 单列堆叠 |
| 标题区左右分栏 | 标题在上，[添加简历] 在下方 |
| 简历行 | 名称 + 按钮堆叠（`flex-col` 或 `flex-col`） |
| AI 概览区 | 可折叠或缩为 2 列 |
| 按钮 | 保持可点击尺寸，不缩小文字 |

## 八、K8-5-35-C 实现边界

### 允许修改

| 文件 | 修改 |
|------|------|
| `web/src/app/pages/ResumeManagementPage.tsx` | 完全重写（按本设计冻结方案） |

### 允许新增

- 页面内部的组件函数（ResumeRow、AIFeatureCards、GroupSection 等，均在同一文件内）
- 用途标签内联样式
- 分组标题 + 色条装饰

### 禁止

| 禁止项 | 原因 |
|--------|------|
| 不改 `routes.tsx` | 不新增路由 |
| 不新增后端接口 | 数据链路不变 |
| 不改 SQL / seed | 不修改数据库 |
| 不改 Agent / Prompt | 不影响 AI 逻辑 |
| 不硬编码简历名称 | 数据来自 `/api/resumes/versions` |
| 不新增 npm 依赖 | 不安装新包 |
| 不创建新文件 | 仅修改 `ResumeManagementPage.tsx` |
| 不删减 `MyResumesPage` 编辑页 | 编辑能力不受影响 |
| 不修改 Navbar | 不做全局导航改造 |

### 关键词类别映射（用于用途标签自动匹配）

简历用途标签不硬编码，而是通过 **关键词匹配** 自动分配：

```ts
function getResumeCategory(name: string): { label: string; color: string; route: string } {
  if (name.includes('岗位匹配')) return { label: '匹配分析', ... };
  if (name.includes('岗位推荐')) return { label: '岗位推荐', ... };
  if (name.includes('版本对比')) return { label: '版本对比', ... };
  if (name.includes('简历优化')) return { label: '简历优化', ... };
  return { label: '', ... }; // fallback: 不显示标签
}
```
