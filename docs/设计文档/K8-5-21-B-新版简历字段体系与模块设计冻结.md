# K8-5-21-B — 新版简历字段体系与模块设计冻结

> 日期：2026-06-03 | 性质：design freeze | 未修改源码

---

## 1. 设计背景

基于 K8-5-21-A 全链路盘点，当前简历体系仅 8 模块 ~30 字段，education/experience/project/skills 以 JSON 存储。无法完整表达学生求职画像，限制 AI 分析质量。

**核心定位**：Offerr鹅 不做 ATS，不做正式投递系统，而做「学生求职画像采集系统」。字段必须服务四核心功能：简历对比、岗位推荐、岗位匹配、简历优化。

---

## 2. 核心设计结论

```text
1. Offerr鹅 不做腾讯招聘 ATS，而做学生求职画像采集系统。
2. 新版简历体系冻结为 10 个模块。
3. 新增模块：证书与语言能力、获奖与竞赛、作品链接与补充信息。
4. 增强模块：教育经历(含GPA/排名/课程)、实习/项目(含成果/技术栈/链接)、技能(含AI技能分层)、求职意向(含入职/出勤)。
5. 明确舍弃：照片/身份证/证件/联系人/证明人/内推串码/附件上传/隐私承诺。
```

## 4. 字段分级总表

### 4.1 简历基础

| 字段 | 级别 | 理由 |
|------|:---:|------|
| 简历名称 | 必填 | 多版本管理标识 |
| 目标方向 | 必填 | 推荐/匹配核心 |
| 简历说明 | 可选 | 内部 memo，不参与 AI |
| 最新分析提示 | 可选 | UI 提示，非数据 |

## 7. 存储方式建议

| 模块 | 建议方式 | 原因 |
|------|---------|------|
| 简历基础 | 结构化列 | name/target_role 单值 |
| 基础信息 | 结构化列 | phone/email/school/major/degree/graduation 单值 |
| 求职意向 | 结构化列 | city/job_type/onboard_date 高频筛选 |
| 教育经历 | JSON 数组 | 多条教育，字段扩展 |
| 实习经历 | JSON 数组 | 多条经历 |
| 项目经历 | JSON 数组 | 多条项目 |
| 技能信息 | JSON 对象 | skills/certificates/awards 层次化 |
| 证书与语言 | JSON 数组 | 多条记录 |
| 获奖与竞赛 | JSON 数组 | 多条记录 |
| 作品与补充 | JSON 对象 + 文本 | links + self_evaluation |

**原则**：高频筛选字段结构化为列，多条数组字段用 JSON。不追求全结构化，避免过度设计 DB schema。
