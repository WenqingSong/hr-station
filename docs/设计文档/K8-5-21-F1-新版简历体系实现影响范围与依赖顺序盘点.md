## 4. 依赖顺序图

### 实际依赖链

```
┌────────────────────────────────────────┐
│  K8-5-22-A：数据库 schema_version       │  ← 最底层，所有代码的依赖
│  + V2 模块 JSON 字段迁移               │
└───────────┬────────────────────────────┘
            ↓
┌────────────────────────────────────────┐
│  K8-5-22-B：后端 Resume V2             │  ← 依赖 A 的表结构
│  Model + Request/Response + Service    │
└───────────┬────────────────────────────┘
            ↓
┌────────────────────────────────────────┐
│  K8-5-22-C：NormalizeResumeToSnapshot   │  ← 依赖 B 的 model
│  V1→V2 归一化                         │
└───────┬────────────────────┬───────────┘
        ↓                    ↓
┌───────────────┐  ┌─────────────────────┐
│ K8-5-22-D：    │  │ K8-5-22-I：         │  ← 这两步可以并行
│ 前端 types/    │  │ Agent Prompt/Schema │
│ api/adapter    │  │ /Mock 接入 Snapshot │
└───────┬───────┘  └──────────┬──────────┘
        ↓                    ↓
┌────────────────────────────────────────┐
│  K8-5-22-E/F/G/H：MyResumesPage V2     │  ← 依赖 D + I
│  Shell + 10 模块拆分实现               │
└───────────────────────────┬────────────┘
                            ↓
┌────────────────────────────────────────┐
│  K8-5-22-J：V1/V2 兼容 + 旧数据回归   │  ← 全链路联调
│  ResumeManagement / Comparison 适配    │
└───────────────────────────┬────────────┘
                            ↓
┌────────────────────────────────────────┐
│  K8-5-22-Z：全链路验收                  │  ← build + test + API + mock
└────────────────────────────────────────┘
```

### 可并行 / 必须串行任务

| 类型 | 任务 | 原因 |
|------|------|------|
| **必须串行** | A → B → C | B 依赖 A 的表结构和 model 字段，C 依赖 B 的 model 和 service |
| **可并行** | D 和 I | 前端适配和 Agent 适配可以同时做，都只依赖 C 的 Snapshot 定义 |
| **必须串行** | C → E/F/G/H | 前端页面需要后端 API 先就绪才能联调 |
| **可内部并行** | F/G/H | 三个模块实现阶段可以由不同开发者并行（但通常单 CodeBuddy 串行） |
| **必须串行** | E/F/G/H → J | 兼容性回归需要所有模块实现完成后才能验证 |
| **必须串行** | J → Z | 最终验收 |

## 7. 风险分级

| 级别 | 风险 | 触发原因 | 影响 | 规避方式 |
|:---:|------|---------|------|---------|
| **P0** | `schema_version` 未先落地，V1/V2 数据混乱 | 跳过 A 直接做 B | 数据不可识别版本 | **严格按 A→B→C 顺序执行** |
| **P0** | Normalize 层缺失，Agent 直接读取 DB JSON | 跳过 C 直接做 I | Agent 耦合 DB 结构，Prompt 不可维护 | C 必须在 I 之前 |
| **P0** | 前端字段先实现，后端不接收，保存丢字段 | 跳过 B 直接做 E | 用户填写后保存失败 | D/E 必须在 B 之后 |
| **P0** | MyResumesPage 一次性塞 90 字段，维护失控 | E/F/G/H 合并为一个阶段 | 单文件 3000+ 行 | **拆为 E+3 个子阶段** |
| **P1** | Prompt 未裁剪，LLM 输入过长 | I 阶段未做字段裁剪 | Token 成本翻倍，推理质量下降 | I 阶段必须实现裁剪逻辑 |
| **P1** | Mock 不覆盖新字段，Demo 验收失真 | I 阶段 Mock 未更新新场景 | AI 页面看不到新模块结果 | I 阶段 Mock 必须覆盖证书/获奖/AI技能 |
| **P1** | 旧简历 V1 无法读取 | C 阶段解析 V1 JSON 出错 | 用户历史数据丢失 | C 必须测试 V1→V2 归一化全路径 |
| P2 | 状态栏完成度计算与字段体系不一致 | E 阶段完成度计算逻辑写死 | 完成度百分比不准确 | F 之后统一调整计算逻辑 |
| P2 | 新组件过多导致构建体积膨胀 | 组件拆分过细 | 影响首屏加载 | 合理合并，不做无意义拆分 |
