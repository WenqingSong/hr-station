# K8-5-21-E — 新版简历前端页面结构设计冻结

> 日期：2026-06-04 | 性质：design freeze | 未修改源码

---

## 1. 设计背景

基于 K8-5-21-A/B/C/D 的冻结成果：
- **K8-5-21-B**：新版简历冻结为 10 模块 ~90 字段，定位学生求职画像采集系统
- **K8-5-21-C**：数据库冻结为主表 + schema_version + 10 JSON 模块；API 同路径区分 V1/V2
- **K8-5-21-D**：所有 Agent 统一接收 ResumeSnapshotV2（meta + 10 模块），Prompt 不感知 DB 字段

**本阶段核心问题**：新版简历编辑页需承载 10 模块 ~90 字段，当前页面仅有 8 模块 ~30 字段，需设计全新页面结构而不吓退学生用户。

## 3. 3 种页面结构方案比较

### 方案 A：单页长表单 + 模块卡片（纯展开）

所有 10 模块在同一页面纵向排列，每模块一张白卡，全部默认展开。

| 维度 | 评价 |
|------|------|
| **直观性** | ✅ 最直观，一次看到所有内容 |
| **实现风险** | ✅ 低，与当前 MyResumesPage 高度兼容 |
| **90 字段压力** | ❌ 高，全部展开可能 3-5 屏长，学生会觉得"太多了" |
| **引导性** | ⚠️ 无，缺乏"先填什么后填什么"的引导 |
| **编辑效率** | ⚠️ 中，快速修改时滚动成本高 |

### 方案 B：单页 + 模块卡片 + 推荐/可选模块折叠（推荐）

10 模块仍在单页，但 6 个核心模块默认展开，4 个可选模块默认折叠。折叠模块标题显示完成状态图标。

| 维度 | 评价 |
|------|------|
| **直观性** | ✅ 核心模块一眼可见，可选模块折叠减少压力 |
| **实现风险** | ✅ 低-中，折叠/展开动画需实现，但组件逻辑成熟 |
| **90 字段压力** | ✅ 低，首次看到仅 6 个模块展开（约 50 字段），可选模块折叠 |
| **引导性** | ✅ 强，默认展开=推荐先填，默认折叠=可选后填 |
| **编辑效率** | ✅ 中-高，核心模块可快速定位，次要模块一键展开 |
| **视觉一致性** | ✅ 好，保持单页浏览节奏 |
| **新增用户友好度** | ✅ 高，不压迫 |

### 方案 C：Stepper 分步填写

将 10 模块拆成 4-5 步：基础画像 → 求职意向 → 经历能力 → 技能证明 → 补充信息。

| 维度 | 评价 |
|------|------|
| **直观性** | ✅ 极高引导性 |
| **实现风险** | ❌ 高，Stepper 状态机、步骤校验、跨步骤回填 |
| **90 字段压力** | ✅ 低，每步仅 2-3 模块 |
| **引导性** | ✅ 极强，适合首次填写的新用户 |
| **编辑效率** | ❌ 低，快速修改某个模块需要跳步骤 |
| **新增用户友好** | ✅ 高 |
| **回头客友好** | ❌ 低，已填过简历的用户不需要分步 |

### 推荐结论

**推荐方案 B：单页 + 模块卡片 + 推荐/可选模块折叠。**

原因：
1. 与当前 MyResumesPage 布局高度兼容，实现成本可控
2. 核心模块默认展开满足 AI 最小可用画像，可选模块折叠减少视觉压力
3. 不要求分步填写，已填过简历的用户可以快速找到需要修改的模块
4. 右侧新增状态栏提供完成度+AI 可用性反馈，兼顾引导和效率

**不推荐方案 C**：虽然对首次填写用户友好，但对编辑场景不友好，且实现复杂。可作为未来可选的新用户 onboarding 模式，不纳入当前阶段设计。

## 4. 推荐页面结构

```
ResumeEditPage
  ├─ PageHeader
  │   ├─ 返回链接 "← 返回我的简历"
  │   ├─ 标题：创建简历 / 编辑简历
  │   ├─ 副标题：完善经历和技能，帮助 Offer捕手 更准确完成岗位推荐、匹配分析和简历优化
  │   └─ AI 提示条：当前可复用的蓝色提示条（保留）
  │
  ├─ MainLayout (max-w-[1280px])
  │   ├─ Left Main Column (flex-1)
  │   │   ├─ 模块 1：简历基础              （默认展开 ✅）
  │   │   ├─ 模块 2：基础信息              （默认展开 ✅）
  │   │   ├─ 模块 3：求职意向              （默认展开 ✅）
  │   │   ├─ 模块 4：教育经历              （默认展开 ✅）
  │   │   ├─ 模块 5：项目经历              （默认展开 ✅）
  │   │   ├─ 模块 6：技能信息              （默认展开 ✅）
  │   │   ├─ 模块 7：实习经历              （默认折叠 ▶）
  │   │   ├─ 模块 8：证书与语言能力        （默认折叠 ▶）
  │   │   ├─ 模块 9：获奖与竞赛            （默认折叠 ▶）
  │   │   └─ 模块 10：作品链接与补充信息   （默认折叠 ▶）
  │   │
  │   └─ Right Status Sidebar (w-[280px], sticky top-28)
  │       ├─ 简历完成度（环形进度 or 进度条）
  │       ├─ AI 分析可用性状态
  │       ├─ 四核心功能可用状态
  │       │   ├─ 岗位推荐     ✅ / ⚠️ / ❌
  │       │   ├─ 岗位匹配     ✅ / ⚠️ / ❌
  │       │   ├─ 简历优化     ✅ / ⚠️ / ❌
  │       │   └─ 简历对比     ✅ / ❌（需 >= 2 版本）
  │       ├─ 必填缺失项列表
  │       ├─ 推荐补充项列表
  │       └─ 保存状态提示
  │
  └─ Bottom Save Section (页面最后一模块)
      ├─ 左侧说明：保存后 Offer捕手 将基于最新版本进行分析
      ├─ 取消按钮
      └─ 保存简历按钮（pending 状态 + loader）
```

### 布局说明

```text
1. >=1280px：双栏（主内容 + 右侧 sticky 状态栏）
2. 768-1279px：单栏（右侧状态栏移到顶部，作为横向状态条）
3. <768px：单栏紧凑（双列字段变单列，按钮全宽）
```

### 右侧状态栏设计

| 区域 | 内容 |
|------|------|
| **完成度** | 环形进度条 + 百分比（基于必填+推荐字段的填写率） |
| **AI 可用性** | 绿/黄/灰三态图标 + 文字说明 |
| **四功能状态** | 每个功能一行：图标（✅可用/⚠️部分/❌不可用）+ 功能名 + 缺失项提示 |
| **必填缺失** | 列表：红色圆点 + 缺失字段名 |
| **推荐补充** | 列表：黄色圆点 + 待补充模块名 |
| **保存状态** | 灰色文字："已保存" / "有未保存修改" |

### 四核心功能可用条件

| 功能 | 可用条件 | 当前提示 |
|------|---------|---------|
| **岗位推荐** | jobIntention.targetRoles + skills（至少 1 类非空）+ projects/internships 至少 1 项 | "请补充求职意向和技能" |
| **岗位匹配** | 同推荐条件 | 同推荐 |
| **简历优化** | profile.school + degree + 至少 1 个经历模块 | "请补充基础信息和经历" |
| **简历对比** | 存在 >= 2 个版本 | "需要先保存至第二个版本" |

## 5. 模块默认状态

| 序号 | 模块 | 默认状态 | 原因 |
|:---:|------|:---:|------|
| 1 | 简历基础 | ✅ 展开 | 必填，定义简历身份和方向 |
| 2 | 基础信息 | ✅ 展开 | 必填核心字段（姓名/学校/学历/专业/毕业时间） |
| 3 | 求职意向 | ✅ 展开 | AI 推荐/匹配核心依赖 |
| 4 | 教育经历 | ✅ 展开 | 校招核心，每学生都有 |
| 5 | 项目经历 | ✅ 展开 | 每学生都有（课程/竞赛/个人项目） |
| 6 | 技能信息 | ✅ 展开 | AI 匹配核心，填写门槛低 |
| 7 | 实习经历 | ▶ 折叠 | 部分学生无实习，不应压迫 |
| 8 | 证书与语言能力 | ▶ 折叠 | 可选加分项，非必需 |
| 9 | 获奖与竞赛 | ▶ 折叠 | 可选加分项，非必需 |
| 10 | 作品链接与补充信息 | ▶ 折叠 | 可选补充项，部分学生无 |

**原则**：
- 所有学生都有（教育/项目/技能）→ 默认展开
- 部分学生有（实习）→ 折叠，但标题备注"推荐填写"
- 少数学生有（证书/获奖/作品）→ 折叠，标题备注"可选加分项"
- 折叠模块标题必须显示状态图标（已填 ✅ / 未填 —）

## 6. 字段布局策略

| 模块类型 | 布局策略 | 示例 |
|---------|---------|------|
| **单字段模块**（简历基础、求职意向） | 单列 `space-y-5`；双字段用 `sm:grid-cols-2` | 简历名称 + 目标方向双列；大文本 textarea 单列 |
| **单字段模块**（基础信息） | `grid grid-cols-1 sm:grid-cols-2 gap-x-6 gap-y-5` | 姓名/学校/学历/专业/毕业时间/城市 双列 |
| **多条目模块**（教育/实习/项目） | 子卡片 `rounded-2xl bg-gray-50/70 ring-1 ring-gray-100 p-5`；条目内部 `sm:grid-cols-2` 双列字段；顶部标题栏（左：序号，右：删除+上下移按钮） | 教育：学校/专业/学历/时间/课程；实习：公司/岗位/时间/内容/技术栈/成果 |
| **多条目模块**（证书/获奖） | 同子卡片模式，但尺寸更紧凑（`p-4`），单列字段 | 证书：名称/类型/等级/分数/获得时间 |
| **技能模块** | 分类区域（每个分类一个 tag 输入区）；已添加标签展示（蓝色 tag + X 删除） | 编程语言区、后端框架区、数据库区、AI技能区 |
| **技能模块（AI 技能）** | 独立高亮区域（蓝色浅底），含示例提示文字 | "例如：使用 CodeBuddy 辅助需求拆解、代码生成" |
| **作品链接模块** | 单列输入框 + 链接列表；每行为一个 URL 输入 + 删除按钮 | GitHub/Gitee/博客/个人主页 |
| **补充信息模块** | textarea + 字数统计 + 示例提示 | 自我评价 100-300 字建议 |

### 技能模块分类

技能模块取消当前扁平 tag 输入，改为分类区域：

```
编程语言：    [Go] [Python] [Java] [C++]    + 输入框
后端框架：    [Gin] [GoFrame]                + 输入框
前端技术：    [React] [Vue]                  + 输入框
数据库：      [MySQL] [Redis] [MongoDB]      + 输入框
中间件：      [Kafka] [RabbitMQ]             + 输入框
云平台：      [Docker] [Kubernetes] [AWS]    + 输入框
开发工具：    [Git] [Linux] [VSCode]         + 输入框
AI 应用技能： [CodeBuddy] [Cursor] [Copilot] + 输入框 ★ 蓝色高亮
其他关键词：  [后端开发]                     + 输入框
```

## 8. 保存区设计

| 元素 | 设计 |
|------|------|
| **位置** | 页面最后一模块（`<section>`），不是 fixed |
| **样式** | `rounded-2xl bg-white ring-1 ring-gray-100 p-6`，与其他模块卡片一致 |
| **左侧说明** | "保存后，Offer捕手 会基于最新保存版本进行岗位推荐、匹配分析和优化建议。" |
| **右侧按钮** | 取消（Link 返回 /resumes）+ 保存简历/创建简历（Primary btn） |
| **Pending** | 按钮 `disabled` + `Loader2` 图标 + "保存中…" |
| **Success** | 绿色提示条（`bg-green-50 ring-green-200`），3 秒自动消失 |
| **Error** | 红色提示条（`bg-red-50 ring-red-200`），需手动关闭 |
| **移动端** | 按钮 `flex-col` 堆叠，主按钮全宽 |

## 9. 响应式策略

| 屏幕 | 策略 |
|------|------|
| **≥1280px** | 双栏：左主内容（flex-1）+ 右侧状态栏（w-[280px] sticky top-28）。双列字段。 |
| **768-1279px** | 单栏：右侧状态栏转为页面顶部的横向状态条（类似当前 ResumeManagementPage 的顶部条）。双列字段保持。 |
| **<768px** | 单栏：双列字段变为单列（`grid-cols-1`）。右侧状态栏转为顶部可折叠条。按钮全宽。卡片内边距缩小（`p-4`）。子卡片 padding 缩小（`p-3`）。 |

### 关键约束

```text
1. 不允许横向滚动。
2. 移动端不在表单旁边保留过重右侧栏。
3. 折叠/展开按钮在移动端保持可点击尺寸（≥44px）。
4. 折叠模块展开动画用 max-height transition（≤300ms）。
```

| 技能信息 | `skills` (9 个分类数组) | 9 分类 |
| 证书与语言 | `certificates[]` (name, type, level, score, issuedAt) | 5/条 |
| 获奖与竞赛 | `awards[]` (name, type, level, awardedAt, description) | 5/条 |
| 作品与补充 | `portfolio` (github, gitee, cnb, blog, demoLinks, portfolioLinks, homepage) + `extraInfo` (selfEvaluation, additionalInfo) | 7+2 |

**保存时**：前端 state → 后端 `CreateResumeRequestV2` payload → 后端按 schema_version=2 写入。

**加载时**：后端 `ResumeVersionResponseV2` → 前端 adapter → 表单 state 回填。
