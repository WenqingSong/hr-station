## 4. 核心约束（不可违反）

1. **阶段 11、12、13 暂停**，不可自动恢复。
2. **不调用腾讯岗位接口**，当前基于本项目 MySQL jobs 表。
3. **不继续 LLM 接入**，后端 Agent 当前走 Mock Agent 模式。
4. **所有用户可见业务数据必须追踪真实来源**，前端不能硬编码/mock/fallback 假业务数据。
5. **后续 prompt 计划必须经过用户允许**，CodeBuddy 不允许私自规划。
6. **不能用 build pass / curl pass / docs pass 替代真实功能完成**。
7. **每次 prompt 结束后必须写入 docs/mcp/** 中的 MCP 上下文记录。
8. **CNB Docker 容器和 CodeBuddy 可能重启**，docs 是恢复上下文的唯一可信入口。
9. **前端没有真实后端接口时**，只能显示空态/错误态/隐藏模块，不能 mock 假业务结果。
10. **当前项目目标是专业化完善设计**，必须优先暴露并消灭低级工程问题。

## 6. 10-P-2-0 工程化清查 P0/P1 问题总表

### 6.1 P0 问题（共 4 个）

| 编号 | 问题 | 证据文件 | 影响 |
|---|---|---|---|
| P0-1 | go.mod 声明 go 1.25.0，系统安装 go 1.24.1 | `server/go.mod:3` → `go 1.25.0`，`go version` → `go1.24.1` | `go run`/`go build` 可能失败，阻塞整个后端 |
| P0-2 | .env.example LLM_ENABLE=true 但无 API Key → 启动时 `log.Fatalf` 崩溃 | `.env.example:58`, `llm/config.go:107-109`(APIKey非空校验) | 新用户 `make up` → 后端启动失败 |
| P0-3 | 5 个前端组件模块顶层 `import mock` 数据，完全绕过 props 和 API | `RecommendationDetail.tsx:6`, `MatchAnalysisDetail.tsx:6`, `ResumeOptimizationDetail.tsx:6`, `RecommendationSidebar.tsx:5`, `RecommendationContext.tsx:4` | 推荐/匹配/优化三个页面的核心内容区域永远展示假数据 |
