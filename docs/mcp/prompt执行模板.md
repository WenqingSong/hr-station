## 章节填写规则

| 章节 | 填写要求 |
|---|---|
| §1 阶段信息 | 固定表头，填入当前阶段编号 |
| §2 本次目标 | 引用上一阶段的"下一步"或本次 prompt 的原目标 |
| §3 本次执行范围 | 区分"执行了"和"仅检查"，防止越权误解 |
| §4 明确未做事项 | **强制**：必须列出 prompt 范围外但可能被误解为"遗漏"的事项 |
| §5 修改文件清单 | **强制**：列出每个修改文件的路径和修改类型，无则写「无」 |
| §6 新增文件清单 | **强制**：同 §5 |
| §7 新增或更新 docs | **强制**：每次 prompt 必须更新至少 2 个 docs 文件 |
| §8 关键决策 | 记录会影响后续阶段的架构/契约/策略决策 |
| §9 验收证据 | **强制**：必须写验证方法（如 `读 router.go`、`grep 返回`），不能只写"pass" |
| §10 当前风险 | 更新本次发现的新风险，P0/P1/P2 分级 |
| §11 不确定项 | **强制**：不确定就写不确定，不假装确认 |
| §12 下次继续前必须读取 | 下一次 prompt 的阅读清单 |
| §13 用户禁止事项 | 汇总本次 prompt 中的限制，防止下一轮越权 |
| §14 重启恢复摘要 | 帮助 CodeBuddy 重启后理解当前进度的最短摘要 |
```

---

## 禁止事项

- ❌ 写 "已完成" 但不给证据
- ❌ 用 "build pass / curl pass / docs pass" 替代真实验证
- ❌ 写 "看起来没问题" / "应该可以" / "基本完成"
- ❌ 在"不确定项"中写"无"但实际有未验证内容
- ❌ 跳过任何章节（14 节全写，无内容写「无」）
- ❌ 不更新 `docs/mcp/项目上下文.md` 中的阶段状态和时间
