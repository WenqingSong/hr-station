# 部署说明

> 最后更新：2026-05-30（阶段 4-3.7.B.R.5 README 与部署说明更新）

## 1. 当前部署目标

当前部署目标是**本地 / 云开发环境可运行**，不是生产部署。

**当前阶段：阶段 4 Agent 与模型接入（进行中）**

## 2. 当前开发环境架构

当前采用**混合式开发环境（方案 B）**：

```text
Docker Compose：
- MySQL（mysql:8.0，端口 3306）
- Nginx（nginx:alpine，端口 80）

Host 本机后台进程：
- Backend：localhost:8080（go run ./cmd/server）
- Frontend：localhost:5173（npm run dev -- --host 0.0.0.0）

Nginx 统一入口：
- http://localhost/        → Frontend
- http://localhost/api/    → Backend（不 strip /api）
- http://localhost/healthz → Backend healthz
```

**关键说明：**

- 当前不是全容器开发模式
- Backend / Frontend 不由 Docker Compose 管理
- Docker Compose 只管理 MySQL + Nginx
- Nginx 通过 `host.docker.internal` 代理到宿主机服务

## 3. 一键启动

```bash
# 1. 复制环境变量（如果 .env 不存在，make up 会自动创建）
cp .env.example .env

# 2. 一键启动
make up
```

`make up` 自动执行：ensure-env → doctor → init → infra-up → db-check → backend-up → web-up → health

启动后访问：

| 入口 | 地址 |
|------|------|
| App | http://localhost/ |
| API | http://localhost/api/ |
| Health | http://localhost/healthz |
| MySQL | localhost:3306 |

## 4. CNB / 云环境重启恢复

```bash
make doctor     # 1. 检查环境
make init       # 2. 补齐 .env、创建目录
make up         # 3. 一键启动
make health     # 4. 健康检查
```

## 5. 常用命令

| 命令 | 说明 |
|------|------|
| `make up` | 启动完整混合式开发环境 |
| `make down` | 关闭完整环境，不清 volume |
| `make restart` | 软重启，不清 volume |
| `make restart-soft` | 同 restart |
| `make status` | 查看完整开发环境状态 |
| `make ps` | 查看 Docker Compose 服务状态 |
| `make logs` | 查看日志入口提示 |
| `make backend-logs` | 后端日志 |
| `make frontend-logs` | 前端日志 |
| `make nginx-logs` | Nginx 容器日志 |
| `make db-logs` | MySQL 容器日志 |
| `make health` | 聚合健康检查 |

## 6. 环境变量准备

| 文件 | 说明 | 提交 Git |
|------|------|---------|
| `.env.example` | 模板，只放占位符 | ✅ 是 |
| `.env.local` | 本地真实配置（含 API Key） | ❌ 否 |
| `.env` | 运行时配置，由 ensure-env 自动生成 | ❌ 否 |

优先级：`.env` 已存在 → 不覆盖；不存在时优先从 `.env.local` 复制，其次从 `.env.example` 复制。

## 7. LLM Key 配置

在本地 `.env` 中配置（不要写入 `.env.example`）：

```env
LLM_ENABLE=true
LLM_API_KEY=sk-your-real-api-key
LLM_BASE_URL=https://your-api-base-url
LLM_MODEL=your-model-name
```

验证连通性：

```bash
make llm-check                          # 检查配置（不请求外部模型）
RUN_REAL_LLM_SMOKE=1 make llm-smoke    # 真实连通性测试
```

## 8. Nginx 统一入口

| 入口 | 目标 | 说明 |
|------|------|------|
| `http://localhost/` | Frontend :5173 | 前端页面（Vite HMR 支持） |
| `http://localhost/api/` | Backend :8080 | 后端 API（不 strip `/api`） |
| `http://localhost/healthz` | Backend :8080/healthz | 健康检查 |

通过 Nginx 访问时，前端和后端属于同源，无需 CORS。

## 9. CORS 策略

| 场景 | 是否需要 CORS |
|------|-------------|
| 通过 `http://localhost/` 访问（Nginx 同源代理） | ❌ 不需要 |
| 前端直连 `http://localhost:8080` 调试 | ✅ 需要 |

CORS 环境变量：

```env
CORS_ALLOWED_ORIGINS=http://localhost,http://localhost:5173
CORS_ALLOWED_METHODS=GET, POST, PUT, PATCH, DELETE, OPTIONS
CORS_ALLOWED_HEADERS=Content-Type, Authorization, X-Requested-With
CORS_ALLOW_CREDENTIALS=false
```

## 10. 本地 / 云开发环境运行方式

### 后台进程管理

| 服务 | PID 文件 | 日志文件 | 端口 |
|------|---------|---------|------|
| Backend | `.run/server.pid` | `.logs/server.log` | 8080 |
| Frontend | `.run/web.pid` | `.logs/web.log` | 5173 |

### 数据库连接

| 项目 | 值 |
|------|------|
| 容器名 | `offer-catcher-mysql` |
| 端口 | 3306 |
| 数据库名 | `offer_catcher` |
| 用户名 | `root` |
| 密码 | 默认 `password`（可通过 `.env` 修改） |

## 11. 生产部署边界

**当前已完成的是开发环境标准化，不是最终生产部署方案。**

| 维度 | 开发环境 | 生产部署（待实现） |
|------|---------|-----------------|
| Docker Compose | MySQL + Nginx | 需单独设计 |
| Backend/Frontend | 本机后台进程 | 需构建镜像或托管 |
| HTTPS | ❌ 无 | ✅ 必须配置 |
| 域名 | localhost | 正式域名 |
| CORS | 允许 localhost | 只允许正式域名 |
| 密钥 | `.env` 占位值 | Secret 注入 |
| `reset` 命令 | 可用 | 禁用 |

### 上线前检查清单

| # | 检查项 | 说明 |
|---|--------|------|
| 1 | 替换 `JWT_SECRET` | 必须为强随机值（≥32 字符） |
| 2 | 替换 `DB_PASSWORD` | 必须为强密码 |
| 3 | 配置正式 `CORS_ALLOWED_ORIGINS` | 只允许正式域名 |
| 4 | 不提交 `.env` | `.env` 不入 Git |
| 5 | 不提交真实 `LLM_API_KEY` | 只保存在服务器环境变量中 |
| 6 | 配置 HTTPS | SSL 证书 + Nginx HTTPS |
| 7 | 配置正式域名 | DNS 解析 + Nginx server_name |
| 8 | 确认数据库备份策略 | 定期备份 MySQL |
| 9 | 禁止生产执行 `reset-up` | `reset` / `reset-up` 仅开发环境可用 |
| 10 | 检查 Nginx 代理 | 确认 `/` `/api/` `/healthz` 路由正确 |

## 12. 禁止事项

1. 不要把开发 `.env` 直接用于生产
2. 不要在生产环境执行 `make reset` / `make reset-up`
3. 不要在 `.env.example` 或 Git 中写入真实密钥
4. 不要使用 `CORS_ALLOWED_ORIGINS=*` 在生产环境
5. 不要暴露 MySQL 3306 端口到公网
6. 不要使用默认 `JWT_SECRET` / `DB_PASSWORD` 在生产环境

## 13. 接口验证示例

### 通过 Nginx（推荐）

```bash
# 健康检查
curl http://localhost/healthz

# 登录
curl -X POST http://localhost/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"arthur@example.com","password":"123456"}'
```

### 直连后端

```bash
# 健康检查
curl http://localhost:8080/healthz

# 登录
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"arthur@example.com","password":"123456"}'
```

### 完整业务接口

```bash
# 获取 token
TOKEN=$(curl -s -X POST http://localhost/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"arthur@example.com","password":"123456"}' \
  | python3 -c "import sys,json; print(json.load(sys.stdin)['data']['token'])")

# 获取岗位列表
curl -s http://localhost/api/jobs -H "Authorization: Bearer $TOKEN"

# 岗位推荐
curl -s -X POST http://localhost/api/jobs/recommend \
  -H "Content-Type: application/json" -H "Authorization: Bearer $TOKEN" -d '{}'

# 岗位匹配
curl -s -X POST http://localhost/api/jobs/1/match \
  -H "Content-Type: application/json" -H "Authorization: Bearer $TOKEN" -d '{}'

# 版本对比
curl -s "http://localhost/api/resumes/versions/compare?from=1&to=2" \
  -H "Authorization: Bearer $TOKEN"
```
