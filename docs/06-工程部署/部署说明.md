## 2. 首次启动流程

### 2.1 一键启动（推荐）

```bash
make up
```

`make up` 自动执行：doctor → init → infra-up → db-check → backend-up → web-up → health

### 2.2 分步启动

```bash
make doctor        # 1. 检查开发环境
make init          # 2. 初始化（复制 .env，提示安装依赖）
make infra-up      # 3. 启动 MySQL
make db-import     # 4. 导入数据库（首次或数据库为空时）
make backend-up    # 5. 启动后端
make web-up        # 6. 启动前端
make backend-health # 7. 健康检查
```

## 3. CNB 环境重启恢复流程

```bash
make doctor     # 1. 检查环境
make init       # 2. 补齐 .env、创建目录
make up         # 3. 一键启动
make health     # 4. 健康检查
```

如果前端依赖缺失：

```bash
make web-install
make web-up
```

如果数据库为空：

```bash
make db-import
```

## 4. 后台运行方式

前后端均以后台进程方式运行，通过 PID 文件管理：

| 服务 | PID 文件 | 日志文件 | 端口 |
|------|---------|---------|------|
| 后端 | `.run/server.pid` | `.logs/server.log` | 8080 |
| 前端 | `.run/web.pid` | `.logs/web.log` | 5173 |

管理命令：

```bash
make backend-up / backend-stop / backend-restart
make web-up / web-stop / web-restart
```

## 5. 日志查看方式

```bash
make logs           # 查看日志入口提示
make logs-backend   # 查看后端日志
make logs-web       # 查看前端日志
make logs-mysql     # 查看 MySQL 日志
make logs-agent     # 查看 Agent 相关日志
```

## 6. 健康检查方式

```bash
make health           # 聚合健康检查（推荐）
make backend-health   # curl /healthz
make web-health       # 检查前端端口
make db-check         # 检查数据库核心表
make status           # 查看所有服务状态
```

`make health` 是 4-1.1.3 新增的聚合健康检查命令，一次检查基础设施、后端、前端、数据库四个维度的健康状态。

## 7. 数据库重置方式

```bash
make db-reset CONFIRM=yes   # 重新导入初始化 SQL（危险）
make db-shell               # 进入 MySQL shell
make db-check               # 检查核心表
```

## 11. 接口验证示例

### 认证接口

```bash
# 登录
curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"arthur@example.com","password":"123456"}'

# 获取当前用户（需要 token）
curl -s http://localhost:8080/api/auth/me \
  -H "Authorization: Bearer <token>"
```

### 业务接口

```bash
# 获取 token
TOKEN=$(curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"arthur@example.com","password":"123456"}' \
  | python3 -c "import sys,json; print(json.load(sys.stdin)['data']['token'])")

# 获取当前简历
curl -s http://localhost:8080/api/resumes/current -H "Authorization: Bearer $TOKEN"

# 获取岗位列表
curl -s http://localhost:8080/api/jobs -H "Authorization: Bearer $TOKEN"

# 岗位推荐
curl -s -X POST http://localhost:8080/api/jobs/recommend \
  -H "Content-Type: application/json" -H "Authorization: Bearer $TOKEN" -d '{}'

# 岗位匹配
curl -s -X POST http://localhost:8080/api/jobs/1/match \
  -H "Content-Type: application/json" -H "Authorization: Bearer $TOKEN" -d '{}'

# 版本对比
curl -s "http://localhost:8080/api/resumes/versions/compare?from=1&to=2" \
  -H "Authorization: Bearer $TOKEN"
```

## 12. 数据卷说明

| 命令 | 是否删除数据卷 | 说明 |
|------|--------------|------|
| `make down` | ❌ 不删除 | 数据保留在 `mysql_data` 卷中 |
| `make stop` | ❌ 不删除 | 只停止前后端进程 |
| `make clean-volume CONFIRM=yes` | ✅ 删除 | ⚠️ 危险操作 |

## 13. 常见问题

### Q: CNB 环境重启后如何恢复？

```bash
make doctor → make init → make up → make health
```

### Q: 前端依赖缺失？

```bash
make web-install
```

### Q: 数据库为空？

```bash
make db-import
```

### Q: 后端启动失败？

1. 确认 MySQL 已启动：`make infra-status`
2. 确认端口未被占用：`make doctor`
3. 如果 8080 端口残留，执行 `make backend-stop` 清理
4. 查看日志：`make logs-backend`

### Q: 后端端口 8080 被占用？

```bash
make backend-stop    # 自动清理残留进程和端口
```

不建议手动 `kill`，除非 `make backend-stop` 失效。

### Q: 如何清空数据库重建？

```bash
make db-reset CONFIRM=yes
```

### Q: LLM API Key 填在哪里？

填在 `.env` 文件中，不要写入 `.env.example`：

```env
LLM_API_KEY=sk-your-real-api-key
```

### 腾讯岗位原始数据拉取

已接入 Makefile，推荐使用以下命令：

```bash
# 检查配置
make jobs-check

# 查看本地状态
make jobs-status

# 查看样本
make jobs-sample

# 真正拉取数据
make jobs-fetch

# 小规模测试拉取
TENCENT_JOBS_PAGE_SIZE=5 TENCENT_JOBS_MAX_PAGES=1 make jobs-fetch

# 清理本地原始 JSON
make jobs-clean
```

说明：当前不会入库，拉取的原始数据仅保存在 `data/tencent-jobs/raw/` 下。

### 腾讯岗位清洗与入库

已编写清洗与入库脚本，当前尚未接入 Makefile，推荐直接使用脚本：

```bash
# 检查环境和原始数据
scripts/dev/tencent_jobs_import.sh check

# 预览将导入的岗位
scripts/dev/tencent_jobs_import.sh preview

# 生成导入 SQL
scripts/dev/tencent_jobs_import.sh generate-sql

# 执行导入（先拉取数据，再导入）
scripts/dev/tencent_jobs_import.sh import

# 查看数据库岗位状态
scripts/dev/tencent_jobs_import.sh status

# 清理生成的临时文件
scripts/dev/tencent_jobs_import.sh clean-generated
```

说明：
- 脚本从本地 `data/tencent-jobs/raw/` 读取原始 JSON，不请求腾讯接口
- 使用 `ON DUPLICATE KEY UPDATE` 实现幂等导入
- 不删除本地 Mock 岗位
- 4-1.3.3 后将接入 Makefile，届时可使用 `make jobs-import` 等命令
