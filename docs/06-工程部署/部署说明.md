## 3. 首次启动流程

### 3.1 前置条件

确保以下工具已安装：

|| 工具 | 用途 | 检查命令 |
||------|------|---------|
|| Go 1.22+ | 后端开发 | `go version` |
|| Node.js 18+ | 前端开发 | `node --version` |
|| npm | 前端依赖管理 | `npm --version` |
|| Docker | MySQL 容器 | `docker --version` |
|| Docker Compose | 服务编排 | `docker compose version` |

### 3.2 启动步骤

```bash
# 1. 检查开发环境
make doctor

# 2. 初始化开发环境（复制 .env，提示安装依赖）
make init

# 3. 启动 MySQL
make up

# 4. 启动前端（建议开新终端）
make dev-web

# 5. 启动后端（建议开新终端）
make dev-server
```

### 3.3 步骤说明

|| 步骤 | 命令 | 说明 |
||------|------|------|
| 1 | `make doctor` | 只读检查工具、项目文件、Docker 状态、端口占用 |
| 2 | `make init` | 幂等初始化：`.env` 不存在则从 `.env.example` 复制；提示安装前端依赖 |
| 3 | `make up` | 启动 Docker Compose（MySQL），约 30 秒变为 healthy |
| 4 | `make dev-web` | 启动前端 Vite 开发服务，默认端口 5173 |
| 5 | `make dev-server` | 启动 Go 后端 HTTP Server，默认端口 8080 |

**重要提示：**

1. 前端和后端建议分别在不同终端运行，便于查看各自日志
2. `make up` 当前只启动 MySQL，不包含前端和后端
3. 当前后端只提供 `/healthz` 健康检查接口
4. 当前前端仍使用 Mock 数据，尚未接后端 API
5. 阶段 2-5 后后端启动需要 MySQL 已运行，否则启动失败

## 4. CNB 环境重启恢复流程

CNB 云原生开发环境重启后，所有本地进程和 Docker 容器都会停止。按以下步骤恢复：

```bash
# 1. 检查环境
make doctor

# 2. 初始化（补齐 .env）
make init

# 3. 启动 MySQL
make up

# 4. 确认 MySQL 就绪
make status

# 5. 启动前端（新终端）
make dev-web

# 6. 启动后端（新终端）
make dev-server
```

### 恢复流程详解

|| 步骤 | 作用 | 说明 |
||------|------|------|
| `make doctor` | 检查环境状态 | 确认工具链、`.env`、`docker-compose.yml`、server、web 是否存在 |
| `make init` | 恢复 `.env` | `.env` 不存在时从 `.env.example` 复制，幂等操作 |
| `make up` | 启动 MySQL | 重新启动 Docker 容器，数据卷 `mysql_data` 保留之前的数据 |
| `make status` | 确认就绪 | 查看容器健康状态，约 30 秒变为 healthy |
| `make dev-web` | 启动前端 | 如 `node_modules` 丢失，需先 `cd web && npm install` |
| `make dev-server` | 启动后端 | Go 依赖会自动下载 |

### 关键说明

1. 如果 `node_modules` 丢失，根据 `make init` 提示安装：`cd web && npm install`
2. 如果 MySQL 数据卷还在，`make down` / `make restart` 不会删除数据
3. 如果需要重建数据库环境，使用 `make reset`，但它是危险命令（需手动确认 `docker compose down -v`）
4. Go 依赖通过 `go run` 时自动下载，无需手动操作

  -H "Content-Type: application/json" \

## 7. MySQL 启动与查看

### 启动与管理

```bash
make up           # 启动 MySQL
make status       # 查看容器状态
make logs-mysql   # 查看 MySQL 日志（实时跟踪）
make down         # 停止 MySQL（不删数据）
make restart      # 重启 MySQL
```

### MySQL 连接信息

|| 项目 | 值 |
||------|------|
| 容器名 | `offer-catcher-mysql` |
| 端口 | 3306 |
| 数据库名 | `offer_catcher` |
| 用户名 | `root` |
| 密码 | 默认 `password`（可通过 `.env` 中 `MYSQL_ROOT_PASSWORD` 修改） |
| 字符集 | utf8mb4 |
| 时区 | Asia/Shanghai |

### 连接 MySQL

```bash
# 本地客户端连接
mysql -h 127.0.0.1 -P 3306 -u root -ppassword offer_catcher

# Docker 容器内连接
docker compose exec mysql mysql -uroot -ppassword offer_catcher
```

### 数据卷说明

| 命令 | 是否删除数据卷 | 说明 |
|------|--------------|------|
| `make down` | ❌ 不删除 | 数据保留在 `mysql_data` 卷中 |
| `make restart` | ❌ 不删除 | 只重启容器，数据保留 |
| `make reset` | ✅ 删除 | ⚠️ 危险操作，需手动执行 `docker compose down -v` |

### 当前阶段说明

1. 阶段 2-5 后后端启动时会连接 MySQL 并 Ping 验证
2. 如果 MySQL 未启动，后端启动会失败（这是预期行为）
3. 阶段 3 才会写真实表结构与种子数据
4. MySQL 已通过 `docker-compose.yml` 配置好，`make up` 启动后后端可连接

## 10. 常见问题

### 1. make doctor 提示 .env 不存在

`.env` 文件由 `make init` 从 `.env.example` 复制生成。执行：

```bash
make init
```

如果 `.env.example` 也不存在，说明阶段 1-3 未完成，请先完成环境变量示例创建。

### 2. docker compose 命令不可用

1. 确认 Docker 已安装：`docker --version`
2. 确认 Docker Compose 已安装：`docker compose version`
3. 如果使用旧版 Docker，可能需要 `docker-compose`（带连字符）命令
4. 确认 Docker 守护进程正在运行：`docker info`

### 3. MySQL 端口 3306 被占用

1. 检查占用进程：`lsof -i :3306` 或 `ss -tlnp | grep 3306`
2. 停止占用进程，或修改 `.env` 中 `MYSQL_PORT` 为其他端口
3. 如果修改了 `MYSQL_PORT`，需同时修改 `DB_PORT` 保持一致
4. 修改后重启：`make restart`

### 4. make dev-web 启动失败

1. 检查 `web/node_modules` 是否存在：`ls web/node_modules`
2. 如果不存在，安装依赖：`cd web && npm install`
3. 检查 Node.js 版本：`node --version`（需要 18+）
4. 检查 `web/package.json` 是否存在

### 5. make dev-server 启动失败

1. 检查 Go 是否安装：`go version`
2. 检查 `server/go.mod` 是否存在：`ls server/go.mod`
3. 尝试手动启动查看错误：`cd server && go run ./cmd/server`
4. 检查端口 8080 是否被占用：`lsof -i :8080`
5. 如果端口被占用，修改 `.env` 中 `SERVER_PORT` 或停止占用进程

### 6. curl /healthz 无响应

1. 确认后端进程是否在运行
2. 确认端口是否正确（默认 8080）
3. 检查端口是否被占用：`lsof -i :8080`
4. 查看后端终端日志是否有错误输出

### 7. CNB 环境重启后服务都停了

这是正常的。CNB 环境重启后所有本地进程和 Docker 容器都会停止。按恢复流程执行：

```bash
make doctor      # 检查环境
make init        # 补齐 .env
make up          # 启动 MySQL
make status      # 确认就绪
make dev-web     # 启动前端（新终端）
make dev-server  # 启动后端（新终端）
```

### 8. 想清空 MySQL 数据重新来

执行危险命令（需手动确认）：

```bash
docker compose down -v
```

这会删除 `mysql_data` 数据卷，MySQL 中所有数据将丢失。

`make reset` 只输出提示，不会自动执行。

### 9. 前端页面没有真实数据

当前前端使用硬编码 Mock 数据，不接后端 API。这是正常的。

- 阶段 5 才会正式接后端 API
- 当前阶段前端页面仅用于预览和 UI 验证

### 10. LLM API Key 应该填在哪里

LLM API Key 应填写在 `.env` 文件中，不要写入 `.env.example`：

```env
LLM_BASE_URL=https://your-llm-api-endpoint
LLM_API_KEY=sk-your-real-api-key
LLM_MODEL=your-model-name
```

- LLM 相关变量阶段 4 才会真正使用
- 当前阶段只需预留，不需要填写
- `.env` 不应提交到代码仓库
