# 文档更新规范

## 1. 规范目标

确保项目文档始终与代码和决策同步，为后续模型接手和团队协作提供可靠信息源。

## 2. 必须更新的根文档

每次任务完成后，必须更新以下根文档：

| 文档 | 更新内容 |
|------|---------|
| `docs/项目状态.md` | 当前阶段、已完成任务、各模块状态、风险 |
| `docs/下一步任务.md` | 任务进度、待执行任务 |
| `docs/变更记录.md` | 追加本次变更（新增/修改/删除/备注） |
| `docs/09-开发日志/YYYY-MM-DD-序号-任务名.md` | 创建完整开发日志 |

## 3. 模块文档更新规则

| 任务类型 | 必须更新的模块文档 |
|---------|-----------------|
| 前端任务 | `docs/01-前端设计/` 相关文档 |
| 后端任务 | `docs/02-后端设计/` 相关文档 |
| 数据库任务 | `docs/03-数据库设计/` 相关文档 |
| 接口任务 | `docs/04-接口文档/` 相关文档 |
| Agent 任务 | `docs/05-Agent设计/` 相关文档 |
| 部署任务 | `docs/06-工程部署/` 相关文档 |
| 产品范围任务 | `docs/00-项目总览/` 相关文档 |

## 4. 开发日志规则

### 命名规则

```
docs/09-开发日志/YYYY-MM-DD-三位序号-中文任务名.md
```

示例：

```
docs/09-开发日志/2026-05-28-005-工程执行规范与CodeBuddy工作规则.md
docs/09-开发日志/2026-05-28-006-阶段0汇总.md
```

### 必须包含的章节

```markdown
# YYYY-MM-DD-序号-任务名

## 1. 本次任务
## 2. 修改范围
## 3. 新增内容
## 4. 修改内容
## 5. 删除内容
## 6. 关键决策
## 7. 未修改内容
## 8. 当前风险
## 9. 如何验证
## 10. 下一步建议
```

所有章节不能留空，没有内容写「无」。

## 5. 变更记录规则

每次变更记录格式：

```markdown
## YYYY-MM-DD - 阶段 X-Y - 任务名

### 新增
- 具体新增内容

### 修改
- 具体修改内容

### 删除
- 具体删除内容（无则写「无」）

### 备注
- 补充说明
```

变更记录按时间倒序排列，最新的在最上面。

## 6. 项目状态更新规则

`docs/项目状态.md` 每次更新必须包含：

1. 更新日期
2. 当前阶段
3. 已完成任务表
4. 各模块当前状态（前端/后端/docs/Docker/Makefile）
5. 当前主要风险
6. 当前不能做的事情
7. 下一阶段目标

## 7. 下一步任务更新规则

`docs/下一步任务.md` 每次更新必须：

1. 标记已完成任务（✅）
2. 标记待执行任务（⬜）
3. 保留后续阶段任务供参考
4. 标注最后更新日期

## 8. ADR 更新规则

架构决策记录（ADR）更新规则：

1. 新增 ADR 使用编号递增：`ADR-序号-中文标题.md`
2. ADR 必须标记状态：已接受 / 已废弃 / 待讨论
3. 已废弃的 ADR 不删除，标记废弃并注明原因
4. ADR 内容变更需记录在变更记录中

## 9. 文档内容质量要求

1. 使用中文
2. Markdown 格式
3. 标题层级清楚（不跳级）
4. 列表使用统一格式
5. 不写营销话术
6. 不写空泛表达
7. 内容要具体、可执行
8. 为后续模型接手服务
9. 为后续工程实现服务
10. 保持文档间引用关系正确

## 10. 新模型接手阅读顺序

新模型或新会话接手本项目时，按以下顺序阅读：

```
1. docs/说明书.md
2. docs/项目状态.md
3. docs/下一步任务.md
4. docs/变更记录.md
5. docs/09-开发日志/ 中最近一篇日志
6. 根据任务类型阅读对应模块文档
```
