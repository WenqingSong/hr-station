# 腾讯招聘信息接入方案

> 创建时间：2026-05-29
> 所属阶段：4-1.2.1
> 最后更新：2026-05-29（阶段 4-1.2.6 阶段 4-1.2 汇总）
> 依据文档：腾讯招聘必要接口确认报告、腾讯招聘公开接口探测报告、腾讯招聘岗位详情接口探测报告

## 1. 方案目标

将腾讯招聘官网公开招聘岗位数据作为本项目 Demo 的外部岗位数据源，通过低频同步 + 本地缓存策略，丰富岗位池，提升岗位推荐和匹配分析的演示效果。

核心目标：

1. 接入腾讯招聘公开岗位列表和岗位详情数据
2. 数据同步后写入本地岗位数据体系
3. 推荐 / 匹配 / 前端展示全部读取本地 jobs 表
4. 不实时依赖 join.qq.com

## 2. 当前探测结论

基于 4-1.2.0、4-1.2.0.1、4-1.2.0.2 三个探测阶段的结论：

| 接口 | 确认状态 | URL | 方法 | 关键返回 |
|------|---------|-----|------|---------|
| 岗位列表 | ✅ 已确认 | `https://join.qq.com/api/v1/position/searchPosition` | POST | positionList + count，含 postId |
| 岗位详情 | ✅ 已确认 | `https://join.qq.com/api/v1/jobDetails/getJobDetailsByPostId` | GET | 完整 JD（desc + request + 加分项 + 事业群详情） |
| 字典 | ✅ 已确认 | `https://join.qq.com/api/v1/dictionary/` | GET | 招聘类型/事业群/岗位类别/城市映射 |

4-1.2.0.1 曾得出"未发现详情接口"的结论，4-1.2.0.2 通过分析前端 JS bundle 修正了此结论。方案以 4-1.2.0.2 为准。

### 3.2 本次不接入

- 应聘进度接口
- 简历上传接口
- 验证码接口
- 任何需要 Cookie / Token / 登录态的接口

### 3.3 本次不做

- 不写正式同步脚本（4-1.2.3 做）
- 不修改数据库（4-1.3 做）
- 不修改后端接口（4-1.3 做）
- 不修改前端页面（阶段 5 做）

## 5. 岗位列表接口接入策略

### 5.1 用途

- 获取岗位池（总数、分页列表）
- 提取 `postId` 供详情接口使用
- 提供基础筛选（项目类型、关键词、城市）
- 列表字段作为详情数据的补充

### 5.2 请求方式

```
POST https://join.qq.com/api/v1/position/searchPosition
Content-Type: application/json
User-Agent: Mozilla/5.0
Referer: https://join.qq.com/post.html?query=p_2
Origin: https://join.qq.com
```

### 5.3 请求体

```json
{
  "bgList": [],
  "keyword": "",
  "pageIndex": 1,
  "pageSize": 100,
  "positionFidList": [],
  "projectIdList": [],
  "projectMappingIdList": [2],
  "recruitCityList": [],
  "workCityList": [],
  "workCountryType": 0
}
```

### 5.4 同步策略

1. 使用 `projectMappingIdList=[2]`（应届实习，岗位最多）作为默认配置
2. `pageSize=100`，循环分页获取全量
3. 不并发请求，每页间隔 ≥ 2 秒
4. 提取每条岗位的 `postId` 作为详情接口的参数

### 5.5 返回字段利用

| 列表字段 | 用途 | 说明 |
|---------|------|------|
| postId | 传入详情接口 | 最关键参数 |
| positionTitle | 列表展示 | 与详情接口 title 一致 |
| bgs | 部门缩写 | 列表级快速筛选 |
| workCities | 城市列表 | 列表级快速筛选 |
| positionFamily | 岗位大类 code | 需字典映射 |
| projectId | 项目 ID | 详情接口参数 |
| projectName | 项目名称 | 直接使用 |
| id | 内部 ID | 存入 external_inner_id |

## 6. 岗位详情接口接入策略

### 6.1 用途

- 获取完整岗位职责（desc）
- 获取完整任职要求（request）
- 获取加分项（internBonus / graduateBonus）
- 获取事业群详情（intentionBGDList，含部门层级）
- 获取城市名称列表（workCityList / recruitCityList）

### 6.2 请求方式

```
GET https://join.qq.com/api/v1/jobDetails/getJobDetailsByPostId?postId={postId}
User-Agent: Mozilla/5.0
Referer: https://join.qq.com/detail.html
```

### 6.3 关键参数

| 参数 | 来源 | 说明 |
|------|------|------|
| postId | 列表接口 `postId` 字段 | 岗位帖子 ID |

### 6.4 同步策略

1. 从列表接口获取全部 postId 后，逐个调用详情接口
2. 每次请求间隔 ≥ 3 秒
3. 不并发请求
4. 详情接口返回的完整数据存入 raw_json

### 6.5 返回字段与 jobs 表映射

| 详情字段 | 用途 | 映射到 jobs 表 | 备注 |
|---------|------|---------------|------|
| title | 岗位名称 | title | 直接映射 |
| desc | 完整岗位职责 | description | 核心字段 |
| request | 完整任职要求 | requirements | 核心字段 |
| tidName | 岗位大类名称 | category | "技术"/"产品"等，无需字典 |
| intentionBGDList | 事业群详情 | department | 取第一个 BG 的 showTitle |
| workCityList | 工作城市名称列表 | city | 逗号拼接 |
| projectName | 项目名称 | job_type | "应届实习"/"应届毕业生" |
| internBonus | 实习加分项 | raw_json | 不单独映射，存入 raw_json |
| graduateBonus | 校招加分项 | raw_json | 不单独映射，存入 raw_json |
| introduction | 岗位介绍 | raw_json | 不单独映射，存入 raw_json |

### 6.6 备用接口

```
GET https://join.qq.com/api/v1/jobDetails/getJobDetailsByPidAndId?pid={projectId}&id={position}
```

参数说明：
- `pid` = 列表接口的 `projectId`
- `id` = 列表接口的 `position`（注意：不是列表的 `id` 字段）

此接口作为备用，4-1.2.3 实现时优先使用 `getJobDetailsByPostId`。

## 7. 字典接口接入策略

### 7.1 用途

- 辅助列表接口的 code→name 映射
- 提供 projectMappingIdList 的配置选项
- 提供城市 code→名称的映射

### 7.2 请求方式

```
GET https://join.qq.com/api/v1/dictionary/?types=RecruitType,BusinessGroup,RecruitProjectPostList,RecruitCity
User-Agent: Mozilla/5.0
Referer: https://join.qq.com/
```

### 7.3 返回字典

| 字典类型 | 数量 | 用途 |
|---------|------|------|
| RecruitType | 3 | 招聘类型映射 |
| BusinessGroup | 10 | 事业群 code→name |
| RecruitProjectPostList | 5 | 岗位大类 code→name |
| RecruitCity | 57 | 城市 code→name |

### 7.4 接入优先级

- P1（可选增强），不阻塞列表和详情接口接入
- 详情接口已返回 `workCityList`（城市名称）和 `tidName`（岗位大类名称），大部分映射不需要字典
- 字典主要用于列表接口的 bgs/positionFamily 映射
- 建议后续 4-1.2.3 中一并接入，缓存到本地 JSON

### 7.5 是否必须接入

⬜ 非必须，但建议接入。时间允许再接。

## 9. 同步策略

### 9.1 核心原则

**低频同步 + 本地缓存 / 本地导入**

- 前端不直接请求 join.qq.com
- 后端业务接口不实时代理 join.qq.com
- 每次推荐 / 匹配 / 前端展示全部读取本地 jobs 表

### 9.2 禁止策略

| 禁止 | 原因 |
|------|------|
| 前端实时请求 join.qq.com | CORS 限制、性能、稳定性 |
| 后端业务接口实时代理 join.qq.com | 依赖外部、不可控 |
| 每次推荐/匹配时实时请求 | 性能、稳定性 |
| 高频定时任务 | 限流风险 |

### 9.3 推荐同步流程

```
步骤 1：调用岗位列表接口，获取岗位分页数据
步骤 2：从岗位列表中提取 postId / external_id
步骤 3：对每个岗位低频调用岗位详情接口（间隔 ≥ 3 秒）
步骤 4：合并列表字段和详情字段
步骤 5：生成标准化岗位原始数据
步骤 6：保存到本地 JSON 缓存（4-1.2.3 中实现）
步骤 7：后续导入 jobs 表（4-1.3 中实现）
步骤 8：推荐 / 匹配 / 前端展示全部读取本地数据
```

### 9.4 同步频率

- 初始同步：手动触发一次全量同步
- 增量同步：可选，Demo 阶段不需要
- 不设置自动定时任务

### 9.5 阶段边界

- **4-1.2** 只处理"外部公开岗位数据源接入"
- **4-1.3** 才处理"适配到本项目 jobs 表与后端业务"

## 12. 数据质量策略

### 12.1 质量标记定义

| data_quality 值 | 含义 | 数据来源 | 用途 |
|----------------|------|---------|------|
| `full_jd` | 完整 JD | 岗位详情接口返回完整 desc + request | 可用于深度匹配分析 |
| `summary_only` | 仅列表摘要 | 只有列表接口字段，详情接口未获取 | 只用于列表展示和轻量推荐 |
| `manual_enriched` | 人工补充 | 本地 Mock 岗位数据 | 可用于深度匹配分析 |

### 12.2 当前策略

- 腾讯岗位优先标记为 `full_jd`（详情接口已确认可用）
- 如果某条腾讯岗位详情获取失败，降级为 `summary_only`
- 原有本地 Mock 岗位标记为 `manual_enriched`
- 8 条种子岗位保持不变，作为本地精选 Demo 岗位

### 12.3 质量与 Agent 的关系

| data_quality | 推荐可用 | 匹配分析可用 | 说明 |
|-------------|---------|------------|------|
| full_jd | ✅ | ✅ | 完整 JD 支持深度证据链 |
| summary_only | ✅ | ⚠️ 受限 | 只有标题和城市，证据链不完整 |
| manual_enriched | ✅ | ✅ | Mock 数据有完整 JD |

## 14. 与推荐 / 匹配 Agent 的关系

### 14.1 岗位推荐

- 推荐从本地 jobs 表中读取腾讯岗位
- 推荐 Agent 不直接调用 join.qq.com
- 推荐输入可包含：岗位标题、岗位类别、城市、事业群、招聘项目、职责描述、岗位要求、加分项

### 14.2 岗位匹配分析

- 匹配分析使用本地 jobs 表中的完整 JD
- 匹配 Agent 不直接调用 join.qq.com
- 匹配输入可包含：description、requirements、bonus、department、city、category、job_type

### 14.3 兜底策略

| 场景 | 兜底方案 |
|------|---------|
| 腾讯接口不可用 | 不影响已有本地 Mock 岗位和 Mock Agent 主链路 |
| 某条腾讯岗位详情缺失 | 该岗位降级为 `summary_only`，仍可在列表展示 |
| 腾讯接口增加鉴权 | Mock 数据兜底，8 条种子岗位仍可正常使用 |
| 接口字段变化 | raw_json 保存原始数据，字段映射层做容错 |

## 15. 失败兜底策略

### 15.1 同步失败

| 失败场景 | 处理方式 |
|---------|---------|
| 列表接口返回非 200 | 记录错误日志，跳过本次同步 |
| 详情接口返回非 200 | 该岗位标记为 summary_only，不阻断其他岗位 |
| 详情接口返回空 data | 该岗位标记为 summary_only |
| 同步中途断网 | 已同步数据保留，下次从断点续传 |

### 15.2 数据降级

- 详情获取失败的岗位 → `data_quality = summary_only`
- 全部接口不可用 → 8 条本地 Mock 岗位仍可正常工作
- 字段映射异常 → raw_json 中仍有原始数据

## 16. 请求频率与安全边界

### 16.1 频率限制

| 接口 | 单次间隔 | 单次批量 | 日总量上限 |
|------|---------|---------|-----------|
| 列表接口 | ≥ 2 秒/页 | 每页 100 条 | ≤ 50 次/天 |
| 详情接口 | ≥ 3 秒/条 | 每次 1 条 | ≤ 300 次/天 |
| 字典接口 | ≥ 5 秒 | 每次 1 次 | ≤ 10 次/天 |

### 16.2 安全边界

| 场景 | 处理方式 |
|------|---------|
| 出现 403 | 立即停止同步，记录日志 |
| 出现 429 | 立即停止同步，间隔 10 分钟后重试 |
| 出现验证码页面 | 立即停止同步，不重试 |
| 出现风控拦截 | 立即停止同步，不重试 |

### 16.3 不做的事

- 不并发请求
- 不循环爆破路径
- 不请求登录态接口
- 不绕过 CORS / 风控

## 21. 拉取脚本说明

4-1.2.3 已新增 `scripts/dev/tencent_jobs.sh`，支持以下命令：

| 命令 | 说明 |
|------|------|
| help | 查看帮助 |
| check | 检查配置项、URL、输出目录、依赖工具 |
| fetch-list | 拉取岗位列表原始 JSON |
| fetch-details | 基于 positions.json 中的 postId 拉取岗位详情原始 JSON |
| fetch-dictionary | 拉取字典原始 JSON |
| fetch-all | 依次执行 fetch-list、fetch-details、fetch-dictionary |
| sample | 打印本地岗位样本摘要 |
| status | 查看本地原始数据文件状态 |
| clean | 清理 data/tencent-jobs/raw 下生成的 JSON 文件 |

输出目录：`data/tencent-jobs/raw/`

输出文件：

| 文件 | 说明 |
|------|------|
| positions.json | 岗位列表原始数据（含 source、fetched_at、total、count、items） |
| details.json | 岗位详情原始数据（含 source、fetched_at、count、items） |
| dictionary.json | 字典原始数据（含 source、fetched_at、ok、response） |
| metadata.json | 元数据（含 source、fetched_at、config、files、summary） |

配置读取规则：

1. 环境变量最高优先（支持 `TENCENT_JOBS_PAGE_SIZE=5 TENCENT_JOBS_MAX_PAGES=1 scripts/dev/tencent_jobs.sh fetch-all`）
2. `.env` 次之
3. `.env.example` 兜底
