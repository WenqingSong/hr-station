# 腾讯招聘公开接口探测报告

> 探测时间：2026-05-29
> 探测目的：验证腾讯招聘公开岗位接口是否可用、分页是否稳定、字段结构是否清晰、是否适合后续作为公开岗位数据源接入

## 1. 探测目标

验证腾讯招聘官网公开招聘页面背后的公开接口，判断是否适合作为本项目的岗位数据源：

- 岗位列表接口是否可访问
- 分页规则是否稳定
- 字段结构是否清晰
- 字典接口是否可用
- 与当前 `jobs` 表的字段映射可行性

## 2. 探测范围

| 接口 | 类型 | 用途 |

| `/api/v1/position/searchPosition` | POST | 岗位列表搜索 |

只使用公开招聘页面（`https://join.qq.com/post.html`）背后的公开接口，不请求任何需要登录或鉴权的接口。

### 12.2 字段重要发现

1. **列表接口不返回 JD 正文**：没有 `description`（岗位描述）和 `requirements`（岗位要求）字段
2. **城市字段是空格分隔字符串**：`workCities` 格式为 "深圳总部 北京 上海 "
3. **事业群字段是空格分隔字符串**：`bgs` 格式为 "CDG CSIG IEG "
4. **有两种 ID**：`id`（数字）和 `postId`（长字符串）
5. **positionFamily 需字典映射**：2=技术、3=产品/职能、5=其他、6=职能
6. **position 是子分类 code**：如 101=后台开发，257=多模态算法

## 13. 与当前 jobs 表映射初判

当前 `jobs` 表字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT UNSIGNED PK | 自增主键 |
| title | VARCHAR(200) | 岗位名称 |
| department | VARCHAR(200) | 部门 |
| city | VARCHAR(100) | 城市 |
| category | VARCHAR(100) | 方向分类 |
| job_type | VARCHAR(100) | 岗位类型 |
| description | TEXT | 岗位描述 |
| requirements | TEXT | 岗位要求 |
| skill_keywords_json | JSON | 技能关键词 |
| created_at | DATETIME | 创建时间 |
| updated_at | DATETIME | 更新时间 |

### 13.1 字段映射表

| 腾讯字段 | 当前 jobs 字段 | 映射可行性 | 备注 |
|---------|--------------|-----------|------|
| positionTitle | title | ✅ 直接映射 | "软件开发-后台开发方向" |
| bgs | department | ⚠️ 需转换 | bgs 是事业群 code 列表，需字典映射取第一个或拼接 |
| workCities | city | ⚠️ 需转换 | 空格分隔多城市，取第一个或保留全部 |
| positionFamily | category | ⚠️ 需字典映射 | 2=技术，需 RecruitProjectPostList 映射 |
| projectName / recruitLabelName | job_type | ✅ 可映射 | "应届实习" → job_type |
| — | description | ❌ 列表接口无此字段 | 需岗位详情接口或填充默认值 |
| — | requirements | ❌ 列表接口无此字段 | 需岗位详情接口或填充默认值 |
| — | skill_keywords_json | ❌ 列表接口无此字段 | 需从标题/描述提取或留空 |
| id / postId | — | ❌ 当前 jobs 表缺 external_id | 需新增字段存储原始 ID |
| 整条记录 JSON | — | ❌ 当前 jobs 表缺 raw_json | 需新增字段存储原始数据 |

### 13.2 映射难点

1. **列表接口缺少 JD 正文**：最关键的 `description` 和 `requirements` 在列表接口中不存在
2. **城市多值**：一个岗位可能对应多个工作城市，需决定取第一个还是全部保留
3. **事业群是 code 列表**：需字典接口做 code→name 映射
4. **缺少技能关键词**：skill_keywords_json 无法直接映射

## 15. 技术风险

### 15.1 接口字段变化风险

- **风险**：接口返回字段结构可能随版本更新变化
- **严重度**：🟡 中
- **应对**：使用 raw_json 保存原始数据，字段映射层做容错

### 15.2 接口限流风险

- **风险**：高频请求可能触发限流或风控
- **严重度**：🟡 中
- **应对**：本地缓存 + 低频同步（如每日一次）

### 15.3 接口增加鉴权风险

- **风险**：接口可能未来增加鉴权要求
- **严重度**：🟡 中
- **应对**：Mock 数据兜底，不依赖实时接口

### 15.4 projectMappingIdList 语义变化风险

- **风险**：项目类型 code 语义可能变化
- **严重度**：🟢 低
- **应对**：通过字典接口动态获取最新映射

### 15.5 pageSize 上限变化风险

- **风险**：大 pageSize 可能被限制
- **严重度**：🟢 低
- **应对**：使用合理 pageSize（如 100），支持分页循环

### 15.6 列表接口缺少 JD 正文

- **风险**：列表接口不返回 description 和 requirements
- **严重度**：🔴 高
- **应对**：后续需探测岗位详情接口，或使用 positionTitle + 字典做基础映射

## 16. 工程风险

### 16.1 不应前端实时请求

- 前端不应直接请求 `join.qq.com` 接口
- 应通过后端做本地数据同步

### 16.2 不应后端接口每次实时代理

- 后端不应每次请求实时代理腾讯接口
- 应做本地数据存储和定时同步

### 16.3 应做本地缓存

- 腾讯岗位数据应本地缓存到 `jobs` 表
- 同步频率低（如每日一次）

### 16.4 完整岗位数据不宜提交仓库

- 完整岗位 JSON 数据不应提交到 Git 仓库
- 数据量大且变化频繁

### 16.5 需要字段清洗层

- 腾讯接口字段与 `jobs` 表字段不完全对应
- 需要清洗/转换层做映射

### 16.6 需要保留 Mock 数据兜底

- 当前 8 条种子岗位仍作为兜底
- 腾讯岗位数据作为增量

## 18. 结论

### 18.1 接口可用性

| 接口 | 状态 | 说明 |
|------|------|------|
| 岗位列表搜索 | ✅ 可用 | 返回结构清晰，分页稳定 |

### 18.2 关键发现

1. ✅ 岗位列表接口可正常访问，返回 JSON 格式数据
2. ✅ 分页机制稳定，pageIndex + pageSize 可正常工作
3. ✅ projectMappingIdList=[2]（应届实习）岗位最多（186 个）

2. 需要字典接口辅助做 code→name 映射
3. 岗位详情接口已确认（4-1.2.0.2 通过前端 JS 分析确认 `getJobDetailsByPostId` 可用）
