### 7.2 结论

**当前项目无 Nginx，不具备统一入口。**

前端直连后端存在 CORS 风险，当前因前端使用 Mock 数据而未暴露。一旦前端接后端 API，将直接面临跨域问题。

### 7.3 建议

后续需要新增 Nginx 作为统一入口：
- `/` → frontend（前端静态资源或 dev server）
- `/api` → backend:8080（反向代理）
- 统一入口建议：`http://localhost/`

## 8. 当前 CORS 现状

### 8.1 CORS 中间件实现

文件：`server/internal/middleware/cors.go`

```go
var allowedOrigins = map[string]bool{
    "http://localhost:5173": true,
    "http://127.0.0.1:5173": true,
}

const allowedMethods = "GET, POST, PUT, PATCH, DELETE, OPTIONS"
const allowedHeaders = "Content-Type, Authorization, X-Requested-With"
```

### 8.2 CORS 策略分析

| 维度 | 当前状态 | 评估 |
|------|---------|------|
| Allowed Origins | localhost:5173 + 127.0.0.1:5173（硬编码） | ✅ 开发够用 |
| 动态 Origin 匹配 | `isAllowedOrigin()` 允许任何 localhost/127.0.0.1 端口 | ⚠️ 宽松 |
| Allowed Methods | GET, POST, PUT, PATCH, DELETE, OPTIONS | ✅ 完整 |
| Allowed Headers | Content-Type, Authorization, X-Requested-With | ✅ 包含关键头 |
| Allow Credentials | true | ✅ 支持 Cookie |
| OPTIONS 预检 | 返回 204 No Content | ✅ 正常 |
| Max-Age | 86400（24 小时） | ✅ 合理 |
| 生产环境 Origin | ❌ 不支持配置外部域名 | 🔴 需修改 |

### 8.3 CORS 风险

| 风险 | 严重度 | 说明 |
|------|--------|------|
| Origin 硬编码 | 🔴 高 | 生产部署时需修改代码或改为配置化 |
| isAllowedOrigin 宽松 | 🟡 中 | 任何 localhost 端口都允许，开发方便但生产不安全 |
| 无 Nginx 代理 | 🔴 高 | 接入 Nginx 后同源，CORS 可收紧 |
| 不支持动态域名 | 🟡 中 | 部署到自定义域名时需修改 |

### 8.4 建议

1. 后续将 allowedOrigins 改为从环境变量读取
2. 接入 Nginx 后，前端和后端同源，CORS 可大幅收紧
3. 生产环境只允许部署域名作为 Origin
4. 开发环境可保留宽松策略

## 14. 当前上线部署风险

| 风险 | 严重度 | 说明 |
|------|--------|------|
| 无 Nginx 反向代理 | 🔴 高 | 无法统一入口，无法配置 HTTPS，无法做负载均衡 |
| CORS 硬编码 localhost | 🔴 高 | 部署到域名后前端无法访问后端 |
| 前后端本地进程管理 | 🔴 高 | 无容器化，不利于部署和弹性伸缩 |
| JWT_SECRET 默认值 | 🟡 中 | 生产环境必须替换为强随机值 |
| DB_PASSWORD 默认值 | 🟡 中 | 生产环境必须替换 |
| 无 HTTPS | 🟡 中 | 传输层无加密 |
| 无环境区分 | 🟡 中 | 开发和部署共享同一配置 |
| .env.example 含疑似 Key | 🟡 中 | 安全风险 |

## 16. 4-3.7.B.1 建议设计方向

4-3.7.B.1 应设计启动与部署标准化方案，建议包含：

1. **Makefile 标准化**
   - `make up` 一键启动全部服务（含 Nginx）
   - `make restart` 安全重启（可选清空 volume）
   - `make down` 安全停止
   - 命令输出专业化

2. **Docker Compose 标准化**
   - 新增 backend / frontend / nginx 服务
   - 区分 docker-compose.yml（基础）和 docker-compose.dev.yml / docker-compose.prod.yml
   - 统一网络和依赖管理

3. **Nginx 接入**
   - `/` → frontend
   - `/api` → backend
   - proxy_set_header 标准配置
   - SSE/WebSocket 预留

4. **CORS 修复**
   - 允许的 Origin 从环境变量读取
   - Nginx 代理后同源，CORS 收紧

5. **环境区分**
   - APP_ENV 控制 CORS 策略
   - .env.development / .env.production 前端环境文件
