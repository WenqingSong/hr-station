# 环境变量

> 最后更新：2026-05-29（阶段 4-2.1 LLM / Hunyuan 环境变量配置项）

## 1. 设计目标

1. 统一前端、后端、数据库、JWT、LLM 的环境变量命名
2. 为后续 Docker Compose、Go 后端、前端 API Client 和模型接入提供标准配置基础
3. 支持本地开发和 Docker Compose 两种运行模式
4. 适配 CNB 云原生开发环境反复重启后的恢复流程
5. 确保不在代码仓库中暴露真实密钥

## 2. 文件说明

| 文件 | 作用 | 是否提交 |
|------|------|---------|
| `.env.example` | 环境变量模板，包含示例值 | ✅ 可以提交 |
| `.env` | 本地实际环境变量，包含真实值 | ❌ 不应提交 |

- `.env.example` 提交到代码仓库，供团队参考
- `.env` 由 `make init` 从 `.env.example` 复制生成，或手动创建
- `.env` 应加入 `.gitignore`
- Docker Compose 运行时自动读取根目录 `.env`

### .env 恢复方式

CNB 环境重启后 `.env` 可能丢失，通过以下方式恢复：

```bash
make init    # 如果 .env 不存在且 .env.example 存在，自动复制
```

- `make init` 是幂等操作，`.env` 已存在则跳过
- `.env` 已存在时不覆盖，保护手动修改的配置
- 恢复后如需修改密钥等敏感信息，手动编辑 `.env`

### .env 自动复制规则

1. `.env` 不存在且 `.env.example` 存在 → 自动复制
2. `.env` 已存在 → 跳过，不覆盖
3. `.env.example` 也不存在 → 提示无法创建

### .env 不覆盖规则

- `make init` 不会覆盖已有的 `.env`
- 这是保护机制：用户可能在 `.env` 中修改了 API Key 等敏感信息
- 如需重置 `.env`，需手动删除后重新 `make init`

### Hunyuan Key 不打印规则

1. `make doctor` 不打印 `LLM_API_KEY` 值
2. `make agent-env` 不打印 `LLM_API_KEY` 值
3. `make agent-check` 只显示「已配置/未配置」
4. `make status` 不显示密钥
5. 所有 `scripts/dev/` 脚本不打印密钥

### make agent-env / make agent-check 说明

```bash
make agent-env    # 查看 LLM 相关环境变量（不打印真实 Key）
make agent-check  # 检查 Agent/LLM 配置完整性
make agent-test   # 当前只提示 LLM Client 尚未实现
```

## 3. .env.example 内容

```env
# 应用基础配置
APP_NAME=offer-catcher
APP_ENV=local
WEB_PORT=5173
SERVER_PORT=8080
VITE_API_BASE_URL=http://localhost:8080/api

# 数据库配置
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=offer_catcher
DB_USER=root
DB_PASSWORD=password
DB_DSN=root:password@tcp(127.0.0.1:3306)/offer_catcher?charset=utf8mb4&parseTime=True&loc=Local

# Docker Compose MySQL 配置
MYSQL_ROOT_PASSWORD=password
MYSQL_DATABASE=offer_catcher
MYSQL_PORT=3306

# JWT 配置
JWT_SECRET=change-me-in-local
JWT_EXPIRE_HOURS=168

# LLM / Hunyuan 配置
LLM_ENABLE=false
LLM_PROVIDER=hunyuan
LLM_BASE_URL=
LLM_API_KEY=
LLM_MODEL=
LLM_TEMPERATURE=0.2
LLM_MAX_OUTPUT_TOKENS=8192
LLM_TIMEOUT_SECONDS=30
LLM_REPAIR_ENABLE=true
LLM_REPAIR_MAX_ATTEMPTS=1
LLM_FALLBACK_ENABLE=true
LLM_LOG_RAW_OUTPUT=false
LLM_PROMPT_DIR=server/prompts
LLM_SCHEMA_DIR=server/prompts/schema

# 开发调试配置
LOG_LEVEL=debug
ENABLE_MOCK_AGENT=true
```

## 4. 应用基础配置

| 变量 | 示例值 | 使用阶段 | 说明 |
|------|--------|---------|------|
| `APP_NAME` | `offer-catcher` | 阶段 2+ | 应用名称，用于日志和标识 |
| `APP_ENV` | `local` | 阶段 2+ | 运行环境：local / production |
| `WEB_PORT` | `5173` | 阶段 1+ | 前端 Vite 开发服务端口 |
| `SERVER_PORT` | `8080` | 阶段 1+ | 后端 Go HTTP 服务端口 |
| `VITE_API_BASE_URL` | `http://localhost:8080/api` | 阶段 5+ | 前端请求后端 API 的基础地址，Vite 环境变量需 `VITE_` 前缀 |

### VITE_API_BASE_URL 说明

- 前端预留变量，阶段 5 接后端时使用
- Vite 环境变量必须以 `VITE_` 前缀开头才能在前端代码中访问
- 当前阶段不使用，仅预留

## 5. 数据库配置

| 变量 | 示例值 | 使用阶段 | 说明 |
|------|--------|---------|------|
| `DB_HOST` | `127.0.0.1` | 阶段 2+ | MySQL 主机地址，本地开发用 127.0.0.1，Docker Compose 内用 `mysql` |
| `DB_PORT` | `3306` | 阶段 2+ | MySQL 端口 |
| `DB_NAME` | `offer_catcher` | 阶段 2+ | 数据库名称 |
| `DB_USER` | `root` | 阶段 2+ | 数据库用户名 |
| `DB_PASSWORD` | `password` | 阶段 2+ | 数据库密码（本地开发示例值） |
| `DB_DSN` | `root:password@tcp(127.0.0.1:3306)/offer_catcher?charset=utf8mb4&parseTime=True&loc=Local` | 阶段 2+ | Go 后端 database/sql 连接字符串 |

## 6. Docker Compose MySQL 配置

| 变量 | 示例值 | 使用阶段 | 说明 |
|------|--------|---------|------|
| `MYSQL_ROOT_PASSWORD` | `password` | 阶段 1+ | Docker Compose 中 MySQL root 密码，与 DB_PASSWORD 保持一致 |
| `MYSQL_DATABASE` | `offer_catcher` | 阶段 1+ | Docker Compose 中 MySQL 初始化数据库名，与 DB_NAME 保持一致 |
| `MYSQL_PORT` | `3306` | 阶段 1+ | Docker Compose 中 MySQL 暴露端口，与 DB_PORT 保持一致 |

这些变量已在 `docker-compose.yml` 中通过 `${VAR:-default}` 语法引用：

```yaml
ports:
  - "${MYSQL_PORT:-3306}:3306"
environment:
  MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD:-password}
  MYSQL_DATABASE: ${MYSQL_DATABASE:-offer_catcher}
```

- 如果 `.env` 存在且包含变量，Docker Compose 使用 `.env` 中的值
- 如果 `.env` 不存在或变量未定义，Docker Compose 使用默认值
- 真实密钥只写 `.env`，不要写入 `.env.example` 或 `docker-compose.yml`

### Compose 中未直接使用 DB_* 变量的原因

`DB_HOST`、`DB_PORT`、`DB_NAME`、`DB_USER`、`DB_PASSWORD`、`DB_DSN` 是 Go 后端读取的变量，不直接被 Docker Compose 使用。Docker Compose 只使用 `MYSQL_*` 变量来配置 MySQL 容器。

**需要保持一致的变量对：**

| Docker Compose 变量 | Go 后端变量 | 必须一致 |
|---------------------|-----------|---------|
| `MYSQL_ROOT_PASSWORD` | `DB_PASSWORD` | ✅ |
| `MYSQL_DATABASE` | `DB_NAME` | ✅ |
| `MYSQL_PORT` | `DB_PORT` | ✅ |

## 8. LLM / Hunyuan 配置

> 4-2.1 已更新：`.env.example` 已替换为新的 LLM / Hunyuan Config 分组（14 项配置）。

| 变量 | 默认值 | 是否必填 | 说明 | 安全要求 |
|------|--------|---------|------|---------|
| `LLM_ENABLE` | `false` | 是 | 是否启用 LLM。false 时使用 Mock Agent | - |
| `LLM_PROVIDER` | `hunyuan` | 是 | LLM 提供商，当前规划为 hunyuan | - |
| `LLM_BASE_URL` | （空） | 是 | LLM API Base URL，不要在 .env.example 中写真实私有地址 | - |
| `LLM_API_KEY` | （空） | 是 | API Key，只填写在本地 .env | 🔴 禁止提交到仓库 |
| `LLM_MODEL` | （空） | 是 | 模型名称，根据实际配置填写 | - |
| `LLM_TEMPERATURE` | `0.2` | 否 | 温度，低温度保稳定 | - |
| `LLM_MAX_OUTPUT_TOKENS` | `8192` | 否 | 最大输出 token，建议 ≥8192 | - |
| `LLM_TIMEOUT_SECONDS` | `30` | 否 | 请求超时秒数 | - |
| `LLM_REPAIR_ENABLE` | `true` | 否 | 是否启用 JSON repair | - |
| `LLM_REPAIR_MAX_ATTEMPTS` | `1` | 否 | repair 最大尝试次数，必须为 1 | - |
| `LLM_FALLBACK_ENABLE` | `true` | 否 | 是否启用 Mock fallback | - |
| `LLM_LOG_RAW_OUTPUT` | `false` | 否 | 是否记录模型原始输出 | 🔴 默认关闭 |
| `LLM_PROMPT_DIR` | `server/prompts` | 否 | Prompt 文件目录 | - |
| `LLM_SCHEMA_DIR` | `server/prompts/schema` | 否 | Schema 文件目录 | - |

### LLM 变量说明

- `LLM_ENABLE=false` 时，所有 Agent 使用 Mock Agent
- `LLM_ENABLE=true` 时，优先使用真实 LLM
- `LLM_FALLBACK_ENABLE=true` 时，LLM 调用失败、JSON 解析失败、字段校验失败时回退 Mock Agent
- `LLM_REPAIR_ENABLE=true` 时，模型输出 JSON 异常时允许修复一次
- `LLM_REPAIR_MAX_ATTEMPTS=1`：固定为 1，禁止递归修复
- `LLM_API_KEY` 不要写入 `.env.example`，只在本地 `.env` 中填写
- `.env.example` 中 `LLM_API_KEY` 保持为空
- 用户需按腾讯云混元官方控制台 / 文档确认 `LLM_BASE_URL` 和 `LLM_MODEL`
- `LLM_LOG_RAW_OUTPUT=false`：默认关闭，避免日志泄露简历、JD 或敏感信息

### 安全红线

**真实 LLM_API_KEY 不得写入 .env.example、docs、开发日志、Git 提交或聊天记录。**

### LLM_ENABLE 与 ENABLE_MOCK_AGENT 的关系

| `ENABLE_MOCK_AGENT` | `LLM_ENABLE` | 行为 |
|---------------------|--------------|------|
| `true` | `false` | 使用 Mock Agent（默认行为） |
| `true` | `true` | 优先使用真实 LLM，失败回退 Mock |
| `false` | `false` | 不启用任何 Agent |
| `false` | `true` | 优先使用真实 LLM，失败直接报错 |

- `ENABLE_MOCK_AGENT=true` + `LLM_ENABLE=false` = 阶段 3 默认行为
- `ENABLE_MOCK_AGENT=true` + `LLM_ENABLE=true` + `LLM_FALLBACK_ENABLE=true` = 阶段 4 推荐配置

### Mock Agent 配置

| 变量 | 示例值 | 使用阶段 | 说明 |
|------|--------|---------|------|
| `ENABLE_MOCK_AGENT` | `true` | 阶段 3+ | 是否启用 Mock Agent，阶段 3 Mock 模式下为 true |

## 10. 本地运行与 Docker 网络差异

本项目阶段 1 / 阶段 2 的推荐开发方式：

```text
前端：本地 npm run dev
后端：本地 go run
MySQL：Docker Compose
```

后端本地连接 MySQL 时使用：

```env
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DSN=root:password@tcp(127.0.0.1:3306)/offer_catcher?charset=utf8mb4&parseTime=True&loc=Local
```

如果未来后端也放入 Docker Compose 容器中运行，则容器内连接 MySQL 应改为：

```env
DB_HOST=mysql
DB_PORT=3306
DB_DSN=root:password@tcp(mysql:3306)/offer_catcher?charset=utf8mb4&parseTime=True&loc=Local
```

| 运行方式 | DB_HOST | DB_DSN 中的主机 | 说明 |
|---------|---------|----------------|------|
| 本地 Go 后端 | `127.0.0.1` | `127.0.0.1` | Go 直连宿主机 Docker 暴露的端口 |
| Docker Compose 内 Go 后端 | `mysql` | `mysql` | 容器间通过服务名通信 |

当前 `.env.example` 默认面向本地 Go 后端连接宿主机端口的开发方式。

## 11. CNB 环境重启后的恢复方式

CNB 云原生开发环境重启后，推荐执行：

```bash
make doctor    # 检查 .env 和 .env.example 是否存在
make init      # 在 .env 不存在且 .env.example 存在时复制生成 .env
make up        # 启动 Docker 服务（MySQL）
```

说明：

1. `make doctor` 检查 `.env` 和 `.env.example` 是否存在
2. `make init` 可以在 `.env` 不存在且 `.env.example` 存在时复制生成 `.env`
3. `.env` 是本地环境文件，不应提交
4. `.env.example` 是模板文件，可以提交
5. Docker Compose 读取 `.env` 中的变量，没有 `.env` 时使用 `docker-compose.yml` 中的默认值
6. LLM 真实 API Key 需要用户手动写入 `.env`，不得写入 `.env.example`

## 12. 安全注意事项

1. **不要在 `.env.example` 中写入真实密钥**
2. **不要在 `.env.example` 中写入真实 API Key**
3. **不要将 `.env` 提交到代码仓库**
4. **不要把真实密码写入 `docker-compose.yml`**
5. **`JWT_SECRET` 在生产环境必须替换为强随机值**
6. **`DB_PASSWORD` 在生产环境必须替换为强密码**
7. **`MYSQL_ROOT_PASSWORD` 在生产环境必须替换为强密码**
8. **`LLM_API_KEY` 应手动写入 `.env`，不要写入 `.env.example`**

### .env 加载策略说明

1. Go 标准库不会自动读取 `.env` 文件
2. 当前配置读取依赖进程环境变量（由 shell 或 Makefile 传入）
3. `.env.example` 是模板，`.env` 由 `make init` 创建
4. 当前不在代码中自动读取 `.env`，不引入 `godotenv`
5. 阶段 2-5 后，Go 后端启动需要 MySQL 可用（使用 `DB_DSN` 连接），如果 MySQL 未启动则服务启动失败
5. 如果需要让 `make dev-server` 自动加载 `.env`，应单独开 Prompt 授权修改 Makefile

## 14. 腾讯招聘公开岗位数据源配置

### 1. 配置目标

为腾讯招聘官网公开岗位数据源提供配置项，用于后续 4-1.2.3 脚本低频同步公开岗位数据。

关键原则：

- 腾讯招聘公开岗位接口**不需要 API Key**
- **不需要 Cookie**
- **不需要 Token**
- **不接登录态接口**
- 不请求投递、收藏、用户中心接口
- 后续脚本通过这些配置低频同步公开岗位数据
- 当前业务接口不会实时请求 join.qq.com

### 2. 配置项总览

| 配置项 | 默认值 | 类型 |
|--------|--------|------|
| TENCENT_JOBS_ENABLE | true | 开关 |
| TENCENT_JOBS_LIST_URL | https://join.qq.com/api/v1/position/searchPosition | URL |
| TENCENT_JOBS_DETAIL_URL | https://join.qq.com/api/v1/jobDetails/getJobDetailsByPostId | URL |
| TENCENT_JOBS_DICTIONARY_URL | https://join.qq.com/api/v1/dictionary/ | URL |
| TENCENT_JOBS_PROJECT_MAPPING_IDS | 2 | 分页 |
| TENCENT_JOBS_PAGE_SIZE | 50 | 分页 |
| TENCENT_JOBS_MAX_PAGES | 3 | 分页 |
| TENCENT_JOBS_FETCH_DETAIL | true | 开关 |
| TENCENT_JOBS_FETCH_DICTIONARY | true | 开关 |
| TENCENT_JOBS_REQUEST_INTERVAL_MS | 500 | 安全 |
| TENCENT_JOBS_TIMEOUT_SECONDS | 10 | 安全 |
| TENCENT_JOBS_USER_AGENT | Mozilla/5.0 | 安全 |
| TENCENT_JOBS_REFERER | https://join.qq.com/post.html?query=p_2 | 安全 |
| TENCENT_JOBS_ORIGIN | https://join.qq.com | 安全 |
| TENCENT_JOBS_OUTPUT_DIR | data/tencent-jobs/raw | 输出 |

### 3. 开关配置

| 变量 | 示例值 | 说明 |

### 9. 安全边界

1. 腾讯招聘公开岗位接口不需要 API Key
2. 不需要 Cookie
3. 不需要 Token
4. 不接登录态接口
5. 不请求投递、收藏、用户中心接口
6. 低频请求（默认间隔 500ms）
7. Demo 阶段限制最大页数（默认 3 页）
8. 出现 403/429/验证码时脚本应立即停止

### 10. 后续使用方式

- 4-1.2.3 中 `scripts/dev/tencent_jobs.sh` 已实现读取这些环境变量
- `.env` 优先，`.env.example` 兜底，环境变量最高优先
- 测试时可临时覆盖：`TENCENT_JOBS_PAGE_SIZE=5 TENCENT_JOBS_MAX_PAGES=1 scripts/dev/tencent_jobs.sh fetch-all`
- 不会读取 API Key、Cookie、Token（公开岗位接口不需要）
- 4-1.2.4 中 Makefile 已提供 `make jobs-*` 统一命令入口
- 测试时可临时覆盖：`TENCENT_JOBS_PAGE_SIZE=5 TENCENT_JOBS_MAX_PAGES=1 make jobs-fetch`
- 当前 Go 后端不直接读取这些变量（后端只读取本地 jobs 表）
- 前端不直接调用 join.qq.com
- 后端业务接口不实时代理 join.qq.com
