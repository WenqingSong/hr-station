# 工程执行规范

## 1. 规范目标

为「Offer 捕手」项目建立统一的工程执行规则，确保：

- 所有任务小颗粒度、边界清晰
- 文档与代码同步更新
- 阶段推进有据可依
- 后续模型接手可快速理解

## 2. 阶段划分

本项目共 8 个阶段：

| 阶段 | 名称 | 核心目标 |
|------|------|---------|
| 阶段 0 | 项目审计与文档中枢 | 只读审计 + 文档体系建设 |
| 阶段 1 | 工程初始化 | Makefile / .env / docker-compose / Go 工程脚手架 |
| 阶段 2 | 后端基础设施 | 数据库建表 / 中间件 / 基础 CRUD |
| 阶段 3 | 核心业务后端 Mock | 简历 / 岗位 / 推荐 / 匹配分析 Mock 实现 |
| 阶段 4 | Agent 与模型接入 | Mock Agent → 真实 LLM API 替换 |
| 阶段 5 | 前端接后端 | 路由 / API Client / 页面接入真实数据 |
| 阶段 6 | 前端体验优化 | 状态处理 / 视觉收敛 / 演示链路优化 |
| 阶段 7 | 交付部署与演示 | Docker 部署 / Demo 演示 / 验收 |

**关键规则**：不允许跨阶段做事。每个 Prompt 只做当前阶段任务。

## 3. 任务颗粒度

每次 CodeBuddy 任务必须满足：

1. 一个 Prompt 只做一个明确工程任务
2. 不允许跨阶段做事
3. 不允许顺手修复无关问题
4. 不允许自行新增产品功能
5. 不允许修改不在任务范围内的文件
6. 不允许删除已有功能
7. 发现问题只记录到文档，不自动修复，除非任务明确要求修复

## 4. 执行前要求

每次执行任务前，CodeBuddy 必须：

1. 阅读 `docs/说明书.md`、`docs/项目状态.md`、`docs/下一步任务.md`、`docs/变更记录.md`
2. 阅读 `docs/09-开发日志/` 中最近一篇日志
3. 阅读任务涉及模块的对应目录文档
4. 输出简短执行计划：将读取哪些文档、修改哪些文件、执行哪些命令、预期产出、风险点

## 5. 执行中要求

1. 只修改任务明确授权的文件
2. 未授权的文件不得修改
3. 遇到不确定事项先记录风险或提问，不擅自决定
4. 不自行选择新技术栈
5. 不自行改变产品边界
6. 不自行新增功能

## 6. 执行后要求

每次执行完成后必须：

1. 更新 `docs/项目状态.md`
2. 更新 `docs/下一步任务.md`
3. 追加 `docs/变更记录.md`
4. 创建 `docs/09-开发日志/YYYY-MM-DD-序号-任务名.md`
5. 如涉及模块文档，同步更新对应模块文档
6. 自检：是否只修改允许范围内的文件

## 7. 修改边界规则

每个任务 Prompt 必须明确：

| 项目 | 说明 |
|------|------|
| 允许修改哪些文件 | 在 Prompt 中列出 |
| 禁止修改哪些文件 | 在 Prompt 中列出 |
| 是否允许安装依赖 | 明确授权 |
| 是否允许创建目录 | 明确授权 |
| 是否允许执行命令 | 明确授权 |
| 是否允许修改配置 | 明确授权 |
| 是否允许重构 | 明确授权 |

**如果 Prompt 没有授权，不得修改。**

## 8. 命令执行规则

1. 只执行任务明确要求的命令
2. 不执行 `rm -rf`、`git push --force` 等危险命令
3. 不修改 git config
4. 不跳过 git hooks
5. 涉及外部操作的命令需用户确认

## 9. 依赖安装规则

1. 只有任务明确授权时才安装依赖
2. 安装前确认 `package.json` 或 `go.mod` 的修改在允许范围内
3. 不擅自升级已有依赖版本
4. 不引入未经产品规划确认的新库

## 10. 代码变更规则

1. 不重写已有页面视觉
2. 不改变产品功能边界
3. 不新增未规划的功能
4. 不删除已有功能
5. 重构需任务明确授权
6. 代码文件命名遵循技术生态惯例（英文），不用中文

## 11. 文档变更规则

1. `docs/` 下所有 Markdown 文档必须使用中文命名
2. 每次任务后必须更新根文档
3. 开发日志必须完整，不能留空
4. ADR 变更需标记状态
5. 文档内容要具体、可执行，不写空话

## 12. 验收规则

1. 每个阶段有阶段汇总任务，确认产出完整后才进入下一阶段
2. 代码任务需通过基础构建和测试
3. 文档任务需通过自检清单
4. Demo 验收按 `docs/07-测试验收/Demo验收清单.md` 执行

## 13. 禁止事项

以下行为绝对禁止，除非用户明确要求：

1. 自行新增多简历管理
2. 自行新增文件上传解析
3. 自行新增自动生成优化版简历
4. 自行新增岗位收藏
5. 自行新增导出报告
6. 自行新增投递追踪
7. 自行新增面试模拟
8. 自行新增社区功能
9. 自行新增企业 HR 后台
10. 自行新增复杂权限系统
11. 自行新增移动端优先适配
12. 在文档任务中修改代码
13. 在代码任务中遗漏文档更新
14. 在未授权情况下修改 `docs/` 之外文件

如确需新增功能，必须先写 ADR，经用户确认后再执行。
