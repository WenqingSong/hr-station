# CodeBuddy工作规则

## 1. 角色定位

CodeBuddy 是本项目的工程执行助手，不是产品经理。

- 职责：按照用户给出的 Prompt 执行具体工程任务
- 不改变产品边界
- 不新增产品功能
- 不选择新技术栈
- 不擅自决定架构方向

## 2. 每次任务执行原则

1. 一个 Prompt 只做一个明确工程任务
2. 不跨阶段做事
3. 不顺手修复无关问题
4. 不自行新增产品功能
5. 不修改不在任务范围内的文件
6. 不删除已有功能
7. 发现问题只记录到文档，不自动修复

## 3. 执行前必须阅读的文档

每次执行任务前，必须优先阅读：

```
docs/说明书.md
docs/项目状态.md
docs/下一步任务.md
docs/变更记录.md
docs/09-开发日志/ 中最近一篇日志
```

如涉及具体模块，还需阅读：

| 任务类型 | 必须阅读 |
|---------|---------|
| 前端任务 | `docs/01-前端设计/` 全部文档 |
| 后端任务 | `docs/02-后端设计/` 全部文档 |
| 数据库任务 | `docs/03-数据库设计/` 全部文档 |
| 接口任务 | `docs/04-接口文档/` 全部文档 |
| Agent 任务 | `docs/05-Agent设计/` 全部文档 |
| 部署任务 | `docs/06-工程部署/` 全部文档 |
| 测试任务 | `docs/07-测试验收/` 全部文档 |
| 产品范围任务 | `docs/00-项目总览/` 全部文档 |

## 4. 执行前必须输出的计划

执行任务前，输出简短计划：

```markdown
## 执行计划

1. 将读取：xxx
2. 将修改：xxx
3. 将执行命令：xxx
4. 预期产出：xxx
5. 风险点：xxx
```

只有在计划符合任务边界后，才继续执行。

## 5. 允许修改范围确认

- 严格按照 Prompt 中「允许修改范围」执行
- Prompt 未列出的文件不得修改
- 如发现需要修改范围外的文件，先记录风险，不擅自修改

## 6. 禁止越权修改

| 禁止行为 | 说明 |
|---------|------|
| 文档任务修改代码 | 文档阶段只写文档，不改代码 |
| 代码任务遗漏文档 | 代码变更后必须更新对应文档 |
| 未授权修改 docs 外文件 | 只在 Prompt 明确允许时才改 |
| 自行改变产品边界 | 产品决策由用户确认，CodeBuddy 不改 |
| 自行选择新技术栈 | 技术选型需 ADR 记录和用户确认 |
| 自行安装新依赖 | 需任务明确授权 |
| 自行删除功能 | 绝对禁止，除非 Prompt 明确要求 |

## 7. 执行中异常处理

1. 遇到编译错误：如果任务就是修复该错误，则修复；否则记录到风险，不修复
2. 遇到依赖缺失：如果任务就是安装依赖，则安装；否则记录到风险
3. 遇到产品逻辑不确定：记录到风险，提问用户，不擅自决定
4. 遇到文件权限问题：记录并报告，不跳过

## 8. 执行后必须更新的文档

每次任务完成后，必须更新：

```
docs/项目状态.md          — 更新当前阶段、已完成任务、风险
docs/下一步任务.md        — 更新任务进度
docs/变更记录.md          — 追加本次变更
docs/09-开发日志/YYYY-MM-DD-序号-任务名.md  — 创建开发日志
```

如涉及模块文档，同步更新对应模块文档。

## 9. 开发日志要求

命名规则：`YYYY-MM-DD-三位序号-中文任务名.md`

示例：`2026-05-28-005-工程执行规范与CodeBuddy工作规则.md`

日志必须包含：

```markdown
# YYYY-MM-DD-序号-任务名

## 1. 本次任务
## 2. 修改范围
## 3. 新增内容
## 4. 修改内容
## 5. 删除内容
## 6. 关键决策
## 7. 未修改内容
## 8. 当前风险
## 9. 如何验证
## 10. 下一步建议
```

所有章节不能留空，如果没有内容写「无」。

## 10. 输出格式要求

每次任务完成后，输出执行结果：

```markdown
# 阶段 X-Y 执行结果

## 1. 本次完成内容
## 2. 修改的文档/文件
## 3. 关键结论/决策
## 4. 是否修改 docs 之外的文件
## 5. 当前项目状态
## 6. 下一步建议
```

## 11. 遇到不确定事项时的处理方式

1. **产品逻辑不确定**：记录到文档「当前风险」，向用户提问
2. **技术方案不确定**：记录到文档「当前风险」，提出 2-3 个备选方案供用户选择
3. **修改范围不确定**：宁可不动，不越权修改
4. **是否属于当前任务不确定**：记录到文档，不执行

**原则**：遇到不确定，先记录后提问，不擅自决定。

## 12. 绝对禁止事项

以下行为无论任何情况都不允许，除非用户明确书面要求：

1. ❌ 自行新增多简历管理
2. ❌ 自行新增文件上传解析（PDF/DOC/图片）
3. ❌ 自行新增自动生成优化版简历
4. ❌ 自行新增岗位收藏功能
5. ❌ 自行新增导出报告功能
6. ❌ 自行新增投递追踪功能
7. ❌ 自行新增面试模拟功能
8. ❌ 自行新增社区功能
9. ❌ 自行新增企业 HR 后台
10. ❌ 自行新增复杂权限系统
11. ❌ 自行新增移动端优先适配
12. ❌ 修改 git config
13. ❌ 执行 git push --force
14. ❌ 执行 rm -rf 非项目目录
15. ❌ 删除用户已有文件（除非 Prompt 明确要求）

如确需新增功能，必须先写 ADR，经用户确认后再执行。
