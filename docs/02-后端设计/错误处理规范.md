# 错误处理规范

> 最后更新：2026-05-28（阶段 2-1 创建阶段 2 后端基础设施方案）

## 当前状态

阶段 1 仅 `/healthz` 返回成功响应，不涉及错误处理。阶段 2-3 将统一错误响应格式。

## 当前实现

`/healthz` 仅返回成功响应：

```json
{
  "status": "ok",
  "service": "offer-catcher-server"
}
```

对于非 GET 请求，返回 `405 Method Not Allowed`。

## 统一响应格式（阶段 2-3 确立）

### 成功响应

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

### 错误响应

```json
{
  "code": 40001,
  "message": "invalid request",
  "data": null
}
```

### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| code | int | 业务状态码，0 表示成功，非 0 表示错误 |
| message | string | 状态描述，成功时为 "ok"，错误时为错误描述 |
| data | any | 业务数据，成功时为实际数据，错误时为 null |

## 错误码规范

### 基础错误码（阶段 2-3 定义）

| 错误码 | 说明 | HTTP 状态码 |
|--------|------|------------|
| 0 | 成功 | 200 |
| 40000 | 请求错误 | 400 |
| 40001 | 参数错误 | 400 |
| 40100 | 未认证 | 401 |
| 40300 | 无权限 | 403 |
| 40400 | 资源不存在 | 404 |
| 40500 | 方法不允许 | 405 |
| 50000 | 服务内部错误 | 500 |
| 50300 | 外部依赖不可用 | 503 |

### 错误码范围规划

| 范围 | 说明 |
|------|------|
| 0 | 成功 |
| 40000-40999 | 通用错误（参数错误、未授权等） |
| 41000-41999 | 用户相关错误（阶段 3） |
| 42000-42999 | 简历相关错误（阶段 3） |
| 43000-43999 | 岗位相关错误（阶段 3） |
| 44000-44999 | 推荐相关错误（阶段 3） |
| 45000-45999 | 匹配分析相关错误（阶段 3） |
| 50000-59999 | 服务端错误（内部错误、外部依赖不可用） |

阶段 2 只定义基础错误码，不写业务错误码。业务错误码在阶段 3 定义。

## HTTP 状态码使用

| 状态码 | 说明 |
|--------|------|
| 200 | 成功 |
| 400 | 参数错误 |
| 401 | 未认证 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 405 | 方法不允许 |
| 500 | 服务器内部错误 |
| 503 | 外部依赖不可用 |

## 错误处理方式

### 统一错误响应

所有 API 错误必须返回统一 JSON 格式：

```json
{
  "code": 40001,
  "message": "参数错误：用户名不能为空",
  "data": null
}
```

### Recover 中间件处理 Panic

1. 捕获 panic
2. 记录堆栈到日志
3. 返回统一错误响应：

```json
{
  "code": 50000,
  "message": "internal server error",
  "data": null
}
```

4. 不暴露 panic 详情给客户端

### 实现文件

| 文件 | 说明 | 创建任务 |
|------|------|---------|
| `server/internal/response/response.go` | 统一响应结构、Success / Error 辅助函数 | 2-3 |
| `server/internal/apperror/error.go` | 应用错误类型、错误码常量、错误构造函数 | 2-3 |

## 阶段规划

| 阶段 | 内容 |
|------|------|
| 阶段 1 | `/healthz` 仅返回成功响应 |
| 阶段 2-3 | 统一响应结构、基础错误码、错误响应格式 |
| 阶段 2-4 | Recover 中间件捕获 panic 返回统一错误 |
| 阶段 3 | 业务接口必须遵守统一错误格式，定义业务错误码 |
