# 错误处理规范

> 最后更新：2026-05-28（阶段 1-5 初始化 Go 后端工程目录）

## 当前状态

阶段 1 仅 `/healthz` 返回成功响应，不涉及错误处理。阶段 2 后统一错误响应。

## 当前实现

`/healthz` 仅返回成功响应：

```json
{
  "status": "ok",
  "service": "offer-catcher-server"
}
```

对于非 GET 请求，返回 `405 Method Not Allowed`。

## HTTP 响应格式（后续统一）

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

## 错误码规范

| 范围 | 说明 |
|------|------|
| 0 | 成功 |
| 10000-19999 | 通用错误（参数错误、未授权等） |
| 20000-29999 | 用户相关错误 |
| 30000-39999 | 简历相关错误 |
| 40000-49999 | 岗位相关错误 |
| 50000-59999 | AI/Agent 相关错误 |

## HTTP 状态码使用

| 状态码 | 说明 |
|--------|------|
| 200 | 成功 |
| 400 | 参数错误 |
| 401 | 未认证 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 405 | 方法不允许 |
| 500 | 服务器内部错误 |

## 阶段规划

1. 阶段 1：`/healthz` 仅返回成功响应
2. 阶段 2：统一错误响应格式，错误处理中间件
3. 阶段 3：业务接口必须遵守统一错误格式

当前不实现复杂错误系统。
