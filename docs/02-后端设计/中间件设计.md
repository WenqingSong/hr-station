## 阶段 2 中间件详细设计

### RequestLogger

记录每个请求的关键信息：

| 字段 | 说明 | 来源 |
|------|------|------|
| method | 请求方法（GET/POST/PUT/DELETE） | `r.Method` |
| path | 请求路径 | `r.URL.Path` |
| status | 响应状态码 | 通过 ResponseWriter 包装获取 |
| duration | 请求耗时 | `time.Since(start)` |
| remote_addr | 客户端地址 | `r.RemoteAddr` |
| user_agent | 用户代理 | `r.UserAgent()` |

实现方式：

1. 使用 Go 标准库 `net/http` 的中间件模式
2. 包装 `http.Handler`，在请求前后记录信息
3. 使用 `log` 标准库输出日志
4. 通过自定义 `responseWriter` 捕获状态码

### CORS

开发环境允许的来源：

```text
http://localhost:5173
http://127.0.0.1:5173
```

配置策略：

| 配置项 | 值 | 说明 |
|--------|-----|------|
| AllowOrigins | localhost:5173, 127.0.0.1:5173 | 开发环境前端地址 |
| AllowMethods | GET, POST, PUT, DELETE, OPTIONS | 常用 HTTP 方法 |
| AllowHeaders | Content-Type, Authorization | 允许的请求头 |
| AllowCredentials | true | 允许携带凭证 |
| MaxAge | 86400 | 预检请求缓存时间（秒） |

策略说明：

1. `local` 环境下使用较宽松策略
2. 生产环境需收紧 AllowOrigins
3. OPTIONS 预检请求直接返回 204
4. 非 local 环境需配置允许的 Origin 列表

### Recover

1. 使用 `defer` + `recover()` 捕获 panic
2. 记录 panic 堆栈到日志
3. 返回统一错误响应：`{"code": 50000, "message": "internal server error", "data": null}`
4. HTTP 状态码返回 500
5. 不暴露 panic 详情给客户端（安全考虑）

## 中间件执行顺序

```
Recover（最外层，捕获所有 panic）
  ↓
CORS（处理跨域和预检）
  ↓
RequestLogger（记录请求日志）
  ↓
Handler（业务处理）
```

执行顺序说明：

1. **Recover 最外层**：确保任何中间件或 Handler 中的 panic 都能被捕获
2. **CORS 其次**：预检请求在日志之前处理，避免记录 OPTIONS 请求的冗余日志
3. **RequestLogger 最内层**：记录所有经过中间件链的实际请求

## 与 Go 标准库的集成方式

本项目使用 Go 标准库 `net/http`，中间件采用函数包装模式：

```go
type Middleware func(http.Handler) http.Handler

func Chain(h http.Handler, middlewares ...Middleware) http.Handler {
    for i := len(middlewares) - 1; i >= 0; i-- {
        h = middlewares[i](h)
    }
    return h
}
```

每个中间件接收 `http.Handler`，返回增强后的 `http.Handler`。
