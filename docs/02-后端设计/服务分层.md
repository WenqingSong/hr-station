# 服务分层

> 最后更新：2026-05-28（阶段 2-1 创建阶段 2 后端基础设施方案）

## 当前状态

已预留 model / repository / service / agent / llm 目录，当前只实现配置和 HTTP 路由基础。阶段 2 将新增基础设施层。

## 分层架构

```
Handler（控制器层）
  ↓
Service（业务逻辑层）
  ↓
Repository（数据访问层）
  ↓
Model（数据模型）
```

### 基础设施支撑层

```
Config（配置读取）
Database（数据库连接）
Response（统一响应）
AppError（错误定义）
Middleware（中间件）
Health（健康检查）
```

## 各层详细说明

### Handler 层

- 接收 HTTP 请求，参数校验
- 调用 Service 层处理业务
- 返回统一格式的响应
- 当前实现：`/healthz` Handler

### Service 层

- 业务逻辑处理
- 调用 Repository 层操作数据
- 调用 Agent 层获取 AI 结果
- 事务管理
- 当前未实现（阶段 3）

### Repository 层

- 数据库 CRUD 操作
- 缓存读写
- 数据模型转换
- 当前未实现（阶段 3）

### Agent 层

- AI 模型调用封装
- Prompt 管理
- Mock Agent 实现（阶段 3）
- 当前未实现

### LLM 层

- LLM API 客户端封装
- 模型调用与响应解析
- 当前未实现（阶段 4）
