# 服务分层

> 最后更新：2026-05-28（阶段 2-5 接入 MySQL 数据库连接）

## 当前状态

已预留 model / repository / service / agent / llm 目录，当前只实现配置和 HTTP 路由基础。阶段 2 将新增基础设施层。

## 分层架构

```
Handler（控制器层）
  ↓
Service（业务逻辑层）
  ↓
Repository（数据访问层）
  ↓
Model（数据模型）
```

### 基础设施支撑层

```
Config（配置读取）
Database（数据库连接）
Response（统一响应）
AppError（错误定义）
Middleware（中间件）
Health（健康检查）
```

## 各层详细说明

### Handler 层

- 接收 HTTP 请求，参数校验
- 调用 Service 层处理业务
- 返回统一格式的响应
- 当前实现：`/healthz` Handler

### Service 层

- 业务逻辑处理
- 调用 Repository 层操作数据
- 调用 Agent 层获取 AI 结果
- 事务管理
- 当前未实现（阶段 3）

### Repository 层

- 数据库 CRUD 操作
- 缓存读写
- 数据模型转换
- 当前未实现（阶段 3）

### Agent 层

- AI 模型调用封装
- Prompt 管理
- Mock Agent 实现（阶段 3）
- 当前未实现

### LLM 层

- LLM API 客户端封装
- 模型调用与响应解析
- 当前未实现（阶段 4）

| Health | `internal/health/service.go` | 健康检查逻辑 | 2-6 新增 |

### Database 连接管理（2-5 已实现）

- `internal/database/mysql.go`：使用 `database/sql` + `go-sql-driver/mysql`
- `NewMySQL(cfg)`：从 DatabaseConfig.DSN 创建连接，配置连接池参数
- `Ping(ctx)`：带 context 的连接验证
- `Close()`：关闭连接释放资源
- 连接池参数：MaxOpenConns=10、MaxIdleConns=5、ConnMaxLifetime=30m、ConnMaxIdleTime=10m
- 当前 database 只负责连接管理，repository 层阶段 3 再实现
- 阶段 3 repository 通过 database 提供的 `*sql.DB` 实现业务查询

### Config 配置结构（2-2 已增强）

Config 提供后续 database、middleware、service、agent、llm 的基础配置：

| 分组 | 对应后续使用 | 说明 |
|------|------------|------|
| App | 全局 | 应用名称和运行环境 |
| Server | HTTP Server | 端口配置 |
| Database | 阶段 2-5 ✅ | MySQL 连接参数，已在 main.go 中使用 |
| JWT | 阶段 3 | 认证配置，当前仅读取不使用 |
| LLM | 阶段 4 | 模型 API 配置，当前仅读取不使用 |
| Feature | 阶段 3 | Mock Agent 开关，当前仅读取不使用 |
| Log | 全局 | 日志级别 |

### Middleware 中间件层（2-4 已实现）

| 中间件 | 文件 | 说明 |
|--------|------|------|
| Recover | `internal/middleware/recover.go` | 捕获 panic，返回统一错误（复用 AppError.ErrInternal） |
| CORS | `internal/middleware/cors.go` | 跨域处理，允许 localhost:5173 |
| RequestLogger | `internal/middleware/logger.go` | 请求日志记录 |

业务层不应手动处理 CORS、不应手动 recover panic。后续业务 handler 自动处于中间件链之下。

### Response 与 AppError（2-3 已实现）

| 组件 | 文件 | 被使用层 | 说明 |
|------|------|---------|------|
| Response | `internal/response/response.go` | HTTP 层、中间件层、业务层 | 统一 JSON 响应结构，阶段 3 所有业务接口必须使用 |
| AppError | `internal/errors/error.go`（包名 apperror） | HTTP 层、中间件层、业务层 | 应用错误类型和基础错误码，阶段 2-4 Recover 中间件将复用 |
