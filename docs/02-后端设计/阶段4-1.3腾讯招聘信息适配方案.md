## 1. 阶段目标

4-1.3 的目标是将 4-1.2 产生的腾讯招聘原始 JSON 适配到项目内部 jobs 数据体系中，使岗位列表、岗位详情、推荐、匹配分析能够使用腾讯公开岗位数据。

核心边界：

- 4-1.3 不再继续探测腾讯接口
- 4-1.3 不实时请求 join.qq.com
- 4-1.3 不让推荐 / 匹配直接调用腾讯招聘接口
- 4-1.3 的数据来源是 `data/tencent-jobs/raw/` 下的本地原始 JSON

## 8. 本地 Mock 岗位与腾讯岗位共存策略

## 10. data_quality 设计

### 10.1 质量标记定义

| data_quality 值 | 含义 | 数据来源 | 用途 |
|----------------|------|---------|------|
| `full_jd` | 完整 JD（desc + request） | 岗位详情接口返回完整 desc + request | 可用于深度匹配分析 |
| `summary_only` | 仅列表摘要 | 只有列表接口字段，详情接口未获取 | 只用于列表展示和轻量推荐 |
| `manual_enriched` | 人工补充/本地 Mock | 种子数据 | 可用于深度匹配分析 |

### 10.2 当前策略

| 数据来源 | 默认 data_quality | 降级条件 |
|---------|------------------|---------|
| 腾讯详情正常 | `full_jd` | — |
| 腾讯详情缺失/失败 | `summary_only` | detail_item 中 ok=false 或 response 为空 |
| 本地 Mock 岗位 | `manual_enriched` | — |

### 10.3 质量与 Agent 的关系

| data_quality | 推荐可用 | 匹配分析可用 | 说明 |
|-------------|---------|------------|------|
| full_jd | ✅ | ✅ | 完整 JD 支持深度证据链 |
| summary_only | ✅ | ⚠️ 受限 | 只有标题和城市，证据链不完整 |
| manual_enriched | ✅ | ✅ | Mock 数据有完整 JD |

## 11. 数据去重与幂等策略

### 11.1 唯一业务键

腾讯岗位以 `external_source + external_id` 作为唯一业务键：

- `external_source = tencent_join`
- `external_id = postId`（如 "1200791473415778304"）

### 11.2 导入策略

| 场景 | 处理方式 |
|------|---------|
| external_source + external_id 不存在 | 插入新记录 |
| external_source + external_id 已存在 | 更新标准字段、raw_json、synced_at |
| 重复导入同一腾讯岗位 | 不重复插入，执行更新 |
| local_mock 岗位 | external_source=local_mock，external_id 为空或 mock-{id}，不覆盖 |

### 11.3 唯一索引

4-1.3.1 需新增唯一索引：

```sql
UNIQUE KEY `uk_jobs_external_source_id` (`external_source`, `external_id`)
```

注意：local_mock 岗位的 external_id 可为空字符串或 `mock-{id}`，需保证唯一。

### 12.1 脚本路径

### 12.2 建议支持命令

| 命令 | 说明 |
|------|------|
| help | 查看帮助 |
| check | 检查 raw JSON 是否存在、MySQL 是否可用、配置是否完整 |
| preview | 预览将导入的岗位数量和字段映射结果（不入库） |
| generate-sql | 生成导入 SQL 文件（保存到 data/tencent-jobs/generated/） |

| status | 查看数据库中各 external_source 的岗位数量 |
| clean-generated | 清理生成的临时 SQL 文件 |

### 12.3 导入流程

```
步骤 1：检查 positions.json 和 details.json 是否存在
步骤 2：连接 MySQL，检查 jobs 表是否存在扩展字段
步骤 3：读取 positions.json 的 items 数组
步骤 4：读取 details.json 的 items 数组，建立 postId → detail 映射
步骤 5：遍历每个列表项，执行字段映射
步骤 6：如果有对应详情，映射 desc→description, request→requirements 等
步骤 7：如果没有对应详情，降级为 summary_only
步骤 8：生成 INSERT ... ON DUPLICATE KEY UPDATE SQL
步骤 9：执行 SQL 导入
步骤 10：输出导入结果统计
```

### 12.4 明确说明

- 导入脚本在 4-1.3.2 实现，本次不创建
- 导入只读取本地 raw JSON，不请求腾讯接口
- 导入前必须先 `make jobs-fetch` 拉取原始数据

## 19. 失败兜底策略

| 失败场景 | 处理方式 |
|---------|---------|
| raw JSON 不存在 | 导入脚本拒绝执行，提示先 `make jobs-fetch` |
| 腾讯详情缺失 | 岗位降级为 `summary_only`，仍可在列表展示 |
| 入库失败 | 不影响现有本地 Mock 岗位 |
| 腾讯岗位导入为空 | `GET /api/jobs` 仍返回原有本地岗位 |
| 推荐 / 匹配接口异常 | 保留原有 Mock 兜底 |
| 腾讯数据字段变化 | raw_json 保存原始数据，字段映射层做容错 |
| 全部腾讯数据异常 | 8 条本地 Mock 岗位仍可正常使用 |

核心原则：**不因腾讯数据失败导致 Demo 主链路崩溃。**
