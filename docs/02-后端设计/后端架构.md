# 后端架构

> 最后更新：2026-05-28（阶段 1-5 初始化 Go 后端工程目录）

## 当前状态

已初始化基础骨架，仅实现 `/healthz` 健康检查接口。

## 技术选型

| 技术 | 选择 | 说明 | 引入阶段 |
|------|------|------|---------|
| 语言 | Go | 高性能、编译型、适合后端 API | 阶段 1 |
| HTTP | Go 标准库 `net/http` | 阶段 1 使用标准库，不引入框架 | 阶段 1 |
| 数据库 | MySQL 8.0 | 关系型，适合结构化简历数据 | 阶段 2 |
| ORM | GORM | Go 主流 ORM | 阶段 2 |
| 缓存 | Redis 7 | 阶段 7 使用，阶段 1-6 不引入 | 阶段 7 |

**说明**：阶段 1 使用 Go 标准库 `net/http` 启动 HTTP Server，不引入 Gin / Echo / Fiber 等 Web 框架。后续根据需要再决定是否引入。

## 整体架构

```
客户端（React 前端）
    ↓
Go HTTP Server（:8080）
    ├── /healthz          健康检查（阶段 1 ✅）
    ├── /api/auth/*       认证接口（阶段 3）
    ├── /api/resumes/*    简历接口（阶段 3）
    ├── /api/jobs/*       岗位接口（阶段 3）
    ├── /api/match/*      匹配分析接口（阶段 3）
    ↓
MySQL（Docker 容器 :3306）
    ↓
Agent 服务（阶段 3 Mock / 阶段 4 真实 LLM）
```

## 服务分层

```
Handler（HTTP 请求处理）
  ↓
Service（业务逻辑）
  ↓
Repository（数据访问）
  ↓
Model（数据模型）
```

| 层 | 职责 | 实现阶段 |
|----|------|---------|
| Handler | HTTP 请求解析、参数校验、响应格式化 | 阶段 1（/healthz）/ 阶段 2（完善） |
| Service | 业务逻辑、Agent 调用 | 阶段 3 |
| Repository | 数据库 CRUD | 阶段 3 |
| Model | 数据结构定义，对应数据库表 | 阶段 3 |

## 阶段 1 当前实现

```
Go 标准库 HTTP Server
  └── GET /healthz → {"status":"ok","service":"offer-catcher-server"}
```

当前只实现：
1. 基础 HTTP Server（Go 标准库 `net/http`）
2. `/healthz` 健康检查接口
3. 基础配置读取（APP_ENV / LOG_LEVEL / SERVER_PORT）

当前不连接数据库、不实现 JWT、不接 Agent。

## 各阶段架构扩展

| 阶段 | 新增内容 |
|------|---------|
| 阶段 1 | ✅ 基础 HTTP Server + `/healthz` + 配置读取 |
| 阶段 2 | 配置加载完善（.env 文件）、CORS 中间件、日志中间件、MySQL 连接、健康检查增强 |
| 阶段 3 | 认证接口、简历接口、岗位接口、匹配接口、Mock Agent |
| 阶段 4 | 真实 LLM 接入，替换 Mock Agent |
| 阶段 7 | Redis 缓存、完整容器化部署 |
