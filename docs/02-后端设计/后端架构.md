# 后端架构

> 最后更新：2026-05-28（阶段 2-6 增强健康检查接口）

## 当前状态

已初始化基础骨架，仅实现 `/healthz` 健康检查接口。阶段 2 将增强后端基础设施。

## 技术选型

| 技术 | 选择 | 说明 | 引入阶段 |
|------|------|------|---------|
| 语言 | Go | 高性能、编译型、适合后端 API | 阶段 1 |
| HTTP | Go 标准库 `net/http` | 阶段 1 使用标准库，不引入框架 | 阶段 1 |
| 数据库 | MySQL 8.0 | 关系型，适合结构化简历数据 | 阶段 2 |
| 数据库驱动 | `database/sql` + `github.com/go-sql-driver/mysql` | 阶段 2 使用标准库 + 驱动，不引入 ORM | 阶段 2 |
| 缓存 | Redis 7 | 阶段 7 使用，阶段 1-6 不引入 | 阶段 7 |

**说明**：阶段 1-2 使用 Go 标准库 `net/http` 启动 HTTP Server，不引入 Gin / Echo / Fiber 等 Web 框架。阶段 2 使用 `database/sql` + MySQL Driver 连接数据库，不引入 GORM / sqlx 等 ORM。

## 整体架构

```
客户端（React 前端）
    ↓
Go HTTP Server（:8080）
    ├── /healthz          健康检查（阶段 1 ✅ / 阶段 2 增强）
    ├── /api/auth/*       认证接口（阶段 3）
    ├── /api/resumes/*    简历接口（阶段 3）
    ├── /api/jobs/*       岗位接口（阶段 3）
    ├── /api/match/*      匹配分析接口（阶段 3）
    ↓
MySQL（Docker 容器 :3306）
    ↓
Agent 服务（阶段 3 Mock / 阶段 4 真实 LLM）
```

## 服务分层

```
Handler（HTTP 请求处理）
  ↓
Service（业务逻辑）
  ↓
Repository（数据访问）
  ↓
Model（数据模型）
```

| 层 | 职责 | 实现阶段 |
|----|------|---------|
| Handler | HTTP 请求解析、参数校验、响应格式化 | 阶段 1（/healthz）/ 阶段 2（完善） |
| Service | 业务逻辑、Agent 调用 | 阶段 3 |
| Repository | 数据库 CRUD | 阶段 3 |
| Model | 数据结构定义，对应数据库表 | 阶段 3 |

### 基础设施层（阶段 2 新增）

| 层 | 职责 | 实现阶段 |
|----|------|---------|
| Config | 配置读取，环境变量解析 | 阶段 1（基础）/ 阶段 2（增强） |
| Database | MySQL 连接管理，Ping，连接池 | 阶段 2 |
| Response | 统一响应结构，Success / Error | 阶段 2 |
| AppError | 应用错误定义，错误码 | 阶段 2 |
| Middleware | RequestLogger / CORS / Recover | 阶段 2 |
| Health | 健康检查逻辑 | 阶段 2 |

## 阶段 1 当前实现

```
Go 标准库 HTTP Server
  └── GET /healthz → {"code":0,"message":"ok","data":{"status":"ok","service":"offer-catcher-server"}}
```

当前已实现：
1. 基础 HTTP Server（Go 标准库 `net/http`）
2. `/healthz` 健康检查接口（已使用统一响应格式）
3. 结构化配置读取（App/Server/Database/JWT/LLM/Feature/Log 七组）
4. 统一响应结构（`{code, message, data}`）
5. 基础错误处理（AppError + 基础错误码）
6. 中间件链（Recover → CORS → RequestLogger）

当前已连接数据库、健康检查已增强、不实现 JWT、不接 Agent。

### Health 健康检查（2-6 已实现）

| 组件 | 文件 | 说明 |
|------|------|------|
| Health | `internal/health/service.go` | 健康检查服务，聚合 app/database 状态，通过 DatabasePinger 接口检查数据库 |

- `DatabasePinger` 接口定义数据库 Ping 能力，`database.MySQL` 已实现该接口
- `Service.Check()` 返回 `Status` 结构（service/env/app/database）+ 健康布尔值
- HTTP Router 只负责暴露 `/healthz`，调用 health service 获取状态
- 数据库正常时 `message=ok`，数据库不可用时 `message=degraded`
- 开发阶段数据库不可用仍返回 HTTP 200
- 不暴露数据库底层错误给前端

### Database 连接管理（2-5 已实现）

| 组件 | 文件 | 说明 |
|------|------|------|
| Database | `internal/database/mysql.go` | MySQL 连接管理，使用 `database/sql` + `go-sql-driver/mysql`，提供 NewMySQL / Ping / Close，连接池参数已配置 |

- 启动时初始化连接并 Ping 验证
- 连接失败则服务启动失败
- 当前未实现 repository，阶段 3 再写业务数据访问
- MySQL Driver 仅作为驱动，不引入 GORM / sqlx

### 配置结构（2-2 已增强）

Config 已从简单 3 字段结构升级为结构化分组配置：

| 分组 | 字段 | 说明 |
|------|------|------|
| App | Name / Env | 应用名称、运行环境 |
| Server | Port | HTTP 服务端口 |
| Database | Host / Port / Name / User / Password / DSN | MySQL 连接配置（2-5 才连接） |
| JWT | Secret / ExpireHours | JWT 配置（阶段 3 才使用） |
| LLM | BaseURL / APIKey / Model | LLM API 配置（阶段 4 才使用） |
| Feature | EnableMockAgent | Mock Agent 开关（阶段 3 才使用） |
| Log | Level | 日志级别 |

保留了 `ServerPort`/`AppEnv`/`LogLevel` 顶层字段，兼容 main.go 无需修改。

### 统一响应与错误处理（2-3 已实现）

| 组件 | 文件 | 说明 |
|------|------|------|
| Response | `internal/response/response.go` | 统一 JSON 响应结构 `{code, message, data}`，提供 OK / OKWithMessage / Error / JSON 函数 |
| AppError | `internal/errors/error.go` | 应用错误类型，基础错误码常量，预定义错误变量 |

基础错误码：0（成功）、40000（请求错误）、40001（参数错误）、40100（未认证）、40300（无权限）、40400（资源不存在）、40500（方法不允许）、50000（内部错误）、50300（依赖不可用）

阶段 3 所有业务接口必须使用统一响应结构。

### 中间件链（2-4 已实现）

| 中间件 | 文件 | 说明 |
|--------|------|------|
| Recover | `internal/middleware/recover.go` | 捕获 panic，返回 `{code:50000, message:"internal server error"}` |
| CORS | `internal/middleware/cors.go` | 允许 localhost:5173 / 127.0.0.1:5173，OPTIONS 返回 204 |
| RequestLogger | `internal/middleware/logger.go` | 记录 method/path/status/duration/remote/user_agent |

执行顺序：Recover（最外层）→ CORS → RequestLogger → Handler

阶段 3 业务接口会自动复用该中间件链。当前不包含 JWT Auth 中间件。
