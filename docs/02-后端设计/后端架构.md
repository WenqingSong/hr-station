# 后端架构

## 当前状态

待初始化（server/ 目录为空，阶段 1-5 执行初始化）

## 技术选型

| 技术 | 选择 | 说明 |
|------|------|------|
| 语言 | Go | 高性能、编译型、适合后端 API |
| 框架 | Gin | 轻量 Web 框架，社区活跃 |
| 数据库 | MySQL 8.0 | 关系型，适合结构化简历数据 |
| 缓存 | Redis 7 | 阶段 7 使用，阶段 1-6 不引入 |
| ORM | GORM | Go 主流 ORM，阶段 2 引入 |

## 整体架构

```
客户端（React 前端）
    ↓
Gin API Server（:8080）
    ├── /healthz          健康检查（阶段 1）
    ├── /api/auth/*       认证接口（阶段 3）
    ├── /api/resumes/*    简历接口（阶段 3）
    ├── /api/jobs/*       岗位接口（阶段 3）
    ├── /api/match/*      匹配分析接口（阶段 3）
    ↓
MySQL（Docker 容器 :3306）
    ↓
Agent 服务（阶段 3 Mock / 阶段 4 真实 LLM）
```

## 服务分层

```
Handler（HTTP 请求处理）
  ↓
Service（业务逻辑）
  ↓
Repository（数据访问）
  ↓
Model（数据模型）
```

| 层 | 职责 | 阶段 |
|----|------|------|
| Handler | HTTP 请求解析、参数校验、响应格式化 | 阶段 2 |
| Service | 业务逻辑、Agent 调用 | 阶段 3 |
| Repository | 数据库 CRUD | 阶段 3 |
| Model | 数据结构定义，对应数据库表 | 阶段 3 |

## 阶段 1 最小实现

```
Gin HTTP Server
  └── GET /healthz → {"status": "ok"}
```

## 各阶段架构扩展

| 阶段 | 新增内容 |
|------|---------|
| 阶段 1 | 基础 HTTP Server + `/healthz` |
| 阶段 2 | 配置加载、CORS、日志、MySQL 连接、健康检查增强 |
| 阶段 3 | 认证接口、简历接口、岗位接口、匹配接口、Mock Agent |
| 阶段 4 | 真实 LLM 接入，替换 Mock Agent |
| 阶段 7 | Redis 缓存、完整容器化部署 |
