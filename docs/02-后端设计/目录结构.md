# 目录结构

## 当前状态

待初始化（阶段 1-5 执行）

## 规划目录结构

```
server/
├── go.mod                     # Go module 定义
├── cmd/
│   └── server/
│       └── main.go            # 入口文件
├── internal/
│   ├── config/                # 配置管理
│   │   └── config.go          # 配置加载（阶段 2 实现）
│   ├── http/                  # HTTP Handler
│   │   └── handler.go         # 基础 handler（阶段 2 实现）
│   ├── middleware/             # 中间件
│   │   └── cors.go            # CORS 中间件（阶段 2 实现）
│   ├── model/                 # 数据模型
│   │   └── user.go            # 用户模型（阶段 3 实现）
│   ├── repository/            # 数据访问层
│   │   └── user_repo.go       # 用户仓库（阶段 3 实现）
│   ├── service/               # 业务逻辑层
│   │   └── user_service.go    # 用户服务（阶段 3 实现）
│   ├── agent/                 # AI Agent 封装
│   │   └── resume_agent.go    # 简历 Agent（阶段 3 实现）
│   └── llm/                   # LLM 调用封装
│       └── client.go          # LLM 客户端（阶段 4 实现）
└── README.md
```

## 各目录职责

| 目录 | 职责 | 创建阶段 |
|------|------|---------|
| `cmd/server/` | 应用入口 | 阶段 1 |
| `internal/config/` | 配置加载，读取 .env | 阶段 2 |
| `internal/http/` | HTTP Handler，路由处理 | 阶段 2 |
| `internal/middleware/` | 中间件（CORS、Auth） | 阶段 2 |
| `internal/model/` | 数据模型，对应数据库表 | 阶段 3 |
| `internal/repository/` | 数据访问层，GORM 操作 | 阶段 3 |
| `internal/service/` | 业务逻辑层 | 阶段 3 |
| `internal/agent/` | AI Agent 封装 | 阶段 3 |
| `internal/llm/` | LLM 调用封装 | 阶段 4 |

## 文件命名规范

- Go 文件使用英文小写 + 下划线
- 示例：`user_handler.go`、`resume_service.go`、`job_match_agent.go`
- 不使用中文命名代码文件

## 阶段 1-5 最小实现

只创建：

1. `go.mod`
2. `cmd/server/main.go`（基础 HTTP Server + `/healthz`）
3. 空的 `internal/` 子目录
4. `README.md`
