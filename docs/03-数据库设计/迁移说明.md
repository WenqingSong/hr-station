# 迁移说明

> 最后更新：2026-05-29（阶段 4-1.3.0 腾讯招聘信息适配方案）

## 当前状态

阶段 3-2 已完成，`server/sql/init.sql` 已包含 6 张表结构和种子数据，可通过 MySQL 导入成功。

## 迁移策略

Demo 阶段不引入复杂迁移工具（如 golang-migrate），采用单 SQL 初始化文件方案。

### 原因

1. Demo 项目数据量小，单 SQL 文件足以管理
2. 便于频繁 `make reset` 后重新导入
3. 降低开发阶段复杂度
4. 集中维护表结构和种子数据
5. 用户会频繁使用 `make up`、`make down`、`make restart`
6. 清空后可通过单 SQL 文件重新导入
7. 对 Demo 和比赛项目更直观

### 当前方案

1. 使用 `DROP TABLE IF EXISTS` + `CREATE TABLE`，支持可重复执行
2. 删除顺序按外键依赖反向
3. 建表顺序按外键依赖正向
4. 使用 `SET FOREIGN_KEY_CHECKS = 0` 避免建表顺序问题
5. 所有表使用 InnoDB + utf8mb4
6. 种子数据紧跟建表语句

### 数据卷与数据关系

| 命令 | 是否删除数据 | 说明 |
|------|------------|------|
| `make up` | ❌ 不删除 | 启动容器，保留数据 |
| `make down` | ❌ 不删除 | 停止容器，保留数据卷 |
| `make restart` | ❌ 不删除 | 重启容器，保留数据 |
| `make reset` | ✅ 删除 | 清空 volume，需手动确认 |

### 重要约定

1. `make up` / `make down` / `make restart` 不应清空数据
2. `make reset` 才会清空 volume
3. 后续如果要"清空 volume + 重新导入 init.sql"，需要单独设计明确命令
4. 当前 `server/sql/init.sql` 可直接导入，无需手动创建数据库

## 迁移文件

```
server/sql/init.sql    # 数据库初始化脚本（3-2 已写入 6 张表 + 种子数据）
```

## 使用方式

```bash
# 方式一：首次导入（MySQL 已运行）
docker exec -i offer-catcher-mysql mysql -uroot -ppassword offer_catcher < server/sql/init.sql

# 方式二：清空数据卷后重建
docker compose down -v
make up
docker exec -i offer-catcher-mysql mysql -uroot -ppassword offer_catcher < server/sql/init.sql
```

## 验证方式

```bash
# 检查表
docker exec -i offer-catcher-mysql mysql -uroot -ppassword offer_catcher -e "SHOW TABLES;"

# 检查数据量
docker exec -i offer-catcher-mysql mysql -uroot -ppassword offer_catcher -e "SELECT COUNT(*) FROM jobs;"
```
