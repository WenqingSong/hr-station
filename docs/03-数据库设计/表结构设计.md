# 表结构设计

> 最后更新：2026-05-29（阶段 3-1 创建阶段 3 核心业务后端 Mock 方案）

## 当前状态

阶段 3 方案已创建，已明确 6 张业务表范围。当前 `server/sql/init.sql` 仍为占位文件，阶段 3-2 将写入真实表结构。

## 阶段 3 数据表范围

| 表名 | 说明 | 填写任务 |
|------|------|---------|
| users | 用户注册、登录、基础身份识别 | 3-2 |
| resume_versions | 简历版本管理（用户只有一份主简历） | 3-2 |
| jobs | 岗位列表和详情（种子数据） | 3-2 |
| recommendation_results | 岗位推荐 Mock 结果快照 | 3-2 |
| match_analyses | 岗位匹配分析 Mock 结果 | 3-2 |
| version_compare_results | 简历版本对比 Mock 结果 | 3-2 |

## 核心设计决策

### 1. 单主简历设计

用户只有一份主简历，不设计多简历 `resumes` 表。每次添加简历就是新增一个版本。历史版本只读。

理由：
- 降低 Demo 复杂度
- 聚焦"单主线迭代"产品理念（V1→V2→V3）
- 符合 ADR-002 单主简历设计决策

### 2. JSON 字段简化

教育经历、工作经历、项目经历、技能列表使用 JSON 字段存储，不单独建子表。

理由：
- Demo 阶段降低 SQL 复杂度
- 结构化数据用 JSON 存储已足够
- 后续如需拆表可迁移

### 3. 分析结果存 JSON

推荐结果、匹配分析结果、版本对比结果均使用 JSON 字段存储核心结果。

理由：
- 阶段 3 结果结构可能随 Mock / 真实模型变化
- JSON 灵活性高，便于迭代
- 后续如需拆字段可迁移

### 4. 与阶段 2 规划的差异

| 调整项 | 原规划 | 阶段 3 实际 | 原因 |
|--------|--------|------------|------|
| 简历主表 | `resumes` + `resume_versions` | 仅 `resume_versions` | 用户只有一份主简历，无需 resumes 表 |
| 经历子表 | 3 张独立表 | JSON 字段 | Demo 阶段简化，降低 SQL 复杂度 |
| 推荐结果 | `job_recommendations` | `recommendation_results` | 更明确的命名 |
| 匹配证据 | `match_evidences` 独立表 | 嵌入 `match_analyses.result_json` | 证据链作为分析结果的一部分存储 |
| 版本对比 | 无 | `version_compare_results` | 新增，支持版本迭代闭环 |

## 各表字段规划

### users

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT UNSIGNED AUTO_INCREMENT | 主键 |
| email | VARCHAR(255) UNIQUE | 登录邮箱 |
| password_hash | VARCHAR(255) | 密码哈希 |
| name | VARCHAR(100) | 用户名 |
| created_at | DATETIME | 创建时间 |
| updated_at | DATETIME | 更新时间 |

不做：多角色 / RBAC / Casbin / 邮箱验证 / 短信验证 / 找回密码 / 刷新 token

### resume_versions

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT UNSIGNED AUTO_INCREMENT | 主键 |
| user_id | BIGINT UNSIGNED | 用户 ID（外键） |
| version_no | INT | 版本号（1, 2, 3...） |
| name | VARCHAR(100) | 姓名 |
| phone | VARCHAR(20) | 电话 |
| email | VARCHAR(255) | 邮箱 |
| location | VARCHAR(100) | 所在地 |
| target_city | VARCHAR(100) | 目标城市 |
| target_role | VARCHAR(100) | 目标岗位 |
| education_json | JSON | 教育经历（数组） |
| experience_json | JSON | 工作经历（数组） |
| project_json | JSON | 项目经历（数组） |
| skills_json | JSON | 技能列表 |
| self_evaluation | TEXT | 自我评价 |
| raw_text | TEXT | 原始文本（可选） |
| created_at | DATETIME | 创建时间 |

说明：所有字段可选；结构复杂字段先用 JSON 存储；阶段 3 不做文件上传、不做 PDF 解析、不自动生成优化版简历

### jobs

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT UNSIGNED AUTO_INCREMENT | 主键 |
| title | VARCHAR(200) | 岗位名称 |
| department | VARCHAR(100) | 部门 |
| city | VARCHAR(50) | 城市 |
| category | VARCHAR(50) | 方向分类 |
| job_type | VARCHAR(50) | 岗位类型（校招/实习/社招） |
| description | TEXT | 岗位描述 |
| requirements | TEXT | 岗位要求 |
| skill_keywords_json | JSON | 技能关键词 |
| created_at | DATETIME | 创建时间 |
| updated_at | DATETIME | 更新时间 |

说明：阶段 3 使用种子数据；不做真实岗位爬取、不做投递、不做收藏

### recommendation_results

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT UNSIGNED AUTO_INCREMENT | 主键 |
| user_id | BIGINT UNSIGNED | 用户 ID |
| resume_version_id | BIGINT UNSIGNED | 简历版本 ID |
| result_json | JSON | 推荐结果 JSON |
| created_at | DATETIME | 创建时间 |

说明：推荐结果先存 JSON；阶段 3 推荐逻辑为 Mock / 规则；阶段 4 再接真实 Agent / LLM

### match_analyses

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT UNSIGNED AUTO_INCREMENT | 主键 |
| user_id | BIGINT UNSIGNED | 用户 ID |
| resume_version_id | BIGINT UNSIGNED | 简历版本 ID |
| job_id | BIGINT UNSIGNED | 岗位 ID |
| score | INT | 匹配分数（0-100） |
| result_json | JSON | 分析结果 JSON |
| created_at | DATETIME | 创建时间 |

说明：匹配分析结果先存 JSON；必须包含 JD-简历证据链、初筛风险、P0/P1 优化建议；不生成优化版简历

### version_compare_results

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT UNSIGNED AUTO_INCREMENT | 主键 |
| user_id | BIGINT UNSIGNED | 用户 ID |
| from_version_id | BIGINT UNSIGNED | 旧版本 ID |
| to_version_id | BIGINT UNSIGNED | 新版本 ID |
| result_json | JSON | 对比结果 JSON |
| created_at | DATETIME | 创建时间 |

说明：用于简历版本迭代页；对比两个版本之间的变化；阶段 3 先 Mock
