# K9-1-B：岗位推荐双阶段契约与页面交互设计冻结

## 背景

K9-1-A 盘点确认当前岗位推荐页存在 7 处字段契约错位，导致页面几乎为空。本阶段完成设计冻结，不修改源码。

## 设计冻结要点

### Fast / Deep 双阶段

- **Fast**：进入页面自动触发，Mock/Fast LLM，快速显示 Top 5
- **Deep**：用户点击按钮触发，Quality LLM，增强详情，失败保留 Fast

### 字段契约

- 后端 16 字段不变，前端 ViewModel 统一为 `RecommendedJobViewModel`（rank + 14 字段）
- 修正映射：`title→title`、`recommendation_score→score`、`recommendation_reason→oneSentenceReason`、`match_highlights→matchHighlights`、`risk_points→riskPoints`、`suggested_action→suggestedAction`

### 状态流转

```
initial → fast_loading → fast_done → deep_loading → deep_done
                         ↓              ↓
                      fast_error    deep_error (keep fast_done)
```

### 文案规范

| 来源 | 文案 |
| -- | -- |
| mock_agent | 快速推荐 · 演示数据 |
| fallback | 快速推荐 · 兜底结果 |
| deep_llm | 深度推荐 · AI 生成 |

## K9-1-C 实现范围

- `JobRecommendationPage` 双阶段 UI
