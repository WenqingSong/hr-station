# 2026-05-31-120-三类Agent接口返回结构现状核验

> 创建时间：2026-05-31
> 所属阶段：4-4.0
> 核验人：CodeBuddy

## 1. 本次任务

核验三类 Agent（MatchAnalysis、Recommendation、ResumeOptimization）接口的真实返回结构，查清 meta 字段位置、fallback / repair 状态字段、接口文档与 Go Model 一致性，为 4-4.1 统一接口返回契约设计提供输入。

## 2. 背景

阶段 4-3 已完成三类业务 Agent 接入 LLM Pipeline，三类 Agent 均具备 LLM + fallback 基础能力。前端产品化阶段即将开始，但三类接口返回结构不一致，前端无法稳定消费。本阶段只做现状核验，不做改造。

## 3. 核验范围

- MatchAnalysis 接口：`POST /api/jobs/{id}/match`
- Recommendation 接口：`POST /api/jobs/recommend`
- ResumeOptimization 接口：`POST /api/resumes/optimize`
- Go Model / Handler / Service / Agent / Pipeline / Schema
- 接口文档

## 4. 三类接口现状

### 4.1 统一 envelope

三类接口均有 HTTP 层统一 envelope `{code, message, data}`，但 `data` 内部结构不一致。

### 4.2 data 内部结构差异

| 维度 | MatchAnalysis | Recommendation | ResumeOptimization |
|------|--------------|----------------|--------------------|
| 业务结果位置 | data.result | data.recommended_jobs | data.result |
| meta 字段位置 | data.result 内 + data.generated_by | data.recommended_jobs[i] 内 + data.generated_by | data.result 内 + data.generated_by |
| meta 字段必填性 | omitempty | omitempty | 必填 |

### 4.3 核心发现

1. **generated_by 双重设置**：三类接口都同时设置了 `data.generated_by` 和 `result/generated_by`
2. **agent_status Mock direct 值不一致**：Match/Rec 为 `"mock"`，ResumeOpt 为 `"mock_success"`
3. **meta 字段位置不一致**：Recommendation 的 meta 字段在 `recommended_jobs[i]` 内部
4. **fallback_required 仅 ResumeOptimization 有**
5. **schema_valid / request_id 三类均缺失**

## 5. meta 字段现状

| 字段 | MatchAnalysis | Recommendation | ResumeOptimization |
|------|--------------|----------------|--------------------|
| generated_by | data + result 内（omitempty） | data + jobs[i] 内（omitempty） | data + result 内（必填） |
| agent_status | result 内（omitempty） | jobs[i] 内（omitempty） | result 内（必填） |
| fallback_reason | result 内（omitempty） | jobs[i] 内（omitempty） | result 内（omitempty） |
| error_code | result 内（omitempty） | jobs[i] 内（omitempty） | result 内（omitempty） |
| repair_applied | result 内（omitempty） | jobs[i] 内（omitempty） | result 内（必填） |
| fallback_required | ❌ 不存在 | ❌ 不存在 | result 内（必填） |
| schema_valid | ❌ 不存在 | ❌ 不存在 | ❌ 不存在 |
| request_id | ❌ 不存在 | ❌ 不存在 | ❌ 不存在 |

## 6. fallback / repair 状态现状

| 场景 | MatchAnalysis | Recommendation | ResumeOptimization |
|------|--------------|----------------|--------------------|
| LLM success | agent_status="success" | agent_status="success" | agent_status="success" |
| LLM repaired | agent_status="repaired" + repair_applied=true | agent_status="repaired" + repair_applied=true | agent_status="repaired" + repair_applied=true |
| LLM fallback | agent_status="fallback" + fallback_reason + error_code | agent_status="fallback" + fallback_reason + error_code | agent_status="fallback" + fallback_reason + error_code |
| Mock direct | agent_status=**"mock"** | agent_status=**"mock"** | agent_status=**"mock_success"** |

**关键不一致**：Mock direct 时 agent_status 值不同。

## 7. 接口文档与实现一致性

| Agent | 一致性 | 关键差距 |
|-------|--------|---------|
| MatchAnalysis | ⚠️ 部分 | 文档 JSON 示例未展示 LLM 后新增 meta 字段；meta 字段 omitempty 导致 Mock 时可能缺失 |
| Recommendation | ⚠️ 部分 | meta 字段在 recommended_jobs[i] 内；priority vs recommend_level 映射 |
| ResumeOptimization | ✅ 基本一致 | meta 字段必填，文档示例准确；但与 Match/Rec 风格不同 |

## 8. 当前风险

| 风险 | 严重度 | 说明 |

| 接口文档示例滞后 | 🟡 中 | 前端开发者可能参考过时示例 |
