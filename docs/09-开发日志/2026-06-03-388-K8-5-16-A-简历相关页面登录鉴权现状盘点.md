## 2. 当前路由配置

路由表位于 `/web/src/app/routes.tsx`，使用 `createBrowserRouter` + `RootLayout`。

```ts
RootLayout = <Navbar /> + <Outlet />
```

所有子路由直接挂载 `Component:`，**无任何 route guard 包裹**：

```ts
children: [
  { index: true, Component: JobListPage },
  { path: "jobs", Component: JobListPage },
  { path: "jobs/:id", Component: JobDetailPage },
  { path: "recommend", Component: JobRecommendationPage },
  { path: "match", Component: JobMatchAnalysisPage },
  { path: "resume-optimization", Component: ResumeOptimizationPage },
  { path: "resumes", Component: ResumeManagementPage },

  { path: "resumes/compare", Component: ResumeComparisonPage },
  { path: "login", Component: LoginPage },
  { path: "register", Component: RegisterPage },

```

**关键发现**：不存在 `ProtectedRoute` / `RequireAuth` / `AuthGuard` / `PrivateRoute` 组件。所有页面无条件渲染。

## 3. 当前 Navbar 登录态判断

Navbar.tsx 使用 `getAuthToken()` 判断：

```ts
useEffect(() => {
  setIsLoggedIn(!!getAuthToken());
}, [location]);
```

Navbar 仅做**显示层鉴权**：
- 已登录 → 显示「我的简历」+「退出」
- 未登录 → 显示「登录」按钮

**Navbar 隐藏登录入口不等于路由被保护。** 用户可直接在地址栏输入 `/resumes/new` 绕过 Navbar。

---

## 4. 当前 authStorage 逻辑

`/web/src/api/authStorage.ts`：

- 单 key：`offer_catcher_auth_token`
- 存/取/清 localStorage
- `getAuthToken()` 返回 `string | null`
- 不做 token 过期判断（JWT expiry 只由后端验证）

---

## 5. 当前 API 401 行为

`/web/src/api/client.ts` 核心逻辑：

1. `buildHeaders()`：自动从 `getAuthToken()` 注入 `Authorization: Bearer <token>`
2. 收到 HTTP 401 → `clearAuthToken()` + 抛出 `ApiClientError`
3. **不跳转登录页** — 只清 token，不导航
4. `viewModels.ts` 的 `loadResumeManagementPageViewModel()`：try/catch 返回 `null`，将 401 静默为「无简历」

| 检查项 | 结果 |

| 是否存在 route guard | ❌ 否 |
| 是否仅是显示层鉴权 | ✅ 是 |
| 跨 tab 同步 | ✅ `storage` event listener |
| 注销行为 | `logout()` API → `clearAuthToken()` → `navigate("/")` |

**结论**：当前存在**「导航显示层鉴权」**，但缺少**「路由访问层鉴权」**。

## 10. 根因判断

| 问题 | 根因 | 影响 |
|------|------|------|
| `/resumes/new` 未登录可进入 | 1) 路由无 guard 2) add 模式不调 API 3) 页面无 auth 检查 | 用户可填写大量数据，保存才失败 |
| `/resumes` 未登录显示空态 | `loadResumeManagementPageViewModel()` 返回 `null`，页面判断为「无简历」而非「未登录」 | 误导用户以为没简历 |
| `/resumes/edit` 未登录显示错误页 | 401 被 catch 为普通错误，不区分 auth vs network | 误导用户以为服务故障 |
| AI 三页面未保护 | 未区分「未登录」vs「无简历」 | 引导创建但创建也无法保存 |
| 整体鉴权缺失 | 项目从未实现 `ProtectedRoute`/`AuthGuard` 组件 | 所有私有页面裸挂在路由上 |

| **P0** | 简历管理/新建/编辑/对比四页面未登录可访问 | 需要新增 `RequireAuth` 路由守卫 |
