## 三、当前控制逻辑

| 项 | 结果 |
|----|------|
| 折叠状态来源 | `ResumeEditorSectionCard` 内部 `useState(defaultOpen)` |
| `defaultOpen` 定义 | 硬编码在每个模块 wrapper 组件中 |
| 是否根据内容动态展开 | ❌ **否**。`useState` 只在 mount 时读取 `defaultOpen`，后续不回读 |
| 数据回填后是否重设状态 | ❌ **否**。无 `useEffect` 监听内容变化并设置 `setOpen` |
| 是否存在 `userTouched` 状态 | ❌ **否**。无用户手动折叠/展开的跟踪 |

## 五、新增简历 vs 编辑已有简历

| 场景 | 当前行为 | 理想行为 |
|------|----------|----------|
| 新增简历（`/resumes/edit`） | 所有模块按 `defaultOpen` 渲染 | 基础模块展开，非基础模块可折叠 |
| 编辑已有简历（`/resumes/edit?versionNo=N`） | **与新增完全相同**（不区分场景） | 有内容模块自动展开 |
| 用户手动折叠后 | 状态在组件内保留 | 不应被数据回填重新展开 |

---

## 六、设计规则建议

```
编辑已有简历：有内容默认展开，无内容默认折叠。
新增简历：基础模块（简历基础、基础信息）展开，非基础模块可折叠。
用户手动折叠后：尊重用户操作，不自动展开。
```

| 方案 | 做法 | 推荐 | 原因 |
|------|------|:--:|------|
| A | 写死所有模块 `defaultOpen={true}` | ❌ | 新增简历时压迫感强 |

| C | 加"展开全部/收起全部"按钮 | ⚠️ | 辅助增强，非当前必需 |

## 八、推荐实现方式

在 `MyResumesPage` 中，数据回填完成后，根据各模块内容状态计算 `defaultOpen`：

```tsx
const hasInternships = internships.length > 0;
const hasCertificateContent = certificateDrafts.length > 0 || awardDrafts.length > 0 || languageExamDrafts.length > 0;
const hasPortfolioContent = portfolioDraft.works.some(w => w.name || w.link) || !!portfolioDraft.homepage || !!summary || !!extraInfoDraft.additionalInfo;
```

然后在 JSX 中传递：
```tsx
<InternshipSection defaultOpen={hasInternships}>...</InternshipSection>
<CertificatesSection defaultOpen={hasCertificateContent}>...</CertificatesSection>
<PortfolioExtraSection defaultOpen={hasPortfolioContent}>...</PortfolioExtraSection>
```

**注意：`ResumeEditorSectionCard` 使用 `useState(defaultOpen)`，只在 mount 时读取 `defaultOpen`。如果模块是从 `false` 变为 `true`（数据回填后），不会自动展开。因此需要在模块渲染前就先计算好 `defaultOpen` 值。**

由于 `formVm` 的回填 `useEffect` 在模块渲染之前执行（`formVm → useEffect → 表单 state 更新 → re-render`），模块组件在 re-render 时才会 mount（如果之前没 mount，首次挂载就用新的 `defaultOpen`），或者已 mount 时不会更新（`useState` 只在首次读取 `defaultOpen`）。

**关键问题**：模块在 `ResumeSkeleton` 之后渲染。Skeleton 显示时模块未 mount。加载完成后模块 mount，此时 `defaultOpen` 应该已经计算好。所以直接传动态 `defaultOpen` 应该可行。
