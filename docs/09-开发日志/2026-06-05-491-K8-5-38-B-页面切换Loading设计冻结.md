## 一、本阶段目标

基于 K8-5-38-A 失败复盘结论，冻结新的页面切换 Loading 设计方案，明确下一阶段 K8-5-38-C 的实现边界。

---

## 二、K8-5-37 Overlay 方案失败原因

| 失败维度 | 原因 |
|----------|------|
| 设计模型错误 | Overlay 适合模态阻塞，不适合普通 SPA 页面跳转 |
| 三层叠加 | RouteProgressBar + Overlay + 页面 Skeleton 同时出现 |
| 触发不真实 | location-change + 固定延迟 = "演戏" |
| 认知冲突 | 遮罩 → "被卡住"；进度条 → "在过渡" |
| 业界不通用 | GitHub/Linear/Notion/Stripe/Vercel 全用顶部进度条 |

---

## 三、设计冻结结论

### 普通页面跳转

```
停用 PageTransitionOverlay 中央遮罩。
RouteProgressBar 成为唯一全局跳转反馈。
页面自身 PageLoading / Skeleton 管好数据加载。
```

### PageTransitionOverlay

```
从 routes.tsx RootLayout 中移除挂载。
组件文件保留，头部加 @deprecated 注释。
不删除文件，避免扩大改动范围。
```

### RouteProgressBar

```
保持当前实现不变（2px / #0052D9 / opacity 0.8 / ~380ms）。
作为普通页面跳转唯一全局反馈。
```

### 页面内容过渡

```
可选增强，下一阶段优先不做。
如果将来要做：opacity 0→1, translate-y 4px→0, 160-220ms ease-out。
最好在 RootLayout 统一包裹 Outlet 实现，不做单页改造。
```

## 四、Loading 分工冻结

| 场景 | 组件 | 结论 |
|------|------|:--:|
| 应用启动 / Auth Bootstrap | AppBootLoading | ✅ 保留 |
| 普通页面跳转 | RouteProgressBar | ✅ 唯一全局反馈 |
| 普通页面跳转遮罩 | PageTransitionOverlay | ❌ 停用/deprecated |
| 页面数据加载 | PageLoading / Skeleton | ✅ 保留 |
| AI 生成中 | AIThinkingLoading | ✅ 保留 |
| 按钮提交 | Loader2 / 按钮 loading | ✅ 保留 |
| 错误/空状态 | PageError / PageEmpty | ✅ 保留 |
