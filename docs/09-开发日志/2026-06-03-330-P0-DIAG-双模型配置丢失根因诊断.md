## 1. 当前问题确认

用户报告：云原生开发环境重启后，执行 `make up` 生成的 `.env` 缺少双模型配置变量：

```env
# 当前 .env 中存在：
LLM_ENABLE=false
LLM_PROVIDER=hunyuan
LLM_MODEL=hy3-preview

# 当前 .env 中缺失：
LLM_FAST_MODEL=deepseek-v4-flash       ← 缺失！
LLM_QUALITY_MODEL=deepseek-v4-pro-202606  ← 缺失！
LLM_DEFAULT_TIER=fast                   ← 缺失！
```

## 4. 根因判断

```text
根因：.env.example 未同步双模型配置变量。

证据链：
1. K7-2 实现时修改了 .env（运行时），但未同步修改 .env.example（模板）。
2. ensure_env.sh 在 .env 不存在时，从 .env.example 复制生成 .env。
3. 云原生环境重启后 .env 可能丢失 → ensure-env 从 .env.example 重新生成。
4. 生成的 .env 只有 LLM_MODEL=hy3-preview，没有 LLM_FAST_MODEL / LLM_QUALITY_MODEL。
5. config.go 的 coalesceModel 回退机制虽正确，但回退到的 LLM_MODEL=hy3-preview（错误模型）。

结论：是。.env.example 未同步双模型配置是根本原因。
```
