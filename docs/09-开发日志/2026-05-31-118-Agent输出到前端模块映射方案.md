- 当前前端现状：8 个页面、6 个自定义组件、40+ shadcn/ui 组件

## 4. 三 Agent 闭环设计

设计了"岗位推荐 → 岗位匹配分析 → 简历优化 → 投递前确认"的求职决策闭环：

| Step | Agent | 核心问题 | 核心输出 |
|------|-------|---------|---------|
| 1 | RecommendationAgent | 先投哪个？ | 岗位推荐看板 + 推荐等级 + 证据链 |
| 2 | MatchAnalysisAgent | 能不能投？ | 匹配分数 + 证据链 + 投递准备度 |
| 3 | ResumeOptimizationAgent | 怎么改？ | Top Fix + JD 证据链 + 核实清单 |
| 4 | 三类 Agent 共享 | 可以投了吗？ | 准备度 + 修复确认 + 真实性确认 |

## 5. 字段到模块映射

### 5.1 共享字段统一展示

| 字段 | 统一前端名称 | 展示形态 |
|------|------------|---------|
| apply_readiness | 投递准备度 | 卡片/标签（四色四态） |
| optimization_stop_signal | 优化停止信号 | 卡片/标签（四色四态） |
| top_fix_items | Top 3 快速修复任务 | 任务卡 / checklist |
| generated_by + agent_status | 结果来源状态 | 小标签 |

### 5.2 RecommendationAgent 映射

18 个字段已映射到 18 个 UI 模块。P0 模块 8 个，P1 模块 6 个。
关键差距：strategy_summary / overall_risks / resume_focus / evidence 仅存在于 Schema，Go Model 需映射。

### 5.3 MatchAnalysisAgent 映射

20 个字段已映射到 19 个 UI 模块。P0 模块 9 个，P1 模块 7 个，P2 模块 1 个。
关键差距：risk_points / gap_points / interview_questions 在 Go Model 中为 string[]，Schema 定义为结构体数组。

### 5.4 ResumeOptimizationAgent 映射

**P0 真实可用字段**（Go Model 已实现）：9 个 → 9 个 P0 UI 模块
**P1 后续增强字段**（仅 Schema 存在）：9 个 → 9 个 P1 UI 模块
**P2 展示增强字段**（仅 Schema 存在）：2 个 → 2 个 P2 UI 模块

核心原则：P0 只基于 Go Model 实际返回的字段设计，Schema 理想字段列为 P1/P2。
