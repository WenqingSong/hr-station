## 3. 核心设计

### 3.1 核心原则

- JD 是判断的核心，不是装饰性引用
- 简历证据必须来自用户输入
- 建议必须可核实
- "示例参考"替代"建议改为"
- START / STAR-T 是检查框架，不是造句模板

### 3.2 JD 证据链结构

`jd_evidence_chain` 标准结构包含：

- `jd_requirement`：岗位要求摘要
- `jd_requirement_source`：JD 原始要求
- `resume_evidence`：简历中对应证据
- `evidence_strength`：证据强度（strong / medium / weak / missing）
- `match_judgement`：匹配判断（matched / partially_matched / missing / risky）
- `gap_analysis`：差距说明
- `screening_risk`：初筛风险
- `action_suggestion`：建议动作
- `example_reference`：示例参考
- `self_check_question`：自查问题
- `learn_more_query`：学习关键词

## 4. JD 证据链结构

### 4.1 evidence_strength 枚举

| 值 | 定义 |
|---|------|
| `strong` | 简历中有直接、具体、可验证的经历证据 |
| `medium` | 简历中有相关经历，但表达不够完整 |
| `weak` | 简历中只有关键词或泛泛描述，缺少职责和结果 |
| `missing` | 简历中没有对应证据 |

约束：
- evidence_strength=missing 时不允许输出强匹配结论
- evidence_strength=weak 时不允许建议用户直接夸大经历

### 4.2 match_judgement 枚举

| 值 | 定义 |
|---|------|
| `matched` | 该 JD 要求已有明确简历证据支撑 |
| `partially_matched` | 有部分相关经历，但证据不完整 |
| `missing` | 完全缺少证据 |
| `risky` | 看似相关，但可能存在夸大或方向不完全一致 |

约束：
- match_judgement 是针对单条 JD 要求的判断，不是整体岗位匹配结论

### 4.3 screening_risk 枚举

| 值 | 含义 |
|---|------|
| `keyword_missing` | 关键词缺失 |
| `responsibility_unclear` | 职责不清 |
| `result_missing` | 结果缺失 |
| `tech_stack_not_supported` | 技术栈未体现 |
| `scope_unclear` | 范围不清 |
| `experience_missing` | 经历缺失 |
| `role_mismatch` | 角色不匹配 |
| `authenticity_risk` | 真实性风险 |
| `location_or_preference_risk` | 地点或意向风险 |

## 5. START / STAR-T 规则

### 5.1 方法定义

- S - Situation：项目 / 业务背景
- T - Task：你承担的任务
- A - Action：你采取的行动
- R - Result：结果 / 产出 / 影响
- T - Tech：技术栈 / 工程方法 / 工具链

### 5.2 核心约束

- 如果用户没有提供 Result，Agent 不能编造结果
- 如果用户没有提供 Tech，Agent 只能提示补充真实技术栈
- START 检查是辅助用户完善表达，不是让 AI 替用户编造完整故事

### 5.3 start_missing_parts

用于标识当前经历中缺少的 START 要素：

```json
{
  "start_missing_parts": ["Task", "Result", "Tech"]
}
```

## 6. 示例参考规范

### 6.1 核心规则

1. 使用"示例参考"而非"建议改为"
2. 每条示例参考必须附带核实提醒
3. 不能编造用户没有的经历和指标

### 6.2 固定核实提醒

```text
仅当你确实使用过 [技术/方法] 并负责过 [职责] 时，才可以参考该表达。
```

或：

```text
以下示例仅供表达参考，AI 可能理解错误。请基于你的真实经历核实后使用，不要加入没有实际发生过的经历、指标或职责。
```

## 7. 与 apply_readiness 的关系

- `ready_to_apply`：多数核心 JD 要求为 matched 或 partially_matched
- `quick_fix_before_apply`：有匹配基础，存在 2-3 个 weak / partially_matched 表达问题
- `not_ready_for_this_role`：核心 JD 要求多为 missing
- `insufficient_information`：简历证据过少，无法形成可靠 jd_evidence_chain
