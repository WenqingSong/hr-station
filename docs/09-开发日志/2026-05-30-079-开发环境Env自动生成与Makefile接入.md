# 2026-05-30-079-开发环境Env自动生成与Makefile接入

## 1. 本次任务

4-3.1.C 开发环境 `.env` 自动生成与 Makefile 接入。解决 `make up` / `make restart` / `make llm-check` / `make llm-smoke` 在 `.env` 不存在时阻塞开发的问题。

## 2. 问题背景

前两次核验（4-3.1 和 4-3.1.B）均因 `.env` 不存在、LLM 配置不完整，导致真实 LLM smoke 无法执行。用户使用云原生 / Docker 开发环境，环境重启后 `.env` 经常丢失，阻塞所有依赖 `.env` 的命令。

- `docs/09-开发日志/2026-05-30-079-开发环境Env自动生成与Makefile接入.md`

### 修改

- 各文档更新

## 4. ensure_env.sh 设计

脚本逻辑：

1. `.env` 已存在 → 跳过，不覆盖
2. `.env` 不存在 + `.env.local` 存在 → 从 `.env.local` 复制
3. `.env` 不存在 + `.env.example` 存在 → 从 `.env.example` 复制
4. 三个文件都不存在 → 返回非零退出码

安全约束：

- 不打印文件内容
- 不打印变量值
- 不打印 API Key
- 脚本可重复执行
- `.env` 已存在时不覆盖

## 5. Makefile 接入

| Target | 修改前 | 修改后 |
|--------|--------|--------|
| `ensure-env` | 不存在 | `@bash scripts/dev/ensure_env.sh` |
| `up` | 无前置依赖 | `up: ensure-env` |
| `restart` | 无前置依赖 | `restart: ensure-env` |
| `llm-check` | 无前置依赖 | `llm-check: ensure-env` |
| `llm-smoke` | 无前置依赖 | `llm-smoke: ensure-env` |

`ensure-env` 已加入 `.PHONY` 和 `make help` 帮助信息。

## 10. 当前风险

1. `.env` 从 `.env.example` 创建后，LLM 配置仍为模板值（LLM_ENABLE=false，API Key 为空），需要用户手动填写真实值
2. 真实 LLM smoke 仍未执行，4-3.2 仍需等待真实 smoke 通过
3. `.env.local` 机制已就绪，但用户需要自行创建 `.env.local` 来保存本地真实配置

## 11. 是否可以重新执行 4-3.1 Smoke

**可以重新执行，但不保证通过。**

- `make llm-check` 和 `make llm-smoke` 现在会自动确保 `.env` 存在
- 但 `.env` 从 `.env.example` 创建后 LLM 配置为模板值
- 用户需在 `.env` 或 `.env.local` 中填写真实 LLM 配置后，才能执行真实 smoke
- 真实 smoke 通过后才能进入 4-3.2

## 12. 下一步建议

1. 用户创建 `.env.local` 并填写真实 LLM 配置（LLM_ENABLE=true、LLM_BASE_URL、LLM_API_KEY、LLM_MODEL）
2. 删除当前 `.env`，执行 `make llm-check`，确保从 `.env.local` 创建 `.env`
3. 执行 `RUN_REAL_LLM_SMOKE=1 make llm-smoke` 验证连通性
4. 真实 smoke 通过后进入 4-3.2 MatchAnalysisAgent 接入 Pipeline
