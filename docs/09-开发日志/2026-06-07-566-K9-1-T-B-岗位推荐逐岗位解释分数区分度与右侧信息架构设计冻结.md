# K9-1-T-B：岗位推荐逐岗位解释、分数区分度与右侧信息架构设计冻结

> 日期：2026-06-07 | 状态：已完成（设计冻结）

## 1. K9-1-T-A 诊断结论

K9-1-T-A 只读诊断确认当前推荐排序方向已基本正确，但存在 11 项核心问题：

1. Top5 推荐卡片高度同质化
2. score 大量触达 95 cap，分数无区分度
3. recommendation_label 大量都是"强匹配，优先投递"
4. recommendation_reason 模板化生成
5. match_highlights 通用标签生成
6. risk_points 兜底模板
7. suggested_action 只有轻微差异
8. 右侧"推荐来源"与顶部状态栏重复
9. 右侧"推荐记录"空占位，无真实业务能力
10. Quality 在 LLM disabled 下是 fallback，非真正深度推荐
11. AgentStepLoadingOverlay 是前端体验型进度，非后端真实阶段同步

核心根因：岗位推荐缺少逐岗位解释能力。

## 2. 设计冻结范围

### 后端字段新增

| 字段 | 类型 | 说明 |
|------|------|------|
| `why_ranked_here` | string | 为什么排在这个名次 |
| `resume_evidence` | []string | 简历匹配证据（2-3条） |
| `job_specific_reason` | string | 逐岗位推荐理由 |
| `job_specific_risks` | []string | 逐岗位风险 |
| `suggested_improvement` | string | 补强建议 |

### 分数区分度

- 去除 top spread（`score += 5-i`）
- 新增 direction_precision_bonus（精确方向匹配奖分 ≤8）
- 新增 risk_penalty（风险罚分 ≤12）
- evidence_bonus 收紧（project/internship/research 降权，上限从 ~20 降至 ≤15）
- 预期分差：Top1-Top5 ≥10 分

### Label 约束

- strong 上限 ≤2 个
- 风险 hard 降级：risk="medium" 且 precision<5 时最高 high
- 方向证据不足时最多 try

### 前端信息架构

- 左侧卡片：核心原因（why_ranked_here）+ 匹配证据（resume_evidence）+ 主要风险（1条）
- 中间详情区：6 个区块（一句话总结 / 为什么推荐 / 证据 / 亮点 / 风险 / 补强建议）
- 右侧：删除"推荐记录"，"推荐来源"合并到顶部
- sourceLabel：去掉"演示数据"，改为"规则推荐/规则兜底/AI生成"

### Agent Loading

- 本轮不实现后端同步，保持前端体验型 AgentStepLoadingOverlay
- 后续 P2：K9-1-X：Recommendation Run 状态表 + 轮询式 Agent Stage 同步
