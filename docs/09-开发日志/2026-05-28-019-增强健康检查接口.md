## 3. 新增内容

1. **health 基础设施模块** (`server/internal/health/service.go`)
   - `DatabasePinger` 接口：定义数据库 Ping 能力，`database.MySQL` 已实现该接口
   - `Service` 结构体：持有 AppName、AppEnv、DB（DatabasePinger）
   - `Status` 结构体：健康检查返回数据（service/env/app/database）
   - `NewService(appName, appEnv, db)` 函数：创建健康检查服务
   - `Check(ctx)` 方法：执行健康检查，返回 Status + 健康布尔值
2. **健康检查增强能力**
   - app 状态：Go 服务自身是否正常（固定为 "ok"）
   - database 状态：MySQL Ping 是否正常（"ok" 或 "unavailable"）

## 4. 修改内容

1. **`server/internal/http/router.go`**
   - `NewRouter()` 签名从 `func NewRouter() http.Handler` 改为 `func NewRouter(healthService *health.Service) http.Handler`
   - healthzHandler 改为接收 healthService 参数
   - 调用 `healthService.Check(r.Context())` 获取状态
   - 健康时返回 `response.OK(w, status)`，不健康时返回 `response.OKWithMessage(w, "degraded", status)`

2. **`server/cmd/server/main.go`**
   - 新增 `health` 包导入
   - 创建 `healthService := health.NewService(cfg.App.Name, cfg.App.Env, mysqlDB)`
   - 传入 `httpserver.NewRouter(healthService)`

## 6. 关键决策

1. **DatabasePinger 接口**：health service 通过接口依赖数据库 Ping 能力，不直接依赖 database 包，便于测试和解耦
2. **开发阶段 degraded 返回 HTTP 200**：避免服务被误判为完全不可用，生产环境后续可考虑 503
3. **不暴露底层数据库错误**：前端只看到 "unavailable"，不暴露具体错误信息
4. **NewRouter 签名变更**：为注入 health service 做最小改动，main.go 同步修改调用处
5. **当前启动时 Ping 失败直接终止**：如果 main.go 中数据库 Ping 失败，服务不会启动，因此 `/healthz` 的 degraded 状态只在运行期数据库中断时体现
