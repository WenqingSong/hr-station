# K8-5-14-A：简历添加/编辑页面现状盘点

## 1. 本次范围确认
只做简历添加/编辑页现状盘点，未修改任何源码。

## 2. 页面结构现状

| 页面 | 路由 | 文件 | 职责 | 问题 |
|------|------|------|------|------|
| 简历列表 | `/resumes` | `ResumeManagementPage.tsx` | 展示简历版本列表+删除+对比入口 | 卡片风格旧，用 `border border-gray-200` |
| 添加/编辑 | `/resumes/new` `/resumes/edit` | **`MyResumesPage.tsx` (958行)** | **「添加」和「编辑」共用同一组件** | 单文件巨型组件 |
| 简历对比 | `/resumes/compare` | `ResumeComparisonPage.tsx` | 版本 diff | 不在本次盘点范围 |

关键发现：**添加和编辑共用 `MyResumesPage`，通过 `location.pathname.includes("/new")` 判定 mode**。无独立 `ResumeEditPage`。

## 3. 表单字段现状

| 模块 | 字段 | 当前UI | 问题 |
|------|------|--------|------|
| **简历基础** | 简历名称、求职方向描述、设为当前简历 checkbox | 文本 input | 复选框 `setAsCurrent` 但实际保存逻辑不依赖它 |
| **基础信息** | 姓名、年龄、学历、学校、专业、毕业年份、手机号、邮箱 | 8个 input (`inputCls`) | 平面罗列无分组 |
| **求职方向** | 意向方向、期望城市、岗位类型 | select+input | 格式不确定 |
| **教育经历** | 学校、专业、学历、起止时间、课程 | 可多条目动态表单 | `Education[]`，字段偏多 |
| **实习经历** | 公司、职位、起止时间、内容 | 可多条目 | `Internship[]` |
| **项目经历** | 项目名、技术栈、描述、职责 | 可多条目 | `Project[]` |
| **技能关键词** | 输入框+回车添加 + tag展示 | 蓝底tag+删除 | 交互尚可 |
| **自我评价** | textarea | 4行 | 无字数建议 |

**核心问题**：所有 ~30 个字段线性排列在 958 行单文件中，无折叠、无卡片化、无分段进度。

## 4. 视觉问题诊断

| 问题 | 当前表现 | 根因 | 建议 |
|------|---------|------|------|
| 左侧导航像后台 | 8节固定黑字竖排 sticky | `NAV_SECTIONS` + `activeSection` scroll-spy | 用更轻盈的 tab/pill 或右侧进度条 |
| 表单过长 | 线性堆叠 8 个 section | `FormSection` 逐一渲染 | 卡片化 + 可折叠 |
| 卡片层级弱 | `border border-gray-200` | 旧表单风格 | 改为 `ring-1 ring-gray-100 rounded-2xl` |
| 底部保存栏像后台 | border-t + 灰色按钮 | 不产品化 | CTA 更突出，右侧状态栏 |
| 缺完成度反馈 | 无 | 无计算 | 右侧添加简历完成度 |
| 缺 AI 友好提示 | 无 | 无 | "AI 可基于此简历分析" |
| 与品牌不统一 | 无 `font-brand`、无圆角大卡 | 未接入新设计语言 | 后续遵循 K8-5-14-B 设计冻结 |

## 5. 数据流和 API 现状

| 动作 | API | 路径 | 处理 |
|------|-----|------|------|
| 获取当前简历(编辑) | `loadResumeManagementPageViewModel()` | adapter 封装 | ✅ 编辑模式 useEffect |
| 创建简历 | `createResume(input)` | POST `/resumes` | ✅ add mode |
| 更新简历 | `updateResume("", input)` | POST `/resumes` | ✅ edit mode（参数 _resumeId 未使用） |
| 设为当前简历 | `setCurrentResume(id)` | — | ❌ 抛异常！后端无此接口 |
| 获取简历列表 | `getResumes()` / `getResumeVersions()` | GET `/resumes/versions` | ✅ |
| 自动保存 | — | — | ❌ 无 |
| 完成度计算 | `completeness` 字段(API返回) | — | ⚠️ API 返回但前端不展示 |
| 保存草稿 vs 保存为当前 | — | — | ❌ 两个按钮调用同一个 `handleSave()` |

## 6. Loading / Error / Pending 现状

| 场景 | 当前实现 | 问题 |
|------|---------|------|
| 编辑模式初次加载 | `loading=true` → `loadResumeManagementPageViewModel` | 无 skeleton，显示文本 |
| 添加模式 | 无 loading | ✅ |
| 保存中 | `saving` → 按钮 disabled + "保存中…" | ✅ 尚可 |
| 保存失败 | `saveErrorMsg` 文本提示 | ⚠️ 无 retry、无 PageError |
| 保存成功 | `saveSuccessMsg` 绿色提示 | ⚠️ 无 toast 动效 |
| 加载简历失败 | `resumeError=true` 但 **无 UI 渲染** | ❌ P0！无错误反馈 |
| ResumeSkeleton | **不存在** | ❌ |
| 401/未登录 | 保存时 catch 提示 | ⚠️ 页面级未处理 |
