## 4. 根因判断

```text
Navbar 登录入口已改为 AuthDialog 弹窗。
首页右侧 AIDecisionWorkspace 组件的「登录」「注册新账号」按钮仍使用旧的 navigate("/login") / navigate("/register")。
导致同一产品中两个登录入口交互不一致。
```

**代码位置**：`web/src/app/components/ai/AIDecisionWorkspace.tsx:45-50`

```tsx
<Button onClick={() => navigate("/login")}>     登录    </Button>
<Button onClick={() => navigate("/register")}>  注册新账号  </Button>
```

## 5. 修复方案建议

| 方案 | 内容 | 优点 | 风险 | 推荐 |
|:---:|------|------|------|:---:|
| **A** | AIDecisionWorkspace 内部管理 AuthDialog（类似 Navbar） | 自包含，不依赖父组件 | 多一个 AuthDialog 实例 | ✅ **推荐** |
| B | JobListPage 管理 AuthDialog，props 传给 AIDecisionWorkspace | 单例 AuthDialog | 需要改 JobListPage 和 AIDecisionWorkspace 两端 | ❌ |
| C | 保留 Link 但 AuthDialog 拦截（全局） | 不改组件 | 过度工程 | ❌ |

**推荐方案 A**：最小改动，仅在 `AIDecisionWorkspace.tsx` 内：
1. `import { AuthDialog } from "../auth/AuthDialog"`
2. 新增 `const [dialogOpen, setDialogOpen] = useState(false)` + `const [dialogMode, setDialogMode] = useState<"login"|"register">("login")`
3. 登录按钮 → `setDialogMode("login"); setDialogOpen(true)`
4. 注册按钮 → `setDialogMode("register"); setDialogOpen(true)`
5. `<AuthDialog open={dialogOpen} onOpenChange={setDialogOpen} defaultMode={dialogMode} onLoginSuccess={() => setDialogOpen(false)} />`
6. `onLoginSuccess` 后触发重新加载（现有 `useEffect` 依赖 `isLoggedIn` 已足够）
7. 删除旧 `navigate("/login")` / `navigate("/register")`

**改动范围**：仅 1 个文件，无需改 JobListPage、Navbar、AuthDialog。
