## 本阶段性质

只读盘点，不修改源码。

## 当前认证链路

| 层级 | 当前实现 |
|------|---------|
| 前端登录入口 | Navbar → `AuthDialog`（Modal 弹窗）+ 独立路由 `/login` `/register` |
| 前端 auth API | `POST /auth/login`（`{phone, password}`）→ 返回 `{token, user}` |
| token 保存 | `localStorage` key `offer_catcher_auth_token` |
| 请求拦截 | `client.ts buildHeaders()`：自动从 localStorage 读 token → `Authorization: Bearer <tok>`；401 自动清 token |
| 后端登录 handler | `auth_handler.go` → `AuthService.Login` |
| 后端 auth service | `auth_service.go`：bcrypt 比对 → 生成 UUID session → 签发 JWT |
| JWT 签发 | HMAC-SHA256，Claims={userID, phone, sessionID}，Issuer="offer-catcher"，过期 168h |
| JWT 校验 | `middleware/auth.go`：解析 Bearer token → 校验签名/过期 → Redis 验证 session |
| 用户表 | `users(id, email, phone UNIQUE, password_hash, name, created_at)` |

## 方案比较

| 方案 | 做法 | 优点 | 风险 | 是否推荐 |
|------|------|------|------|:---:|
| **A** | 前端一键填入固定手机号密码并调用现有 login API | 最简单，0 后端改动；复用完整 JWT+Session 链路 | 账号密码写在前端 bundle | ✅ 推荐 |
| **B** | 后端新增 `/api/auth/demo-login` 接口 | 账号密码不暴露在前端 | 需改后端+中间件+路由+测试；新增攻击面 | ❌ 过度工程 |
| **C** | 前端只自动填充账号密码，评委手动点登录 | 最安全，无额外逻辑 | 评委体验不"一键"，与普通登录无区别 | ⚠️ 可接受 |

## 推荐方案：A

**AuthDialog 新增"评委一键体验"按钮**，点击后调用现有 `POST /auth/login`，使用固定的示范账号。

**代码改动（最小）：**

```
AuthDialog.tsx:
  1. 在登录表单底部新增按钮："🎯 评委一键体验"
  2. onClick → login({phone:"13900139000", password:"123456"})
  3. 成功后正常走 setAuthToken + onLoginSuccess + 关闭弹窗
```

**不改**：后端、API、SQL、Token/JWT/Session、路由、鉴权中间件。

## 安全边界

| 风险 | 分析 | 规避建议 |
|------|------|---------|
| 示范账号密码暴露在前端 bundle | ⚠️ 手机号+密码以字符串形式存在于 JS | 可接受（Demo 用途，非生产数据） |
| 示范账号可被任意修改简历 | ⚠️ 当前系统无权限模型 | 可接受（Demo 独立数据库实例） |
| 示范账号 Token 泄露 | 低风险（JWT 7 天过期 + Redis Session 伴生） | — |
| 是否需要 DEMO_MODE 开关 | ⚠️ 当前无 env 控制 | 可选：根据 `import.meta.env` 控制按钮显示；不强制 |
| 是否需要只读权限 | ❌ 当前系统无 RBAC | 暂不实现，Demo 环境隔离即可 |
