## 求职意向删除影响范围

### 搜索证据

| 层 | 命中数 | 关键引用 |
|----|:---:|---------|
| MyResumesPage.tsx | ~30 | state/jobType/cities/acceptOtherCities 等 9 州; L581-589 payload; L412-420 backfill; JobIntentionSection 组件 |
| types/resume.ts | ~8 | ResumeJobIntentionV2; Resume.job_intention; CreateResumeRequestV2.job_intention |
| adapter/resumeAdapter.ts | ~5 | ResumeManagementViewModel.v2.jobIntention; adapter v2.jobIntention 赋值 |
| 后端 ResumeVersion | ~10 | job_intention_json 列(job_intention_json); backfillV1FromV2 依赖 target_roles/expected_cities; response 含 JobIntention |
| Snapshot | ~10 | ResumeSnapshotJobIntention (9 fields); agent_snapshot.go prompt 注入 |
| Agent/Prompt | ~15 | 推荐/匹配 prompt 引用 job_intention/target_roles/expected_cities |

### 影响判定

| 层级 | 影响 | 建议 |
|------|------|------|
| **MyResumesPage.tsx** | 删除 JobIntentionSection 组件渲染; 删除 9 个 state(jobType/cities/acceptOtherCities 等); 删除 V1/V2 backfill 中对这些字段的赋值; payload 中 job_intention 传 undefined | 全部前端清理 |
| **types/resume.ts** | Resume.job_intention 可保留(后端仍返回); CreateResumeRequestV2.job_intention 可保留 optional | 不改 types 以免连锁报错 |
| **adapter/resumeAdapter.ts** | ResumeManagementViewModel.v2.jobIntention 保留; 后端仍返回 resp → adapter 仍解析 | 不改 adapter |
| **payload 保存** | `job_intention: undefined` → JSON.stringify 剔除 → 后端收到空 | 前端传 undefined 即可 |
| **后端 resume_service.go** | `req.JobIntention` 为空 → `backfillV1FromV2` 的 target_roles 分支跳过 → target_role/target_city 需要其他来源 | 不改后端; K8-5-24-B 已解决(target_direction/target_role 来自 direction) |
| **后端 ResumeVersionResponse** | job_intention 列已存在 → 返回空 JSON `[]` → 前端 v2.jobIntention 为 undefined | 不改后端 |
| **SQL** | job_intention_json 列已存在 → 空值 → 不阻塞 | 不改 SQL |
| **Snapshot** | ResumeSnapshotJobIntention 可选所有字段 → 空值 → Agent 收到空 | 不改 Snapshot |
| **Agent/Prompt** | ⏸️ 暂停; K8-5-26-A 再设计 | 不改 |

**结论：纯前端 UI 删除 + payload 传 undefined。后端/SQL/Snapshot 不改。**

## 技能信息重构影响范围

### 改为腾讯招聘风格

当前：10 分类 Input(skillsDraft: programmingLanguages/backendFrameworks/frontendTechnologies/databases/middleware/cloudPlatforms/devTools/aiTools/aiApplicationScenarios/otherKeywords)

目标：3 模块
- 外语考试/等级: examType(string) + score(string)
- 开发语言: languages(string 逗号分隔)
- AI 应用技能: aiApplication(textarea)

### 影响判定

| 层级 | 影响 | 建议 |
|------|------|------|
| **MyResumesPage.tsx** | SkillsDraft interface 从 10 分类改为 3 字段; state 改为 skillsV2: {examType,examScore,languages,aiApplication}; UI 改为 3 项; payload 需重构 | 改前端 |
| **types/resume.ts** | ResumeSkillsV2 (10 sub-fields) → 保留旧类型让后端兼容; 新增 CreateResumeRequestV2.skills 结构可选 | 保留旧类型+后端不改 |
| **payload** | payload skills 改为 `{exam_type,exam_score,languages,ai_application}` → JSON → 存入 skills_json 列 | JSON 兼容，后端无 schema 校验 |
| **后端** | skills_json 列接受任意 JSON → 新结构无冲突 | 不改后端 |
| **SQL** | skills_json 列不变 | 不改 SQL |
| **Snapshot** | ResumeSnapshotSkills 仍有 10 分类 → normalizeV2Snapshot 从新 payload 映射 → `OtherKeywords` 仍为旧 skills 数组 | 不改; 新 payload 写旧列 |
| **证书模块** | 外语考试从 certificate 迁到 skills → 证书模块不受影响 | 无影响 |

**结论：前端 UI 重构 + payload 重构。后端/SQL/Snapshot 不改。**

## 是否需要改后端 / SQL / Snapshot / Agent

| 层 | 是否需要改 | 原因 |
|----|:---:|------|
| **后端 Go 源码** | ❌ 不改 | 4 个修正点都可以通过前端 payload 传 undefined/新结构 兼容; 后端 `CreateResumeRequest` 使用 `json.RawMessage` → 接受任意 JSON |
| **后端 Response** | ❌ 不改 | response 字段为 optional/json.RawMessage → 保留不影响前端 |
| **数据库 SQL** | ❌ 不改 | 模板 JSON 列为大字段存储 → 不会因内容变化而失败 |
| **Snapshot** | ❌ 不改 | Snapshot 已有所有模块; Agent 暂停时保持但接收空值 |
| **Agent** | ⏸️ 暂停 | K8-5-26-A 将单独盘点 |
| **Adapter** | ✅ 部分改 | displaySchool→education[0]; V2 raw 字段仍保留 |
| **Frontend** | ✅ 全改 | 4 模块全都需要 UI 修改 + state 重定义 + payload 重构 + backfill 修复 |

## 核心结论

**4 个设计修正点全部可以只改前端完成** — 不需要改动后端 Go 源码、SQL、Snapshot 结构。关键前提是后端使用 `json.RawMessage` 作为 V2 模块字段 → 接受任意 JSON 内容 → 前端只需调整 payload 结构。Agent 暂停至 K8-5-26-A。

**唯一需要 adapter 修改**：基础信息去重复后 `displaySchool` 需从 `education[0]` 读取。
