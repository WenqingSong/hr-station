# 2026-05-29-023-实现用户注册登录基础接口

## 1. 本次任务

实现阶段 3-3：用户注册 / 登录基础接口。目标是在不接真实模型、不做复杂权限的前提下，实现最小认证闭环，包含注册、登录、获取当前用户 3 个接口，使用 JWT 签发与验证，使用 bcrypt 加密密码。

## 3. 新增内容

1. **用户模型** `model/user.go`：User struct，字段与 users 表匹配
2. **用户 Repository** `repository/user_repository.go`：Create / FindByEmail / FindByID，使用 database/sql
3. **Auth Service** `service/auth_service.go`：
   - Register：校验 email/password、检查邮箱唯一性、bcrypt 加密、创建用户、签发 JWT
   - Login：查找用户、bcrypt 校验密码、签发 JWT
   - Me：根据 ID 查找用户
   - ParseToken：解析 JWT，提取 user_id
   - JWT Claims 包含 user_id、email、exp
4. **Auth Handler** `http/auth_handler.go`：Register / Login / Me HTTP 处理，参数校验，错误映射
5. **Auth Middleware** `middleware/auth.go`：
   - 从 Authorization 头读取 Bearer Token
   - 解析 JWT 提取 user_id 放入 context
   - 提供 UserIDFromContext 辅助函数
   - 定义 TokenParser 接口
6. **认证错误码**：41001（邮箱已注册）、41002（邮箱或密码错误）
7. **JWT 依赖**：`github.com/golang-jwt/jwt/v5`
8. **bcrypt 依赖**：`golang.org/x/crypto`

## 4. 修改内容

## 6. 关键决策

1. **使用 RouterDeps 结构体**：替代 `NewRouter(healthService)` 单参数，便于后续 3-4/3-5 扩展
2. **TokenParser 接口**：Auth Middleware 通过接口调用 ParseToken，解耦 middleware 和 service
3. **context 传值**：使用自定义 contextKey 类型避免键冲突
4. **错误映射在 Handler 层**：Service 返回普通 error，Handler 层根据错误消息映射为具体业务错误码
5. **种子密码统一为 123456**：方便 Demo 演示，但文档明确标注不应在生产使用
6. **不引入 Web 框架**：继续使用 Go 标准库 `net/http`
7. **不引入 ORM**：继续使用 `database/sql`

## 8. 当前风险

1. **JWT Secret 默认值**：`change-me-in-local` 是不安全的，生产必须更换
2. **种子密码为 123456**：仅用于 Demo，生产需强制密码强度
3. **错误映射基于字符串匹配**：Service 层返回的错误消息需要 Handler 精确匹配，重构时需注意
4. **无刷新 token**：JWT 过期后需要重新登录，长期使用体验不佳
5. **无 email 格式校验**：当前仅检查 email 非空，未校验格式

## 9. 如何验证

```bash
# 1. 导入 SQL（更新种子密码）
docker exec -i offer-catcher-mysql mysql -uroot -ppassword offer_catcher < server/sql/init.sql

# 2. 启动后端
cd server && go run ./cmd/server

# 3. 登录（种子用户）
curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"arthur@example.com","password":"123456"}'

# 4. 获取当前用户（使用上一步返回的 token）
curl -s http://localhost:8080/api/auth/me \
  -H "Authorization: Bearer <token>"

# 5. 注册新用户
curl -s -X POST http://localhost:8080/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"newuser@example.com","password":"123456","name":"New User"}'

# 6. 验证错误响应
curl -s http://localhost:8080/api/auth/me  # 无 token → 40100
curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"arthur@example.com","password":"wrong"}'  # 错误密码 → 41002

# 7. 健康检查仍正常
curl http://localhost:8080/healthz
```
