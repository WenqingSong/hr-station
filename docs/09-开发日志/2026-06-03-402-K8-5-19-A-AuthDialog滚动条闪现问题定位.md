## 2. AuthDialog 当前结构

```
<Dialog open={open}>              ← Radix Root, modal=true, auto body scroll-lock
  <DialogPortal>                  ← Radix Portal (renders to document.body)
    <DialogOverlay />             ← Radix Overlay (fixed inset-0)
    <div outer-shell>             ← 自定义 div, 非 DialogPrimitive.Content
      overflow-hidden
      max-h-[min(88vh,720px)]
      animate-auth-dialog-in/out  ← scale(0.94→1) + translate, 400ms
      └─ <div inner-scroll>       ← 滚动容器
           max-h-[min(88vh,720px)]
           overflow-y-auto
           overscroll-contain
           ├─ Close button (absolute)
           ├─ Header (px-5 pt-6 pb-4)
           └─ <div key={mode}>    ← animate-auth-panel-in, 240ms
                login form (2 inputs)
                OR
                register form (3 inputs)
```

| 关键发现 | 说明 |
|---------|------|
| AuthDialog 使用**自定义 div**，不是 `DialogPrimitive.Content` | 绕过了 Radix 默认的 scroll-lock/content 行为 |
| 存在**双层 max-h**（外层 overflow-hidden + 内层 overflow-y-auto） | 内层滚动容器高度受外层约束 |
| 动画改变 **transform: scale** | 400ms 内从 0.94 缩放到 1 |
| 模式切换使用 **`key={mode}`** | 会导致整个 body div 卸载+重新挂载 |

## 3. 滚动条来源判断

| 来源候选 | 是否可能 | 证据 |
|---------|:---:|------|
| **Dialog Content 内部溢出** | ✅ **最可能** | 内层 `overflow-y-auto` + `max-h`，打开/切换时内容高度变化触发浏览器渲染滚动条 |
| Radix body scroll-lock | ✅ **次要因素** | `DialogPrimitive.Root` with `modal=true` (默认) 会给 body 添加 `overflow:hidden`，导致 body 滚动条消失 → 视口宽度变化 → 内容重新布局 → 瞬间溢出 |
| body/html 主滚动条 | ❌ 排除 | 弹窗打开时 body 被 Radix lock，主滚动条消失而非出现 |
| 动画 transform | ✅ **放大器** | `scale(0.94→1)` 改变 content 视觉尺寸，scale < 1 时内容显得比容器小，到 1 时恰好填满，过渡帧可能瞬间触发溢出计算 |
| mode 切换重渲染 | ✅ **独立触发因素** | `key={mode}` 卸载旧内容 + 挂载新内容，register 比 login 多一行（`confirm-password`），高度差导致短暂溢出 |

---

## 4. 两个场景的根因分析

### 场景 A：打开弹窗时闪现

```
时间线：
1. open=true → Radix Root 锁 body scroll (overflow:hidden)
2. body 滚动条消失 → 视口宽度 +15px → 对话框宽度重新计算 (92vw/420px)
3. outer-shell 开始动画：scale(0.94) → scale(1), opacity(0→1), 400ms
4. 动画中间，outer-shell 的 max-h 基于新视口，inner-scroll 内容恰好接近 max-h 阈值
5. 浏览器在某个中间帧判定 overflow → 渲染滚动条 → 下一帧 scale 变大 → 滚动条消失
```

**核心**：body scroll-lock 改变视口尺寸 + scale 动画中 max-h 边界计算 → 闪现。

### 场景 B：登录↔注册切换时闪现

```
时间线：
1. switchMode("register") → setMode("register")
2. key={mode} 变 → React 卸载旧 <div>，挂载新 <div>
3. animate-auth-panel-in (translateY(6→0), 240ms) 同时启动
4. register form (3 输入框 + 提示文字) > login form (2 输入框)
5. 新内容瞬间超出 inner-scroll 的 max-h → 浏览器显示滚动条
6. panel-in 动画结束后 content 位置稳定，但瞬间已经渲染过滚动条
```

**核心**：key remount + register 更高 + overflow-y-auto 在内容超限时立即显示滚动条。

## 5. 修复方案比较

| 方案 | 内容 | 优点 | 风险 | 推荐 |
|:---:|------|------|------|:---:|
| **A** | `scrollbar-width:none` / `::-webkit-scrollbar{display:none}` 加到 inner-scroll | 最简单，视觉完美 | 仍可触摸滚动但看不到指示器 | ✅ **推荐** |
| B | 移除 `overflow-y-auto`，靠外层 `overflow-hidden` clip | 彻底无滚动条 | 内容超高时被裁切，不可滚动 | ❌ 不推荐 |
| C | 根据 mode 动态设置 min-height 或固定高度 | 切换时高度稳定 | 不同屏幕适配复杂，空白区域多 | ❌ 过度设计 |
| D | 把 `max-h` 从 `88vh` 增大到 `92vh` 或 `min(96vh,720px)` | 更多 headroom | 高屏下弹窗撑满不美观 | 可选 |
| **E** | 方案 A + 方案 D（综合） | 隐藏滚动条 + 增加余量 | 稳妥 | ✅ **最推荐** |

---

## 6. 推荐修复

**K8-5-19-B 推荐方案 E = 方案 A + 方案 D**：

1. 给 inner-scroll 增加 `scrollbar-width: none`（Firefox）+ `::-webkit-scrollbar{display:none}`（Chrome/Safari/Edge）
2. 将 `max-h-[min(88vh,720px)]` 改为 `max-h-[min(92vh,760px)]`
3. 改动仅限 AuthDialog.tsx 的 `className`，不改结构、不改动画、不改业务

```css
/* 全局 CSS 补丁（theme.css） */
.auth-dialog-scroll-none {
  scrollbar-width: none;
}
.auth-dialog-scroll-none::-webkit-scrollbar {
  display: none;
}
```

预期效果：
- 打开：不再看到内部滚动条闪现 ✅
- 切换模式：不再看到内部滚动条闪现 ✅
- 内容溢出时：仍可触摸/滚轮滚动 ✅
- 对动画/登录注册逻辑/表单控件：零影响 ✅
