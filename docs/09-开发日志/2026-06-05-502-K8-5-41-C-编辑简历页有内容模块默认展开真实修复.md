## 二、K8-5-41-B 未生效原因

### 时序分析

```
T1: 组件 mount
    editingVersionNo=9, resumeName=""（空）
    internships.length=0, certificates=0 → hasContent=false
    defaultOpen = isEditingExistingResume && false = false
    sectionAutoOpenKey = "9:_empty"
    useEffect: autoOpenKey="9:_empty" !== prevKey=undefined → keyChanged!
    → setOpen(false), setTouched(false)  ✅ SectionCard 初始化为折叠

T2: 数据回填完成
    editingVersionNo=9, resumeName="09-211后台开发..."（非空）
    internships.length=4 → hasInternshipContent=true
    defaultOpen = true && true = true
    sectionAutoOpenKey = "9:09-211后台开发..."
    useEffect: autoOpenKey="9:09-..." !== prevKey="9:_empty" → keyChanged!
    → setOpen(true), setTouched(false)  ✅ 展开！

    但 K8-5-41-B 的 autoOpenKey 不含 resumeName：
    sectionAutoOpenKey = "9"（不变！）
    所以 keyChanged=false → body 跳过 ❌
```

**B 的根因：`autoOpenKey` 不含 `resumeName`，导致数据回填后 key 不变，effect 跳过同步。**

（C 的修复还增加了 `!touched` 时的 defaultOpen 同步作为兜底，即使 autoOpenKey 不变也能响应。）

## 四、SectionCard 修复详情

```tsx
useEffect(() => {
    const keyChanged = autoOpenKey !== undefined && autoOpenKey !== prevKeyRef.current;

    if (keyChanged) {
      // 切换简历版本 → 完全重置
      prevKeyRef.current = autoOpenKey;
      setOpen(defaultOpen);
      setTouched(false);
      return;
    }

    // key 没变但 defaultOpen 变了（首次渲染时数据未加载，后续回填完成）
    // → 只要用户未手动操作过，就同步 defaultOpen
    if (!touched) {
      setOpen(defaultOpen);
    }
  }, [autoOpenKey, defaultOpen, touched]);
```
