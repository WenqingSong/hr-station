# 2026-05-28-016-实现统一响应结构与错误处理基础

## 1. 本次任务

实现 Go 后端的统一响应结构与基础错误处理能力，创建 `server/internal/response` 和 `server/internal/errors` 包，将 `/healthz` 调整为统一响应格式。

- `server/internal/response/response.go`：新建
- `server/internal/errors/error.go`：新建
- `server/internal/http/router.go`：修改 /healthz 使用统一响应
- `docs/`：更新相关文档

## 3. 新增内容

- **统一响应包** `server/internal/response/response.go`：
  - `Response` 结构体（Code int / Message string / Data interface{}）
  - `JSON(w, statusCode, payload)` — 写入自定义统一 JSON 响应
  - `OK(w, data)` — 成功响应（code=0, message="ok"）
  - `OKWithMessage(w, message, data)` — 自定义 message 的成功响应
  - `Error(w, statusCode, code, message)` — 错误响应（data=null）
- **应用错误包** `server/internal/errors/error.go`（包名 `apperror`）：
  - `AppError` 结构体（Code / Message / HTTPStatus / Err）
  - `New(code, message, httpStatus)` — 创建新错误
  - `Wrap(code, message, httpStatus, err)` — 包装底层错误
  - `Error()` / `Unwrap()` 方法
  - 基础错误码常量：CodeOK(0) / CodeBadRequest(40000) / CodeInvalidParam(40001) / CodeUnauthorized(40100) / CodeForbidden(40300) / CodeNotFound(40400) / CodeMethodNotAllowed(40500) / CodeInternal(50000) / CodeDependencyUnavailable(50300)
  - 预定义错误变量：ErrBadRequest / ErrInvalidParam / ErrUnauthorized / ErrForbidden / ErrNotFound / ErrMethodNotAllowed / ErrInternal / ErrDependencyUnavailable

## 4. 修改内容

- `server/internal/http/router.go`：
  - /healthz GET 请求：从 `json.NewEncoder(w).Encode(map)` 改为 `response.OK(w, data)`
  - /healthz 非 GET 请求：从 `w.WriteHeader(405)` 改为 `response.Error(w, 405, 40500, "method not allowed")`
  - 新增 import `offer-catcher/server/internal/errors` 和 `offer-catcher/server/internal/response`

## 5. 删除内容

- 无（旧格式被替换，功能不变）

## 6. 关键决策

1. **目录名 `errors`，包名 `apperror`**：避免与 Go 标准库 `errors` 包名冲突
2. **错误码 5 位数字**：40000-50300，与 HTTP 状态码对齐但独立编号
3. **新增 40500 CodeMethodNotAllowed**：原错误处理规范未列出 40500，因 router.go 的 405 处理需要而新增
4. **JSON 编码失败降级**：如果 `json.NewEncoder(w).Encode()` 失败，尝试返回 500 + 硬编码 JSON
5. **AppError.Err 不暴露**：Err 字段用于日志，不出现在 HTTP 响应中
6. **不修改 main.go 和 config.go**：保持 2-2 的兼容性设计不变
