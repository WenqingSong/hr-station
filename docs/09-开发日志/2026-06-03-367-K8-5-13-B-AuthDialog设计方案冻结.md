## 2. AuthDialog 设计方案

| 项目 | 冻结方案 |
|------|---------|
| 组件名 | `AuthDialog` |
| 建议路径 | `web/src/app/components/auth/AuthDialog.tsx` |
| 结构策略 | **方案 A：Phase 1 内聚 login/register 表单**（不拆 LoginForm/RegisterForm，原因：表单简单、字段少、无需提前抽象） |
| 职责 | 承载登录/注册弹窗，不负责全局鉴权 |
| Props | `open: boolean; onOpenChange: (open: boolean) => void; defaultMode?: "login" \| "register"; onLoginSuccess?: () => void` |
| 实现方式 | 基于 shadcn `Dialog` + `DialogContent`，局部传 className 实现玻璃模糊 |
| 表单复用 | 内部直接复制 LoginPage/RegisterPage 的字段(手机号/密码/确认密码)、校验、pending/error 逻辑 |

推荐方案 A 原因：
- 表单简单（2-3 个字段），无需立即抽象
- 避免过度设计，Phase 1 内聚更安全
- 后续如有新表单需求再抽 LoginForm/RegisterForm

## 3. 交互流程冻结

| 场景 | 行为 |
|------|------|
| 打开弹窗 | Navbar 登录按钮 `onClick` → `setDialogOpen(true)`，默认 mode="login" |
| 切到注册 | 弹窗内"还没有账号？注册" → `setMode("register")` |
| 切回登录 | 弹窗内"已有账号？登录" → `setMode("login")` |
| 登录成功 | `setAuthToken()` → `onLoginSuccess?.()` → `onOpenChange(false)`，**不强制 navigate("/")** |
| 注册成功 | 同上 |
| 关闭弹窗 | 点击 X / overlay / ESC → `onOpenChange(false)` |
| fallback 页面 | `/login` / `/register` 保留旧 `navigate("/")` 行为不变 |

**关键设计决策**：弹窗登录成功后**留在当前页面**，不跳转。仅刷新 Navbar 状态。这与 13-A 盘点结论一致（`navigate` 触发 location 变化 → Navbar 自动重读 token）。

## 4. Navbar 接入方案

**方案 A：Navbar 内部管理 `authDialogOpen` state**（推荐 Phase 1）。

| 维度 | 决策 |
|------|------|
| open state 位置 | Navbar 内部 `useState(false)` |
| 触发方式 | 登录按钮由 `Link to="/login"` 改为 `button onClick={...}` |
| AuthDialog 位置 | 在 Navbar JSX 末尾渲染 |
| onLoginSuccess | Navbar 传入 `() => { setIsLoggedIn(true) }` |

**为什么推荐 Navbar 内部**：
- 当前只有 Navbar 一个登录入口
- 改动最小，无需提升到 App
- 后续如有其他入口，可轻松将 state 提升到 App/AuthProvider

**缺点**：其他页面如需触发登录弹窗，需重复 state 或重构。Phase 1 可接受。

## 5. /login /register fallback 策略

| 维度 | 决策 |
|------|------|
| 是否保留路由 | ✅ **保留** `/login` `/register`，不删除 |
| 为什么 | URL 直达、外部链接、登录后回调等场景依赖 |
| 页面行为 | 保留旧 LoginPage/RegisterPage，**本阶段不改** |
| 视觉同步 | K8-5-13-C/D 不处理 fallback 页面视觉 |
| 后续统一 | K8-5-13-F（可选）让 fallback 页面也渲染 AuthDialog |

## 7. Auth 状态同步方案

| 步骤 | 行为 |
|------|------|
| 1 | AuthDialog 登录成功后 `setAuthToken(response.token)` |
| 2 | 调用 `onLoginSuccess?.()` |
| 3 | 关闭弹窗 `onOpenChange(false)` |
| 4 | Navbar `onLoginSuccess` handler 执行 `setIsLoggedIn(true)` |

**不依赖**：全局 AuthContext、状态管理库、页面刷新、强制 navigate。

**为什么这个方案可行**：
- `setAuthToken` 将 token 写入 localStorage
- Navbar 在 `useEffect([location])` 中已通过 `getAuthToken()` 检测
- 额外 `setIsLoggedIn(true)` 作为立即刷新，不依赖 location 变化
- 后续如在 /login fallback 页面仍走原 `navigate("/")` 逻辑，location 变化自动触发

## 8. 风险分级

| 级别 | 问题 | 影响 | 规避方案 |
|------|------|------|---------|
| P0 | 登录成功后 Navbar 不刷新 | 用户以为未登录 | `onLoginSuccess` + `setIsLoggedIn(true)` 双保险 |
| P1 | 全局改 Dialog 影响 SelectResumeModal | 弹窗视觉破坏 | AuthDialog 局部 className 定制 |
| P1 | 删除 /login /register 路由 | URL 直达 404 | 保留路由不变 |
| P1 | 登录成功强制 navigate("/") | 破坏当前浏览上下文 | 弹窗内不 navigate，只关弹窗 |
| P2 | 移动端弹窗高度适配 | 小屏顶部/底部切边 | 后续响应式精修 |
