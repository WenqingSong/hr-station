## 八、根因判断

**根因：非代码问题。最可能的原因是运行时环境问题。**

| 可能原因 | 概率 | 证据 |
|----------|:--:|------|
| **Token 过期/无效** | **高** | 无 token → 401 → `requestRaw` 清除 token + 触发 `offerr-auth-expired` → 组件 catch 中 `navigate` 可能竞态失败 → 回退到显示错误文案 |
| **Token 存在但后端 session 丢失** | **高** | Redis 重启后 session 消失，token 仍有效但后端找不到用户 |
| **React Strict Mode** | 中 | useEffect 双触发，第二次可能状态不一致 |
| **网络问题/Vite 代理故障** | 低 | 其他接口正常排除了此可能 |
| **代码逻辑错误** | **极低** | 逐层验证全部通过 |

**最终判断：H（token/auth 问题导致 401，但组件 catch handler 未能正确重定向到登录）。**

补充说明：
- 如果错误确实是 401，`getAuthRedirectIf401` 应该返回 redirect URL，`navigate` 应跳转
- 但如果组件在 401 处理后已经因状态变化被卸载/重新挂载，`navigate` 可能不生效
- 此时 `resumeError` 被设置为"指定简历版本加载失败"，用户看到此错误文案

---

## 九、推荐修复方案

**方案：防御性修复 — 401 时明确重定向，避免回退到错误文案。同时增加通用错误分类。**

### 推荐改动

| 文件 | 修复内容 |
|------|------|
| `MyResumesPage.tsx` | 在 `getResumeDetail` 的 catch 中加入：错误分类（401/404/other），401/404 分别给不同提示 |
| 不需要改 | `api/resumes.ts`、`client.ts`、`resumeAdapter.ts`、后端 |

具体修改建议：
```tsx
.catch((err) => {
  // 401 → 登录重定向
  const authRedirect = getAuthRedirectIf401(err, location.pathname, location.search);
  if (authRedirect) { navigate(authRedirect, { replace: true }); return; }
  
  // 404 → 版本不存在
  if (isApiClientError(err) && err.status === 404) {
    setResumeError("该简历版本不存在或已被删除。"); return;
  }
  
  // 其他 → 通用错误
  setResumeError("指定简历版本加载失败，请稍后重试。");
  setLoading(false);
});
```

### 额外建议

为帮助后续排障，建议在 `.catch` 中加入 `console.error` 打印完整错误对象，便于从浏览器 console 确认具体失败原因。
