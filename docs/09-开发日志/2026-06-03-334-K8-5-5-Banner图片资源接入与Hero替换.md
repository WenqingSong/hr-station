# K8-5-5：Banner 图片资源接入与首页 Hero 替换

## 一、本阶段目标

将用户提供的生成图片作为 `/jobs` 岗位列表页顶部 Hero Banner，替换当前 K8-5-4 的 CSS 渐变/抽象图形版本。

核心要求：
1. Banner 使用用户提供的图片素材
2. Banner full-width，不再是 CSS 小卡片
3. 与现有 Liquid Glass Navbar 适配（Navbar 悬浮覆盖 Banner 上方）
4. 图片不变形、不重复叠加旧 HTML 文案
5. 保持响应式适配

## 三、JobHeroBanner 修改方案

将 `JobHeroBanner.tsx` 完全重写为图片版：

- **移除所有旧 CSS 装饰层**：渐变背景、光斑、圆环、网格纹理、底部微光边缘
- **移除所有旧文案叠加层**：主标题、副标题、辅助说明、AI 智能匹配标签
- **移除右侧 CSS 抽象卡片图形**
- **改为 `<img>` 引用**：`src="/images/offer-catcher-banner.png"`
- **响应式高度**：
  - 小屏（<640px）：`h-[180px]`
  - 中屏（640px~1023px）：`h-[240px]`
  - 大屏（1024px~1279px）：`h-[320px]`
  - 超宽（≥1280px）：`h-[360px]`
- **图片展示策略**：`object-cover object-center`
  - 保证图片横向铺满容器
  - 中心聚焦，裁切上下边缘以适配容器高度
  - 不变形
- **加载前 fallback**：容器保留 `bg-[#0052D9]` 背景色，避免图片加载前出现空白

## 八、响应式风险

| 断点 | 容器高度 | 说明 |
|------|---------|------|
| 桌面端（≥1280px） | 360px | 图片中心聚焦，主视觉和文字可见性较好 |
| 大屏（1024px~1279px） | 320px | 适度裁切上下边缘 |
| 中屏（640px~1023px） | 240px | 图片纵向压缩较多，但仍可辨识主视觉 |
| 小屏（<640px） | 180px | 高度较小，主文字仍可辨识，装饰元素可能部分裁切 |

**风险提示**：
- `object-cover` 策略会根据容器高度裁切图片上下边缘。由于原始图片比例（2.5:1）与桌面端容器比例（如 1920/360 ≈ 5.3:1）差异较大，宽屏下上下裁切量较多。
- 若实机验证发现主文字或核心视觉被过度裁切，可后续调整为 `object-contain` + 背景色填充方案，或降低容器高度以贴近图片原始比例。
- 当前中心聚焦策略（`object-center`）在多数屏幕下能保留图片核心内容。
