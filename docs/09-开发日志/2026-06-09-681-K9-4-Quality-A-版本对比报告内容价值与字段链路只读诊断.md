### 3.1 问题文本来源

| 问题文本 | 文件位置 | 生成逻辑 |

### 3.2 逐字段诊断

| 字段 | 当前生成逻辑 | 是否空泛 | 根因 |
| -- | -- | -- | -- |
| `keep_from_items` | 模板 "保留from版本的整体结构框架" | ❌ **极度空泛** | 未引用实际简历内容（项目/技能/教育等） |
| `keep_to_items` | 模板 "保留to版本的整体结构框架" | ❌ **同上** | 同上 |
| `merge_suggestions` | 模板 "合并为完整简历" | ❌ **无具体模块** | 未说明具体合并哪部分、怎么写 |
| `rewrite_examples` | 模板 "将经历改写为STAR格式" | ❌ **无实际文本** | 无 before/after 示例 |
| `next_version_suggestions` | 模板 "继续补充项目经验" | ❌ **无行动项** | 非可执行清单 |
| `key_differences` | 仅 1 条 | ❌ **太少** | 应至少 3 条 |
| `winner_label` | 硬编码 "目标版本在整体质量上更优" | ❌ **无信息量** | 固定字符串 |

### 3.3 根本原因

**Mock Agent 是模板生成器，不是真正的内容生成器**。它没有：
- 读取两份简历的具体项目、技能、教育、实习、作品差异
- 基于真实模块差异生成建议
- 将"from/to"替换为"旧版/新版"的用户术语

### cleanText 现状

`cleanText()` 函数（L30 附近）做基础清洗（trim/null check），但**不处理**：
- "from版本" → "旧版"
- "to版本" → "新版"
- "方向方向" → "方向"
- "整体结构框架" → 无

**前端兜底建议**：在 `cleanText` 中增加正则替换 `/\bfrom版本\b/g` → `旧版`，`/\bto版本\b/g` → `新版`。

## 六、内容质量标准设计

| 字段 | 新标准 |
| -- | -- |
| `key_differences` | 至少 3 条，格式："**变化点**" + "**影响**"（如："新增了Go项目经历，直接支撑后端岗位初筛关键词"） |

| `merge_suggestions` | 至少 3 条，可执行（如："将旧版课程描述作为新版项目经历的背景句，不单独占一个模块"） |

| `next_version_suggestions` | 至少 3 条，可执行的行动清单 |
| `delivery_advice` | 明确投递方向和版本选择理由 |
| **禁止文案** | "from版本"/"to版本"/"整体结构框架"/"目标版本在整体质量上更优"/"方向方向" |
