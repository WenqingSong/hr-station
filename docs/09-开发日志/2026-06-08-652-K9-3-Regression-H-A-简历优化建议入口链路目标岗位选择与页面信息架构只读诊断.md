## 六、状态机诊断

### 6.1 当前状态机 (OptPhase)

```
入口 → loading_latest → [has_result && quality] → deep_done
                       → [has_result && !quality] → fast_done
                       → [!has_result] → fast_loading → fast_done / fast_error

fast_done/ deep_done → deep_loading → deep_done / deep_error
```

| 状态 | 触发条件 | 当前 UI | 问题 |
|------|---------|---------|------|
| loading_latest | 页面挂载，GET latest | PageLoading "正在加载优化建议…" | 无骨架屏 |
| fast_loading | latest has_result=false，自动 POST fast | PageLoading "正在加载优化建议…" | 无骨架屏 |
| fast_done | fast 返回成功 | FastView（max-w-[720px]） | 内容少，仅 quickFix + risk + delivery |
| deep_loading | 用户点击"生成深度优化" | AgentStepLoadingOverlay | 覆盖层效果 OK |
| deep_done | quality 返回成功 | DeepView（max-w-[780px]） | 内容多但平铺，无优先级 |
| fast_error | fast 生成失败 | 错误提示 + 返回链接 | — |
| deep_error | quality 生成失败 | 保留 activeResult + 重试按钮 | OK |

### 6.2 核心问题

| # | 问题 |
|---|------|
| 1 | **general 模式被作为主路径**：2 个入口不传 jobId 时 fallback 到 general，但 general 结果缺乏针对性 |
| 2 | **缺少 jobId 时的 fallback 不合理**：应该引导用户先选择目标岗位，而非默默降级为 general |
| 3 | **target_job 依赖 URL 参数**：页面无法在不离开的情况下切换到 target_job |
| 4 | **没有入口弹窗**：用户应在进入页面前完成"选择简历 + 选择目标岗位" |
| 5 | **三模式推导优先级**：`target_job > target_direction > general`，但实际仅 target_job 和 general 被使用 |
