# K8-5-15-C-R：我的简历页 Navbar 视觉异常修复

## 1. 问题背景

用户反馈：`/resumes` 我的简历页面的 Navbar 视觉异常：

1. Navbar 背景是灰色/半透明状态。
2. 品牌字 Offerr鹅、我的简历、退出都是白色。
3. 在普通内容页背景（`bg-[#F5F7FB]` 浅灰）上对比度很低，像被蒙了一层灰。
4. 这明显不像普通内容页 Navbar，反而像 Hero 页面顶部的透明白字 Navbar。

## 2. Navbar 原因分析

| 检查项 | 结果 |
|--------|------|
| Navbar 是否只按 `isTop` 控制视觉 | **是**。所有样式类（`navSurfaceClass`、`brandTextClass`、`linkClass`、`logoutLinkClass`、`loginButtonClass`）均仅基于 `isTop`（scrollY ≤ 80）判断 |
| Navbar 是否通过 `useLocation()` 获取当前路由 | **是**。`location` 已存在于组件中，但仅用于 auth 监听刷新，未用于样式判断 |
| `/resumes` 是否被错误套用了顶部白字透明样式 | **是**。`isTop=true` 时，内容页使用 Hero 样式：`bg-slate-950/18 text-white`（深色半透明玻璃 + 白字），在浅灰 `bg-[#F5F7FB]` 背景下对比度极低 |
| `/jobs` 首页是否需要保留 Hero Navbar | **是**。首页有 `JobHeroBanner` 深蓝背景，白字透明 Navbar 体验正确 |
| `/jobs/:id` 岗位详情是否需要保留 Hero Navbar | **是**。详情页有 `JobDetailBanner` 蓝色背景 |

**根因**：Navbar 缺失路由类型判断，`isTop` 全局生效导致所有页面在顶部时都使用 Hero 透明样式。

## 3. 修复方案

### 新增路由语义判断

```ts
const isHeroNavbarRoute =
  location.pathname === "/" ||
  location.pathname === "/jobs" ||
  /^\/jobs\/[^/]+$/.test(location.pathname) ||
  /^\/job\/[^/]+$/.test(location.pathname);

const useHeroNavbar = isHeroNavbarRoute && isTop;
```

### 样式分流

| 区域 | 修改前 | 修改后 |
|------|--------|--------|
| `navSurfaceClass` | `isTop ? Hero样式 : 普通样式` | `useHeroNavbar ? Hero样式 : 普通样式` |
| `brandTextClass` | `isTop ? text-white : text-slate-950` | `useHeroNavbar ? text-white : text-slate-950` |
| `linkClass` | `isTop ? text-white/88 : text-slate-700` | `useHeroNavbar ? text-white/88 : text-slate-700` |
| `logoutLinkClass` | `isTop ? text-white/72 : text-slate-500` | `useHeroNavbar ? text-white/72 : text-slate-500` |
| `loginButtonClass` | `isTop ? 白字玻璃 : 深色字` | `useHeroNavbar ? 白字玻璃 : 深色字` |
| `brandTextShadow` | `isTop ? shadow : undefined` | `useHeroNavbar ? shadow : undefined` |

### 核心原则

```
isTop 只影响 Hero 页面。
普通内容页不管是否在顶部，都使用普通 Navbar（白底/毛玻璃/深色字）。
```

### 普通页面确认不会进入 Hero Navbar

全部 `/resumes`、`/resumes/new`、`/resumes/edit`、`/resumes/compare`、`/recommend`、`/match`、`/resume-optimization` 路由均不匹配 `isHeroNavbarRoute` 的 4 条规则，因此 `useHeroNavbar = false`，不会进入 Hero 样式。

### Hero 页面保护确认

`/`、`/jobs`、`/jobs/:id`（含 legacy `/job/:id`）仍正确触发 `isHeroNavbarRoute = true`，配合 `isTop` 即可使用 Hero Navbar。
