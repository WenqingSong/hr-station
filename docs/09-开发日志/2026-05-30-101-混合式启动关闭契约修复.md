# 2026-05-30-101-混合式启动关闭契约修复

## 1. 本次任务

修复 `make down` 不能可靠关闭 frontend Vite 子进程的问题，以及 `make restart-soft` 可能复用旧 Vite 进程的问题。

## 2. 背景

4-3.7.B.R.2 已落地混合式开发环境，但判定为 `partial_pass`，因为：
- `make down` 后 Vite 子进程可能仍然占用 5173
- npm 启动前端时产生多层子进程树（npm→sh→node），`stop_pid_file()` 只杀直接子进程，node 孙进程可能残留
- 这违反了最核心的启动关闭契约：启动就是启动，关闭就是关闭

## 3. 问题原因

1. **`stop_pid_file()` 只杀直接子进程**：使用 `pgrep -P $pid` 只找一层子进程，无法处理 npm→sh→node 三层进程树
2. **`web.sh stop_web()` 无端口兜底**：`backend.sh` 有端口兜底清理逻辑，但 `web.sh` 没有
3. **npm→sh→node 进程链**：`npm run dev` 会通过 `sh -c` 执行脚本，sh 再启动 node 进程。当 kill sh 后，node 成为孤儿进程继续监听 5173

## 4. 修改范围

- `scripts/dev/common.sh`：增强 `stop_pid_file()`，新增 `get_all_descendants()` 递归后代查找
- `scripts/dev/web.sh`：`stop_web()` 新增端口 5173 兜底检查
- 文档更新（Makefile说明、混合式开发环境最终方案、启动与部署标准化方案、项目状态、下一步任务、变更记录、说明书）

## 5. frontend stop 修复

### 5.1 `common.sh` 修复

新增 `get_all_descendants()` 函数：
- 递归查找 PID 的所有后代进程（深度优先）
- 处理 npm→sh→node 等多层进程树

修改 `stop_pid_file()` 函数：
- 在 kill 之前先收集所有后代 PID（递归）
- 先杀后代（从叶子到根），再杀主进程
- 等待时检查所有进程（主进程+后代）是否退出
- 强制终止时也覆盖所有后代

### 5.2 `web.sh` 修复

新增 `stop_web()` 端口兜底逻辑：
- `stop_pid_file()` 执行后检查 5173 是否仍被占用
- 通过 `lsof` 找到占用进程
- 判断是否属于本项目：
  - 命令行含 `vite` → 是
  - 命令行含 `npm.*dev` → 是
  - cwd 为项目 web 目录 → 是
- 确认属于本项目：杀进程及其后代，必要时 SIGKILL
- 不属于本项目：只输出 WARN，不强杀，提示用户手动处理

## 9. 当前限制

- 端口兜底依赖 `lsof` 命令，如果系统无 lsof 则无法检测端口残留
- 端口兜底的项目归属判断基于命令行关键词和 cwd，可能存在极少数边界情况无法判断
- 不使用 `killall node` 或 `pkill node`，避免影响其他项目的 Node 进程
