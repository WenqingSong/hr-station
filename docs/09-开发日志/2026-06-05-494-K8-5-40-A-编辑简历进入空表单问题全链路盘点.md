## 八、根因判断

**根因组合：A（编辑按钮不传参数）+ B（编辑页不读参数）+ E（versions 列表只有摘要无法直接复用）**

```
链路还原：

1. 用户在 /resumes 点击第 1 份简历"编辑"
   → <Link to="/resumes/edit">（无 versionNo）
   
2. MyResumesPage mount，pathname 不含 "/new"
   → mode = "edit"
   → 调用 loadResumeManagementPageViewModel()
   → getCurrentResume()
   → 返回 version_no=9 的数据
   
3. 如果 current 成功返回 → 显示 version 9 的数据（不是用户点的那份）
   如果 current 失败/为空 → 显示空表单

4. 无论显示什么数据，都不是用户点击的那份简历。
```

**最根本的缺陷**：编辑按钮不传 versionNo，编辑页也只关心当前最新版本。这是"当前简历"模型的遗留设计，不适用于多版本简历管理。

## 九、方案比较

| 方案 | 做法 | 是否可行 | 原因 |
|------|------|:--:|------|
| **A（纯前端）** | `/resumes/edit?versionNo=X`，编辑页用 `getResumeDetail(versionNo)` 加载 | ✅ **推荐** | `GET /api/resumes/versions/{versionNo}` 已返回完整数据，只需前端传参和读取 |
| B（新后端接口） | 新增 `GET /api/resumes/versions/{versionNo}/full` | ❌ 不必要 | 已有 `GET /api/resumes/versions/{versionNo}` 返回完整数据 |
| C（versions 改返回完整数据） | versions 列表改为返回完整 JSON | ❌ 不必要 | 列表不需要完整数据，指定版本已有单独接口 |

**推荐：方案 A，纯前端修复。**

### 数据转换

`loadResumeVersionDetail(versionNo)` 返回 `Resume | null`，与 `getCurrentResume()` 返回的同类型。编辑页已有完整的 V1+V2 回填逻辑（`toResumeManagementViewModel` → `formVm` → 表单 state），复用 `toResumeManagementViewModel(resume)` 即可。

核心改动点：
```tsx
// MyResumesPage: 根据 query param 决定加载目标
const [searchParams] = useSearchParams();
const targetVersionNo = searchParams.get("versionNo");

useEffect(() => {
  if (mode === "edit") {
    if (targetVersionNo) {
      const vn = Number(targetVersionNo);
      if (vn && !isNaN(vn)) {
        loadResumeVersionDetail(vn).then((resume) => {
          if (resume) setFormVm(toResumeManagementViewModel(resume));
          else setResumeError("简历版本不存在或加载失败。");
        }).catch(...);
        return;
      }
    }
    loadResumeManagementPageViewModel().then(...).catch(...);
  }
}, [mode, retryCount, targetVersionNo]);
```
