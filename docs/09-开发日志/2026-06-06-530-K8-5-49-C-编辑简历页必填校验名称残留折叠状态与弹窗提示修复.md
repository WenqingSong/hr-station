# K8-5-49-C：编辑简历页必填校验、名称残留、折叠状态与弹窗提示修复

## 任务背景

K8-5-49-B 完成后，用户浏览器验收发现编辑简历页仍有 6 个交互问题。

## 用户反馈的 6 个问题

1. 重新打开"添加简历 / 编辑简历"页面时，"简历名称"出现之前填写过的残留值。
2. "基础信息"模块是必填模块，不应该出现折叠按钮，应始终展开。
3. "简历名称"和"姓名"都是必填字段；前端必须检查，未填写不能保存。
4. 简历名称冲突提示应明显偏红色；当前黑色不够像错误提示。
5. 如果必填内容未填写，或者简历名称冲突，点击保存时都应该弹出通用弹窗提示用户。
6. 添加新简历时，"教育经历"、"项目经历"、"技能信息"都应该默认折叠。

| 文件 | 修改 |

### MyResumesPage.tsx 详细修改

#### 1. 新增页面残留值修复
- 新增 `isCreateMode` 变量：`const isCreateMode = !editingResumeId;`
- 新增 `resetFormForCreate()` 函数：清空所有表单状态（resumeName、personalName、phone、email、currentCity、educations、projects、skillsDraft、internships、languageExams、certificates、awards、portfolio、extraInfo），并重置 nameCheckStatus 和消息。
- 新增 `useEffect`：当 `editingResumeId` 变化且 `isCreateMode` 为 true 时，调用 `resetFormForCreate()`。

#### 2. 基础信息模块不可折叠
- 修改 `BasicInfoSection.tsx` 组件内部，添加 `collapsible={false}`（与 `ResumeBasicsSection` 一致）。

#### 3. 新增简历默认折叠规则
- 新增模式下：
  - `EducationSection`: 传入 `defaultOpen={!isCreateMode}`
  - `ProjectSection`: 传入 `defaultOpen={!isCreateMode}`
  - `SkillsSection`: 传入 `defaultOpen={!isCreateMode}`
- 编辑模式下：保持原有逻辑不变（根据内容自动展开）。

#### 4. 简历名称与姓名必填校验
- 修改 `saveDisabled` 逻辑：仅在 `saving || nameCheckStatus === "checking"` 时禁用保存按钮。
- 在 `handleSave` 开头新增必填校验：
  - 两者都为空 → 弹窗"请填写必填信息"
  - 名称为空 → 弹窗"请填写简历名称"
  - 姓名为空 → 弹窗"请填写姓名"
- 名称状态校验（checking / duplicate / invalid / error）→ 弹窗提示

#### 5. 重名提示红色化
- 修改 `nameCheckStatus` 样式：
  - `duplicate` / `invalid`：`bg-red-50 border-red-200 text-red-600`（去掉了 opacity 修饰符）
  - `error`：`bg-red-50 border-red-100 text-red-500`
  - `available`：`bg-green-50 border-green-100 text-green-700`
  - `idle`：`bg-slate-50 border-slate-100 text-slate-500`

#### 6. 必填缺失 / 名称冲突弹窗
- 新增 `formAlert` 状态管理（open、title、description、variant）
- 新增 `AppConfirmDialog` 实例，使用 `hideCancel` + `confirmText="我知道了"`
- 保存前检查必填、名称状态，不符合条件时弹出对应提示弹窗
- 保存前主动校验名称（当 `nameCheckStatus !== "available"` 时调用 `checkResumeName`）
- POST / PUT 返回 409 时，设置 duplicate 状态并弹窗提示
