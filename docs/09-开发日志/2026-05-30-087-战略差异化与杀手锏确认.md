# 2026-05-30-087-战略差异化与杀手锏确认

## 1. 本次任务

阶段 4-3.5.B：战略差异化与杀手锏确认。docs only，不修改任何代码。

## 2. 背景

当前项目已完成 MatchAnalysisAgent 和 RecommendationAgent 的 LLM Pipeline 接入与接口验收。但腾讯校招官网已有 Offer捕手 类 AI 交互入口，能进行岗位问答和基础推荐。本项目不能再把"根据简历推荐岗位"作为唯一核心卖点，需要重新明确战略定位。

## 3. 战略判断

1. 本项目不与官网 Offer捕手 做同质化岗位推荐定位
2. 将产品定位从"岗位推荐工具"升级为"投递前决策与简历初筛优化系统"
3. 不攻击或贬低腾讯官网能力，不写"替代 Offer捕手"
4. 官方 Offer捕手 告诉学生可以了解什么岗位；Offer 捕手帮助学生判断为什么投、先投哪个、哪里有风险、简历怎么改、优化到什么时候可以停止

## 4. 新产品定位

面向学生的投递前决策与简历初筛优化系统。

Demo 新主线：

```
学生填写/输入简历资料
→ 系统基于真实岗位 JD 推荐岗位
→ 用户选择目标岗位
→ 系统做 JD 证据链匹配分析
→ 系统给出简历初筛优化建议
→ 系统判断当前是否可以投递
→ 系统告诉用户优化到什么程度可以停止
```

## 5. 三个杀手锏

### 杀手锏一：投递边界与优化停止条件

- apply_readiness 枚举：ready_to_apply / quick_fix_before_apply / not_ready_for_this_role / insufficient_information
- optimization_stop_signal 枚举：stop_and_apply / fix_top_3_then_apply / needs_more_evidence / target_role_mismatch
- 核心原则：优化不是越多越好，当简历已能证明目标岗位核心能力时应建议投递

### 杀手锏二：JD 证据链匹配

- 每条建议绑定 JD 要求和简历证据
- 证据链结构：JD 要求 → 简历证据 → 匹配判断 → 风险差距 → 投递建议 → 简历优化动作
- 不输出泛泛建议，不脱离岗位要求做职业规划式回答

### 杀手锏三：Agent 输出 Quality Gate

- 设计：Generator Agent → Quality Gate/Critic → 通过则返回 → 不通过则重试一次或保守 fallback
- 检查项：基于真实 JD、基于简历证据、不编造经历、不编造岗位、给出投递边界、给出优化停止条件、使用示例参考、提醒用户核实、包含自查问题、不评价敏感属性、符合 Schema、前端可展示
- 本阶段只做设计确认，不实现

## 6. Prompt / Schema / Agent 影响

### Prompt 影响

- 匹配分析 Prompt：需强化 JD 证据链、投递边界、优化停止条件、用户核实提醒
- 推荐 Prompt：需强化推荐优先级、投递边界、推荐置信度、候选岗位证据
- 简历优化 Prompt：需强化示例参考（不是必须照写）、STAR-T 方法、自查问题、学习关键词

### Schema 影响

- 可能新增字段：apply_readiness / optimization_stop_signal / self_check_question / learn_more_query / verification_notice / quality_gate_result
- 本阶段只登记方向，不修改 Schema 文件

### Agent 影响

- MatchAnalysisAgent：输出需从"给结果"升级为"给证据、边界、可核实建议"
- RecommendationAgent：输出需从"给推荐列表"升级为"给优先级、投递边界、推荐理由证据"
- ResumeOptimizationAgent：输出需从"建议改为"升级为"示例参考 + STAR-T 检查 + 可核实机制"

### 简历优化表达原则

- 术语替换："建议改为" → "示例参考"
- 标准输出：原表达 → 问题 → 影响初筛原因 → 优化方向 → 示例参考 → 使用前请核实 → 自查问题 → 学习关键词
- START / STAR-T 技术岗表达法：Situation / Task / Action / Result / Tech
