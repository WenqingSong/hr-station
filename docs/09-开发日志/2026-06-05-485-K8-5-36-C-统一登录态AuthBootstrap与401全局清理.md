# K8-5-36-C：统一登录态 Auth Bootstrap、401 全局清理与统一登录弹窗链路修复

> **日期**: 2026-06-05
> **性质**: 前端改造（只改前端）
> **状态**: ✅ 已完成
> **依赖**: K8-5-36-B（只读盘点）

---

## 一、本阶段目标

基于 K8-5-36-B 的盘点结论，实施专业前端登录态治理：

1. 所有页面统一使用同一套登录态来源（AuthContext）
2. App 启动时做 auth bootstrap（/auth/me 校验）
3. token 存在时调用 /api/auth/me 校验，失败清理 token + store + UI
4. API 401 全局通知前端清理登录态
5. Navbar / RequireAuth / AIDecisionWorkspace 统一从 AuthContext 读状态
6. /?auth=login&redirect=... 自动打开统一 AuthDialog
7. 不再出现 Navbar 已登录、页面又要求登录的状态错乱

---

## 二、根因（来自 K8-5-36-B 盘点）

```
C: Redis 重启 / make reset-up 后 Redis Session 丢失，旧 JWT 失效。
A: Navbar 只看 localStorage token 是否存在。
G: AIDecisionWorkspace 独立管理登录态，isLoggedIn 只在 mount 初始化。
D: client.ts 401 清 localStorage，但不通知 React 组件刷新。
```

## 三、修改文件

| 文件 | 操作 | 说明 |
|------|:---:|------|
| `web/src/stores/authStore.tsx` | **新增** | React Context + useReducer 统一 auth 状态；AuthProvider、useAuth、bootstrapAuth、offerr-auth-expired 监听 |
| `web/src/api/client.ts` | 修改 | 401 时新增 `window.dispatchEvent(new Event("offerr-auth-expired"))` 通知 React |
| `web/src/app/App.tsx` | 修改 | 包裹 `<AuthProvider>` + `<AuthBoot />` 启动 bootstrap |
| `web/src/app/components/Navbar.tsx` | 修改 | 移除 localStorage 直接读取；改用 `useAuth().isAuthenticated`；handleLogout → clearAuth() |
| `web/src/app/components/auth/AuthDialog.tsx` | 修改 | 登录成功后调用 `useAuth().setAuthenticated(token, user)` 替代直接 `setAuthToken` |
| `web/src/app/components/auth/RequireAuth.tsx` | 修改 | 接入 useAuth()；isAuthReady → loading；isAuthenticated → 判断登录 |
| `web/src/app/components/ai/AIDecisionWorkspace.tsx` | 修改 | 移除独立 `isLoggedIn` state；改用 `useAuth().isAuthenticated`；401 后 UI 同步刷新 |

## 四、登录态统一结果

| 位置 | 修改前 | 修改后 |
|------|--------|--------|
| **Navbar** | `!!getAuthToken()` 直接读 localStorage | `useAuth().isAuthenticated`（AuthContext） |
| **RequireAuth** | `getAuthToken()` 同步读 localStorage | `useAuth().isAuthReady` → loading；`useAuth().isAuthenticated` → 判断 |
| **AIDecisionWorkspace** | `useState(() => !!getAuthToken())` 仅 mount 初始化 | `useAuth().isAuthenticated`（AuthContext，响应式） |
| **client.ts 401** | `clearAuthToken()` 只清 localStorage | `clearAuthToken()` + `dispatchEvent("offerr-auth-expired")` 全局通知 |
| **AuthDialog** | `setAuthToken(res.token)` 只写 localStorage | `useAuth().setAuthenticated(res.token, res.user)` 写 store + localStorage |
| **LoginPage** | 已是 redirect wrapper（K8-5-36-A） | 无变化 |
| **RegisterPage** | 已是 redirect wrapper（K8-5-36-A） | 无变化 |

## 五、Auth Bootstrap 结果

| 检查项 | 结果 |
|--------|:---:|
| App 启动时调用 bootstrapAuth() | ✅ App.tsx `<AuthBoot />` → `useEffect(() => bootstrapAuth())` |
| 无 token → 直接 setAuthReady | ✅ `dispatch({ type: "SET_AUTH_READY" })` |
| 有 token → 调用 GET /api/auth/me | ✅ `getMe(token)` 调用后端验证 |
| 校验成功 → setAuthenticated | ✅ `dispatch({ type: "SET_AUTHENTICATED", token, user })` |
| 校验失败 → clearAuth | ✅ `clearAuthToken()` + `dispatch({ type: "CLEAR_AUTH" })` |
| isAuthReady 阻止 protected 页面闪烁 | ✅ RequireAuth 在 `!isAuthReady` 时显示 `<PageLoading>` |
| public 页面不被 bootstrap 阻塞 | ✅ `<AuthBoot />` 渲染 null，不阻塞 Router |
