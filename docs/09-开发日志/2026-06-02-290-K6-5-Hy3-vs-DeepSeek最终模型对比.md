## 5. 成本对比

假设一次 Agent 调用：
- Prompt 约 2000 tokens（系统提示 + Prompt 模板 + 简历上下文 + JD）
- 输出约 3000 tokens（JSON 结构化输出）

| 模型 | 1 次调用（美元，约） | 100 次调用 | 1000 次调用 |
|------|:--:|:--:|:--:|
| **deepseek-v4-flash** | $0.00112 | **$0.11** | **$1.12** |
| deepseek-v4-pro | $0.00348 | $0.35 | $3.48 |
| Tencent HY 2.0 Instruct (0-32K) | ¥0.0302 ≈ $0.0042 | ¥3.02 ≈ $0.42 | ¥30.2 ≈ $4.20 |
| Hy3 preview | 待定价 | 待定价 | 待定价 |

**结论**：
- deepseek-v4-flash 成本最低（约 deepseek-v4-pro 的 1/3）。
- 腾讯混元使用 TokenHub 定价可能不同（TokenHub 有套餐和折扣）。
- Demo 场景下调用量低（< 100 次），成本差异可忽略。

## 9. 最终推荐

### 推荐：混合策略

```
主模型：     deepseek-v4-flash
高质量模式：  deepseek-v4-pro（或 Hy3 preview，如后续 API 可用）
Demo 叙事模式：Hy3 preview（需获取 TokenHub Hy3 Key）
Fallback：    Mock Agent（始终可用）
```

### 为什么是混合策略

1. **deepseek-v4-flash 为主模型**
   - 成本最低（pro 的 1/3），1M 上下文窗口是杀手级特性
   - 384K 最大输出可容纳完整 JSON 结果 + 长简历
   - JSON Output + Tool Calls 原生支持
   - 适合高频调用（岗位推荐、匹配分析、版本对比）
   - 与现有 `HunyuanClient` OpenAI-compatible 接口**完全兼容**，只需改 model 名

2. **deepseek-v4-pro 为高质量模式**
   - Core 优化已验证通过（llm_agent / success）
   - 推理更强，适合作业复杂的简历优化标准模式
   - 1M 上下文 + thinking mode 可处理长简历 + 详细 JD

3. **Hy3 preview 为 Demo 叙事模式（如 API 可用）**
   - Demo 场景中"腾讯自研模型"的叙事价值远大于成本差异
   - 中文求职场景腾讯生态原生（腾讯 HR 系统、招聘数据理解）
   - CodeBuddy / CNB Docker 环境已在腾讯生态内
   - TokenHub 同平台接入，技术成本几乎为零（只需 model name + 可能新 Key）

4. **Mock Agent 始终做 fallback**
   - 任何模型都可能失败 → 不影响 Demo 演示
   - 现有 fallback 链路已稳定

### 各功能模型分配

| 功能 | 模型 | 原因 |
|------|------|------|
| 岗位推荐 | deepseek-v4-flash | 高频、大量岗位筛选、成本敏感 |
| 岗位匹配分析 | deepseek-v4-flash | JSON 输出稳定、成本可控 |
| 简历优化（标准） | deepseek-v4-pro | 需要更高质量的表达改写 |
| Optimization Core | deepseek-v4-pro | 已验证通过，2-3 条核心建议 |
| 简历版本对比 | deepseek-v4-flash | 差异检测 + 结构化输出 |

### Demo 模式（推荐场景）

```
Demo 模式：    可选全部切到 Hy3 preview
               - 叙事价值：腾讯自研模型 + CodeBuddy + TokenHub
               - 中文求职场景腾讯数据生态
               - 如 Key 不可用，切回 DeepSeek 混合策略
```
