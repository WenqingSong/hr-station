# K9-1-U-B：岗位推荐结果持久化、Fast/Deep 展示分层与状态机设计冻结

> 日期：2026-06-07 | 状态：已完成（设计冻结）

## 1. K9-1-U-A 诊断结论

- P0×2：Quality pending → 前端超时 / 结果只存不读
- P1×2：Fast/Deep 展示无差异 / 表缺 generation_tier
- P2×2：Quality 异步无通知 / 保存简历不触发 profile

## 2. 设计冻结范围

### 表结构

`recommendation_results` 新增 `generation_tier`、`generated_by`、`status` 列 + 2 个索引。开发库 ALTER，不改 init.sql。

### API

- 新增 `GET /api/jobs/recommend/latest?resume_id=X` — 读取最新保存结果
- `POST /api/jobs/recommend` 保持现有，增加 result_id / generation_tier 返回

### 保存策略

Append-only + latest 查询。每次成功生成 INSERT 一条，页面进入优先 GET /latest。

### 前端状态机

- 页面进入 → GET /latest → has_result → 展示；no → POST fast → 展示
- Deep 生成 → pending ≠ error → deep_profile_pending + 超时温和文案
- Fast 简化展示（1 evidence + 1 risk），Deep 完整展示（6 区块）

### Profile 生成

- 保存简历后触发 fast profile 生成
- Quality 按需（点击 Deep 时）触发
