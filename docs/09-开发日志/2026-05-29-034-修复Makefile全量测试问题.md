## 4. 修复内容

### P0-1：修复 `local` 在 case 块中的使用

**根因**：Bash 中 `local` 只能在函数体内使用。`case` 块不属于函数体。

**修复方式**：将使用 `local` 的 case 分支逻辑封装为独立函数，在 case 中调用函数。

- `mysql.sh`：`check)` → `do_check()` 函数
- `backend.sh`：`status)` → `do_status()` 函数，`health)` → `do_health()` 函数
- `quality.sh`：`lint)` → `do_lint()` 函数

### P0-2：修复 `go run` 子进程残留

**根因**：`go run ./cmd/server` 产生两个进程——`go run`（父）和 `server`（子）。`stop_pid_file` 只杀父进程，子进程仍在端口监听。

**修复方式**：
1. 增强 `stop_pid_file()`：在 kill 主进程前先查找并终止子进程（`pgrep -P`）
2. 增强 `stop_backend()`：增加端口残留进程兜底清理（检查 `SERVER_PORT` 上是否有 go/server 相关进程）

### P1-1：新增 `make health` target

**修复方式**：在 Makefile 中新增 `health` target，聚合基础设施状态、后端健康检查、前端健康检查、数据库检查。

同时更新 `check` target 从直接调用 `backend.sh health` 改为调用 `make health`，使 `check` = `doctor` + `health`。

### P1-2：优化 `backend-up` 等待逻辑

**修复方式**：将等待时间从 15 秒增加到 30 秒，适应首次 `go run` 下载依赖的场景。
