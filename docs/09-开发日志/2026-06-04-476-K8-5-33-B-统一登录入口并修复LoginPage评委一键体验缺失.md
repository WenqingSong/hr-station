# K8-5-33-B：统一登录入口并修复 LoginPage 评委一键体验缺失

## 一、本阶段目标

在 LoginPage.tsx 中补齐"评委一键体验"按钮和登录逻辑，使 RequireAuth 重定向到 `/login?redirect=...` 时评委也能一键体验。

## 二、P0 根因

```
RequireAuth 未登录时 → /login?redirect=%2Fresumes → LoginPage（旧版，无评委一键体验）。
AuthDialog 已有评委一键体验，但 LoginPage 独立页面缺失该按钮。
```

## 三、修改文件

| 文件 | 修改内容 |
|------|---------|
| `web/src/app/pages/LoginPage.tsx` | 新增 handleDemoLogin 函数 + "评委一键体验"按钮 + Loader2 导入 |

## 四、LoginPage 一键体验实现方式

1. **新增 import**：`Loader2` from lucide-react（用于 loading spinner）
2. **新增状态**：`demoLoading` / `setDemoLoading`
3. **新增函数 `handleDemoLogin`**：调用 `login({ phone: "13900139000", password: "123456" })`，成功写入 token 并 `navigate(safeRedirect)`，失败显示"示范账号登录失败，请稍后重试"
4. **UI 新增**：在普通登录按钮下方添加 `—— 或 ——` 分隔 + `🎯 评委一键体验`按钮 + 辅助说明
5. **互斥 disabled**：普通登录 loading 时禁用一键体验，反之亦然

## 五、redirect 处理是否保留

✅ 保留 — LoginPage 的 `getSafeRedirect` 和 `safeRedirect` 逻辑未修改。`handleDemoLogin` 登录成功后 `navigate(safeRedirect)`，与普通登录完全一致。

## 六、AuthDialog 是否未破坏

✅ 未修改 AuthDialog.tsx。仅新增 LoginPage 的一键体验。

## 七、是否新增后端接口

❌ 未新增。复用现有 `POST /api/auth/login`。
