## 3. 新产品目标冻结

**岗位匹配页面只回答 4 个问题：**

```
Q1: 这个岗位该不该投？（分数 + 投递建议 + 一句话结论）
Q2: 为什么是这个判断？（核心匹配点 + 主要风险 + 关键依据）
Q3: 最大风险是什么？（风险摘要 + 影响说明）
Q4: 简历现在该怎么改？（修改建议，最多 3 条可执行动作）
```

**所有页面信息必须服务于这 4 个问题。不服务的，不允许进入主视野。**

## 6. 第一屏信息架构

**第一屏只展示 4 块：**

```
1. Hero 决策卡
   └─ 分数（76）｜等级（中等匹配）｜建议（修改后投递）
   └─ 一句话结论
   └─ 重新生成按钮

2. 核心匹配点（最多 3 条）
   └─ ✅ Go 后端实习并上线 / 🔹 MySQL 数据库设计 / 🔹 Redis 缓存和限流

3. 主要风险（最多 3 条）
   └─ 🔴 Kubernetes 缺失 → 影响筛选通过率 → 如有学习经历可补充
   └─ 🟡 证据表达偏弱 → 建议使用 STAR 法则强化

4. 简历修改建议（最多 3 条）
   └─ 1. 将 Go 后端实习前置到核心位置
   └─ 2. 补充限流、幂等、权限校验描述
   └─ 3. 为关键技能补充量化成果

┌─────────────────────────────────────────────┐
│ 展开详情 ▼                                  │
│   JD 要求覆盖 · 简历证据映射 · 风险详情 ·    │
│   面试追问参考 · 技术调试信息                │
└─────────────────────────────────────────────┘
```

**第一屏不展示：** 面试追问、Agent Trace、quality_checks、完整 JD 解构长列表、完整证据映射长列表

**第一屏目标：** 用户 5 秒内知道该不该投、为什么、怎么改。

## 8. Fast / Deep 展示关系

**Fast：快速初筛**

- 该不该投（分数 + 等级 + 建议）
- 为什么（核心匹配 + 主要风险）
- 怎么改（修改建议，最多 3 条）
- 依据（JD 覆盖摘要 + 证据摘要）
- **详情折叠**：完整覆盖、完整证据、分数拆解

**Deep：深度顾问**

- 继承 Fast 的所有内容
- **额外：** Fast/Deep 分数对齐（一行）
- **额外：** Deep 补充判断（摘要 1-2 句）
- **详情折叠：** JD 深度解构、完整覆盖、完整证据、风险详情、简历改写策略、面试追问参考、Agent Trace

**Deep 也必须摘要优先！** 不再默认展示完整 10 个大模块长页面。
