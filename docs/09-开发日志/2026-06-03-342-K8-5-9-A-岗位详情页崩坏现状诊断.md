## 二、当前结构链路

```
JobDetailPage
  ├─ JobDetailBanner          (全宽蓝色 Hero，max-w-[1200px] 内容区)
  └─ TwoColumnPageShell       (max-w-6xl = 1152px)
       ├─ JobDetailJD          (主内容：白卡×2)
```

- 右侧 AI 内容通过 `AISidebarShell` 做 sticky + 高度限制 + 内部滚动

## 四、右侧 AI 崩坏根因（重点）

### 直接根因

**`AISidebarShell.tsx` L46-47**：
```tsx
"xl:max-h-[calc(100vh-7rem)]",
"xl:overflow-y-auto",
```

这两行代码将右侧 AI 容器限制在一个固定高度内（约 `100vh - 112px`），当内容超出时就触发独立滚动条。

### 间接根因

**`JobDetailAIDecision.tsx` 内容过长**（155 行）：
- Header（标题 + 说明）
- 当前岗位卡片
- 当前简历卡片（含切换简历按钮）
- 主操作卡片（分析匹配度 + 生成优化建议）
- 投递前确认提示卡片
- 2 个 `<SelectResumeModal>` 实例

这些内容在桌面端通常会超出 `100vh - 7rem` 的高度，从而触发 AISidebarShell 的内部滚动。

### 根因链条

```
AISidebarShell 声明了 max-h + overflow-y-auto（直接根因）
  → JobDetailAIDecision 内容过长（间接根因）
    → AI 模块出现独立滚动条
      → 页面出现双层滚动区域
        → 视觉崩坏
```

### 为什么在 JobListPage 没那么严重？

JobListPage 使用 `AISidebarShell` + `AIDecisionWorkspace`（约 120 行），结构类似但也有内部滚动风险。区别在于：
- JobListPage 的 AISidebarShell 显式 `className="xl:w-[300px]"` 强制宽度
- JobDetailPage 没有传 `stickyTopClassName`，默认为 `top-24`
- JobDetailAIDecision 的内容比 AIDecisionWorkspace 更多（岗位卡片 + 简历卡片 + 操作卡 + 提示卡 + Modal）
