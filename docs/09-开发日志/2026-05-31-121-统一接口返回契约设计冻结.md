# 2026-05-31-121-统一接口返回契约设计冻结

## 1. 本次任务

阶段 4-4.1：统一接口返回契约设计冻结

## 2. 背景

4-4.0 已完成三类 Agent 接口返回结构现状核验，发现：
- meta 字段位置不一致
- agent_status Mock direct 值不一致
- generated_by 双重设置
- fallback_required 仅 ResumeOptimization 有
- schema_valid / request_id 缺失

本阶段只做契约设计冻结，不做工程改造。

## 3. 设计依据

- `docs/04-接口文档/三类Agent接口返回结构现状核验.md`
- 三类接口文档（匹配分析 / 推荐 / 简历优化）
- Go Model 代码（match.go / recommendation.go / resume_optimization.go）
- Handler / Service / Agent 代码
- Pipeline / LLM 代码

## 4. 统一 Envelope

保持现有 HTTP 外层 `{code, message, data}` 不变。

新增 `data.result` + `data.meta` 分层：
- `data.result`：只放业务结果
- `data.meta`：只放系统状态（agent_name / generated_by / agent_status / fallback_reason / error_code / repair_applied / schema_valid / request_id）

## 5. meta 字段策略

### 5.1 字段清单

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| agent_name | string | ✅ | match_analysis / recommendation / resume_optimization |
| generated_by | string | ✅ | llm_agent / mock_agent |
| agent_status | string | ✅ | success / repaired / fallback / mock_success / error |
| fallback_reason | string | ✅ | none / llm_disabled / llm_error / llm_timeout / json_parse_failed / json_repair_failed / schema_invalid / pipeline_error / unknown |
| error_code | string | ✅ | none / LLM_DISABLED / LLM_ERROR / ... / UNKNOWN_ERROR |
| repair_applied | bool | ✅ | LLM repair 是否被应用 |
| schema_valid | bool | ✅ | 最终结果是否满足契约 |
| request_id | string | ✅ | 请求追踪 ID |

### 5.2 关键决策

1. **generated_by 唯一可信位置**：`data.meta.generated_by`，旧字段标记 deprecated
2. **agent_status 统一枚举**：Mock direct 一律使用 `mock_success`
3. **所有 meta 字段必填**：不使用 omitempty，前端稳定消费
4. **fallback_reason 默认 none**：不再使用空字符串
5. **error_code 默认 none**：不再使用空字符串

## 6. 状态枚举

### agent_status

| 值 | 含义 |
|---|------|
| success | LLM 正常成功 |
| repaired | LLM 输出异常，repair 成功 |
| fallback | LLM 失败或 repair 失败，Mock fallback |
| mock_success | Mock 直接返回 |
| error | 无可用结果 |

### fallback_reason

| 值 | 说明 |
|---|------|
| none | 无 fallback |
| llm_disabled | LLM 未启用 |
| llm_error | LLM 调用出错 |
| llm_timeout | LLM 超时 |
| json_parse_failed | JSON 解析失败 |
| json_repair_failed | JSON repair 失败 |
| schema_invalid | Schema 校验失败 |
| pipeline_error | Pipeline 异常 |
| unknown | 未知原因 |

### error_code

| 值 | 说明 |
|---|------|
| none | 无错误 |
| LLM_DISABLED | LLM 未启用 |
| LLM_ERROR | LLM 调用出错 |
| LLM_TIMEOUT | LLM 超时 |
| JSON_PARSE_FAILED | JSON 解析失败 |
| JSON_REPAIR_FAILED | JSON repair 失败 |
| SCHEMA_INVALID | Schema 校验失败 |
| PIPELINE_ERROR | Pipeline 异常 |
| MOCK_FALLBACK_USED | 使用兜底结果 |
| VALIDATION_ERROR | 参数错误 |
| INTERNAL_ERROR | 内部异常 |
| UNKNOWN_ERROR | 未知异常 |

## 7. 前端展示规则

| 路径 | 条件 | 前端展示 |
|------|------|---------|
| LLM success | generated_by=llm_agent, agent_status=success, repair_applied=false | 正常结果 + "LLM 生成" |
| Repaired | generated_by=llm_agent, agent_status=repaired, repair_applied=true | 正常结果 + "已自动修复结构" |
| Fallback | generated_by=mock_agent, agent_status=fallback, fallback_reason!=none | 兜底结果 + "已使用兜底结果" |
| Mock direct | generated_by=mock_agent, agent_status=mock_success | Mock / 演示标签 |
| Error | agent_status=error 或 code!=0 | 错误态 + error_code 友好文案 |
