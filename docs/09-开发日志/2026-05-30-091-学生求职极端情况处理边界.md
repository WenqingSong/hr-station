## 3. 核心设计

### 3.1 candidate_case_type 十种枚举

| 值 | 定义 | 默认 case_risk_level |
|---|------|---|
| `normal_case` | 普通情况 | low |
| `insufficient_information` | 信息不足 | medium |
| `weak_resume` | 弱简历 | medium |
| `target_role_mismatch` | 岗位不匹配 | high |
| `overseas_or_location_risk` | 海外/地点风险 | medium |
| `high_potential_research_or_deep_tech` | 优秀候选人 | low |
| `unclear_job_intention` | 求职目标不清晰 | medium |
| `authenticity_risk` | 真实性风险 | high |
| `over_optimization_risk` | 过度优化 | low |
| `unsafe_user_request` | 造假请求 | critical |

### 3.2 核心原则

1. 极端情况处理不能脱离课题主旨（匹配合适岗位 + 提升初筛命中率）
2. 判断对象是"当前简历 × 当前岗位 JD"，不是"这个学生行不行"
3. 信息不足时保守，不强行推荐
4. 弱简历给最小可行动作，不否定学生
5. 岗位不匹配回到 JD 证据，不做人格判断
6. 海外/地点问题只处理投递条件与岗位适配
7. 优秀候选人只提示方向，不做长期职业规划

## 4. candidate_case_type 设计

定义了 10 种候选人情况类型，每种类型明确了：

1. 定义
2. 触发条件
3. 建议输出方式
4. 禁止表达
5. 与 apply_readiness 的关系
6. 与 Quality Gate 的关系

关键设计：

- `insufficient_information` → `apply_readiness=insufficient_information`，`case_handling_strategy=clarify_before_recommendation`
- `target_role_mismatch` → `apply_readiness=not_ready_for_this_role`，`case_handling_strategy=recommend_alternative_jobs`
- `unsafe_user_request` → `case_risk_level=critical`，`case_handling_strategy=refuse_fabrication`

## 5. case_risk_level 设计

四级枚举：

| 值 | 说明 |
|---|------|
| `low` | 普通情况或轻微表达问题 |
| `medium` | 信息不足、表达不清、地点偏好不明确 |
| `high` | 目标岗位明显不匹配、真实性风险较高 |
| `critical` | 用户要求造假、存在严重不当风险 |

与 Quality Gate 的关系：critical → fallback_required，high → revise_required，medium → manual_review_suggested，low → pass。

## 6. case_handling_strategy 设计

七种策略：

| 值 | 说明 |
|---|------|
| `normal_response` | 正常输出 |
| `clarify_before_recommendation` | 先提示补充信息 |
| `quick_fix_then_apply` | 先修 2-3 个点再投 |
| `recommend_alternative_jobs` | 建议优先看更匹配岗位 |
| `conservative_advice` | 输出保守建议 |
| `refuse_fabrication` | 拒绝编造或夸大 |
| `manual_review_suggested` | 建议用户自行核实 |

## 7. 三类 Agent 影响

### 7.1 MatchAnalysisAgent

- 需要识别 candidate_case_type
- 信息不足时不强行给高分
- 岗位不匹配时表达为"当前简历 × 当前岗位 JD 不匹配"
- 输出 apply_readiness 和 optimization_stop_signal

### 7.2 RecommendationAgent

- 信息不足时降低推荐置信度
- 岗位目标过宽时提示缩小方向
- 地点/语言/调配风险时标注风险
- 推荐更匹配的岗位

### 7.3 ResumeOptimizationAgent

- 区分表达问题和经历证据缺失
- 存在真实性风险时保守处理
- 拒绝编造请求
- 输出示例参考而非最终文本

## 8. Quality Gate 关系

Quality Gate 应检查 Agent 是否正确识别极端情况：

1. insufficient_information 被强行判断为 ready_to_apply → 不合格
2. authenticity_risk 被忽略 → 不合格
3. target_role_mismatch 被包装成高匹配 → 不合格
4. unsafe_user_request 被满足 → fallback_required
5. over_optimization_risk 继续给大量优化项 → consistency_check 失败
