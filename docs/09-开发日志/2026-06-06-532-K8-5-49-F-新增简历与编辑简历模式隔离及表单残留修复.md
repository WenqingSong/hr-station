# K8-5-49-F：新增简历与编辑简历模式隔离及表单残留修复

## 用户反馈问题

在 `/resumes` 页面中点击"添加简历"进入 `/resumes/edit` 后，"简历名称"仍然残留上一次保存过的简历名称。

## 根因分析

**双重根因**：

### 1. `loadResumeManagementPageViewModel()` 调用了 `getCurrentResume()`

在 create 模式下（`editingResumeId === null`），原代码调用 `loadResumeManagementPageViewModel()`，该函数会调用 `getCurrentResume()` 获取用户的当前简历数据，然后用它填充表单。这导致新增页面被旧简历数据污染。

```ts
// viewModels.ts line 92-101
export async function loadResumeManagementPageViewModel() {
  const resume = await getCurrentResume();  // ← 加载当前简历！
  if (!resume) return null;
  return toResumeManagementViewModel(resume);
}
```

### 2. `resetFormForCreate()` 未清除 `formVm`

即使先调用了 `resetFormForCreate()` 清空各字段，`formVm` 仍保留旧值。后续 form-filling useEffect 会用旧 `formVm` 重新填充字段，产生竞态。

## 修复内容

### 1. Create mode 不再调用 `loadResumeManagementPageViewModel()`

```ts
// 修改前（create mode 分支）：
loadResumeManagementPageViewModel().then((vm) => { setFormVm(vm); setLoading(false); })

// 修改后：
setFormVm(null);  // 清空 ViewModel，阻止 form-filling 触发
setLoading(false);
```

### 2. `resetFormForCreate()` 增加 `setFormVm(null)`

确保清空 ViewModel，阻断 form-filling useEffect 的触发路径。

### 3. 增加 `cancelled` 异步防护

```ts
let cancelled = false;
// ...async calls...
if (cancelled) return;
// ...
return () => { cancelled = true; };
```

防止从编辑页快速切到新增页时，旧 `getResumeById(N)` 回填覆盖 create mode。

### 4. `sectionAutoOpenKey` 加入模式区分

```ts
// 修改前：
const sectionAutoOpenKey = `${editingResumeId ?? "_new"}:${resumeName || "_empty"}`;

// 修改后：
const sectionAutoOpenKey = isCreateMode ? "create" : `edit-${editingResumeId}:${resumeName || "_empty"}`;
```

确保 create mode 和 edit mode 的展开/折叠状态完全独立。

### 5. 移除两个死代码 import

- `loadResumeManagementPageViewModel` — create mode 分支不再调用
- `getAuthRedirectIf401` — 仅被已删除的 catch 使用
