## 6. 关键决策

1. **路由分发机制**：Go 标准库 `http.ServeMux` 不支持路径参数，使用 dispatchJobRoutes 函数解析 /api/jobs/ 下的子路径，根据是否以 /match 结尾分发到 MatchHandler 或 JobHandler
2. **jobID 上下文传递**：使用自定义 contextKey 将解析后的 jobID 传递给 MatchHandler，避免重复解析
3. **证据链设计**：对岗位每个技能关键词、城市、方向分别生成证据条目，每条包含 requirement / resume_point / judgement
4. **初筛判断**：基于匹配分数区间划分（highly_likely ≥ 85, likely ≥ 70, possible ≥ 55, risky < 55）
5. **优化建议优先级**：P0 为缺失关键技能或岗位明确要求缺失，P1 为可提升的量化指标等
6. **真实性提示**：每条匹配分析结果都包含 authenticity_notice，明确告知用户不要虚构经历

## 9. 如何验证

```bash
# 默认匹配分析
curl -s -X POST http://localhost:18088/api/jobs/1/match \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{}'

# 指定简历版本
curl -s -X POST http://localhost:18088/api/jobs/1/match \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{"resume_version_no":1}'

# 非法岗位 ID（预期 40001）
curl -s -X POST http://localhost:18088/api/jobs/abc/match \
  -H "Authorization: Bearer <token>" -d '{}'

# 不存在岗位（预期 43001）
curl -s -X POST http://localhost:18088/api/jobs/999/match \
  -H "Authorization: Bearer <token>" -d '{}'

# 非法版本（预期 42001）
curl -s -X POST http://localhost:18088/api/jobs/1/match \
  -H "Authorization: Bearer <token>" -d '{"resume_version_no":999}'
```
