## 5. 工程改造评审

### 方向 A：立即修改 Prompt / Schema

- 收益：让当前 Agent 输出更贴合新战略
- 风险：Prompt / Schema 已稳定，直接改动可能破坏已通过验收的链路
- 结论：**不建议立即全面修改**

### 方向 B：立即实现 Quality Gate

- 收益：能体现核心杀手锏
- 风险：增加 LLM 调用成本、接口延迟、测试复杂度
- 结论：**不建议立即接入完整 LLM Critic，后续优先考虑轻量规则版**

### 方向 C：立即改 ResumeProfile / ResumeSection

- 收益：输入层更稳定
- 风险：涉及数据库/接口/前端，改动面大，打断 4-3 主线
- 结论：**不建议现在实现完整工程，放到阶段 5**

### 方向 D：继续 4-3.6 ResumeOptimizationAgent 现状核对

- 收益：保持阶段 4 主线完整
- 风险：简历优化 Agent 可能不完全符合新战略
- 应对：4-3.6 只做现状核对和接入方案，吸收战略边界
- 结论：**推荐**

### 方向 E：是否插入 4-3.5.I Prompt / Schema 改造评审

- 收益：避免直接改工程，先判断字段需求
- 风险：继续延长 docs 阶段
- 结论：**可选**，4-3.6 自然会评估 Prompt / Schema

## 6. 推荐决策

**主推荐：不立即大改工程，先进入 4-3.6。**

1. 不立即修改 Prompt / Schema
2. 不立即实现完整 Quality Gate
3. 不立即改 ResumeProfile / ResumeSection 工程结构
4. 先进入 4-3.6：ResumeOptimizationAgent 现状核对与接入方案

4-3.6 必须吸收 4-3.5.B ~ 4-3.5.G 的战略边界：
- 不做无限简历优化
- 不直接输出"建议改为"
- 使用"示例参考"
- 保留用户核实提醒
- 围绕 JD 证据链
- 区分 Top 3 快速优化项和长期提升项
- 如当前工程不支持，在方案中标记为后续改造
