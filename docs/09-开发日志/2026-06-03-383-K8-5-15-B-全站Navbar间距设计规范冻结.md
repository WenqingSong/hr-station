# K8-5-15-B：全站 Navbar 间距设计规范冻结

## 1. 本次范围确认
只做设计规范冻结，未修改源码。

## 2. 核心设计结论

**不建议直接给 RootLayout `<main>` 全局加 `pt-20`。**

原因：
- `/jobs` Hero 已有 `pt-24`，重复加间距会导致 Hero 下推
- `/jobs/:id` 详情已有自己的 offset
- `/login` `/register` 已有 `calc(100vh-3.5rem)` 处理

**推荐方案**：两类页面分开处理。

## 3. Navbar 高度 token

| Token | 值 | 用途 |
|-------|-----|------|
| mobile navbar | 64px (`h-16`) | pt 计算基准 |
| desktop navbar | 68px (`md:h-[68px]`) | pt 计算基准 |
| content gap | 24px | Navbar 到内容的呼吸间隔 |
| **总 pt** | **`pt-24`** (~96px) | 普通内容页统一顶部间距 |

推荐 `pt-24`（96px = 68px navbar + 28px gap），恒定即可，不区分 md 断点。

## 4. 页面类型规范

| 页面类型 | 顶部间距规则 | 适用页面 |
|---------|------------|---------|
| **Hero 页** | Hero 内部自行 `pt-24`，不走 ContentPageShell | `/jobs`, `/jobs/:id` |
| **普通内容页** | 统一使用 `ContentPageShell` (`pt-24`) | `/resumes`, `/recommend`, `/match`, `/resume-optimization`, `/resumes/compare`, `/resumes/new\|edit` |
| **Auth fallback** | 保留 `calc(100vh-3.5rem)`，暂不动 | `/login`, `/register` |

## 5. ContentPageShell 设计

| 项目 | 冻结方案 |
|------|---------|
| 文件路径 | `web/src/app/components/layout/ContentPageShell.tsx` |
| Props | `children, className?, maxWidthClassName?` |
| 默认样式 | `min-h-screen bg-[#F5F7FB] pt-24 pb-12 px-4 sm:px-6 lg:px-8` |
| 默认 max-w | `max-w-[1280px] mx-auto` |
| 可覆写 | 简历列表 `max-w-[960px]`，AI页面 `max-w-[1440px]` |
| 不处理 | Hero offset（留给 Hero 组件自己） |
