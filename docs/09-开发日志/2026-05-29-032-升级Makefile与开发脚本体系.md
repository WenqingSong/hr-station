## 4. 修改内容

### 4.1 Makefile 重写

- 核心设计：Makefile = 统一入口，scripts/dev/*.sh = 具体执行逻辑
- `make up` 按依赖顺序执行：doctor → init → infra-up → db-check → backend-up → web-up → health
- 后台进程管理：PID 文件 `.run/server.pid` / `.run/web.pid`，日志 `.logs/server.log` / `.logs/web.log`
- 危险操作保护：rebuild/db-reset/clean-volume 必须 CONFIRM=yes

### 4.2 .gitignore 更新

新增 `.run/` 和 `.logs/` 目录忽略

### 4.3 load_env 函数修复

原来使用 `source .env` 会导致 DSN 中的括号语法错误，改为逐行解析 export

## 5. 删除内容

无。

## 6. 关键决策

1. **Makefile 不堆复杂逻辑**：具体逻辑下沉到 scripts/dev/*.sh
2. **后台进程 PID 管理**：前后端以后台进程方式启动，PID 写入 .run/，日志写入 .logs/
3. **load_env 不用 source**：逐行解析避免 DSN 中特殊字符导致语法错误
4. **危险操作双重保护**：CONFIRM=yes 环境变量 + clean-volume 额外要求输入 YES
5. **agent.sh 不在 case 块中使用 local**：bash 的 local 只能在函数中使用，改为将逻辑封装到函数
6. **mask_secret 只显示「已配置」**：不泄露密钥长度或部分内容
7. **go run 而非 go build**：避免产生 server/server 编译产物

## 7. 云原生环境恢复设计

推荐恢复流程：

```bash
make doctor → make init → make up → make health
```

各步骤职责：
- doctor：只读检查环境
- init：补齐 .env（不覆盖已有），创建 .run/ 和 .logs/
- up：按依赖顺序一键启动（MySQL → 后端 → 前端）
- health：健康检查确认

## 8. 危险操作保护

| 命令 | 保护机制 | 提示 |
|------|---------|------|
| make rebuild CONFIRM=yes | 环境变量确认 | 显示危险提示，需 CONFIRM=yes |

| make clean-volume CONFIRM=yes | 环境变量 + 交互输入 | 先检查 CONFIRM=yes，再要求输入 YES |
