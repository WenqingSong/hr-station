## 四、MyResumesPage 失败点定位

### Line 269 精确对应

```
268:            // 其他错误 → 通用提示 + console.error 便于排障
269:            console.error("[resume-edit] failed to load resume version", { versionNo: editingVersionNo, error: err });
270:            setResumeError("指定简历版本加载失败，请稍后重试。");
```

**这是 `getResumeDetail` catch 的 "other" 分支**。

### 失败原因推断

Line 269 命中意味着 `isApiClientError(err)` 返回 false 或 `err.status` 不是 401/404。

| 可能原因 | 概率 | 解释 |
|----------|:--:|------|
| **`toResumeManagementViewModel(resume)` 抛异常** | **中** | `getResumeDetail` 成功返回数据，但 `.then((resume) => { const vm = toResumeManagementViewModel(resume); })` 在 adapter 中抛异常。异常是普通 `Error`，不是 `ApiClientError` → `isApiClientError` 失败 → 进入 "other" |
| **Vite HMR 模块身份问题** | **中** | Vite HMR 可能导致 `ApiClientError` 的 `instanceof` 检查失败（不同模块实例的类对象），使 `isApiClientError` 返回 false |
| **401 处理竞态** | **低** | `requestRaw` 清除 token + 触发 `offerr-auth-expired`，catch 中的 `isApiClientError` 可能因组件状态变化而失效 |

**最可能原因**：adapter (`toResumeManagementViewModel`) 中对特定版本数据处理时抛异常，异常类型为普通 `Error`，未被分类到 401/404。

## 七、根因判断

**C（adapter 对特定版本的 `Resume` 对象抛异常导致进入 "other" error 路径）+ G（PageTransitionOverlay 404 为 Vite HMR 残留，非根因）**

```text
链路还原：

1. 用户访问 /resumes/edit?versionNo=1
2. editingVersionNo = 1 → getResumeDetail(1) → /api/resumes/versions/1
3. 后端返回 200 + 完整 JSON（包含 profile/education/V2 字段）
4. request() 自动解包 result.data → Resume 对象
5. THEN: toResumeManagementViewModel(resume) → adapter 处理
   → 某字段/method 可能抛普通 Error（非 ApiClientError）
   → Promise reject 进入 .catch()
6. CATCH: isApiClientError(err) → false → 跳过 401/404 检查
   → 进入 "other" 分支 → console.error line 269
   → setResumeError("指定简历版本加载失败，请稍后重试。")
```

## 八、推荐最小修复方案

**方案 E（组合修复）：MyResumesPage 的 catch 增加 `getErrorStatus` 兜底函数，不依赖 `instanceof`。**

```ts
function getErrorStatus(error: unknown): number | undefined {
  // 首选：ApiClientError instance
  if (isApiClientError(error)) return error.status;
  // 兜底：plain object 上可能携带 status
  if (error && typeof error === 'object') {
    const e = error as Record<string, unknown>;
    if (typeof e.status === 'number') return e.status;
    if (typeof e.statusCode === 'number') return e.statusCode;
  }
  return undefined;
}
```

然后在 catch 中使用 `getErrorStatus(err)` 替代 `isApiClientError(err) && err.status === 401/404`。
