## 6. 关键决策

| 决策 | 说明 |
|------|------|
| 不设计多简历 resumes 表 | 用户只有一份主简历，通过 resume_versions 版本号管理 |
| 经历用 JSON 字段存储 | 不单独建 education_experiences / work_experiences / project_experiences 子表，Demo 阶段简化 |
| API 路径不带 /v1 | 阶段 3 使用 `/api/` 前缀，简化 Demo 阶段路径 |
| 匹配分析是核心亮点 | 必须有 JD-简历证据链、初筛风险、P0/P1 优化建议 |
| 不自动生成优化版简历 | 只给诊断和建议，用户手动修改（ADR-004） |
| 简历提取 Agent 阶段 3 暂不独立实现 | 简历详情页直接展示结构化数据，阶段 4 再实现 |
| Mock Agent 使用固定 JSON 或简单规则 | 不请求外部模型，不读取 LLM_API_KEY |
| 分析结果存 JSON 字段 | 推荐结果、匹配结果、对比结果均用 JSON 存储，灵活便于迭代 |
