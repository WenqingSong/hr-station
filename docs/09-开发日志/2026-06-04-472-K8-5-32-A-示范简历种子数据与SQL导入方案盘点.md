## make reset-up SQL 链路

| 检查项 | 结果 |
|--------|------|
| `make reset-up CONFIRM=yes` 做什么 | docker compose down -v（删除 volume）→ clean → up |
| 是否 drop DB | ✅ 删除 volume = DB 全清 |
| 会自动执行哪些 SQL | 仅 `init.sql`（容器 `/docker-entrypoint-initdb.d/01-init.sql`） |
| `server/sql/seed/tencent_jobs.sql` 是否自动执行 | ❌ 不自动，需 `make jobs-seed-apply` 手动导入 |
| 新增 SQL 文件需怎么处理 | 选项 A：追加到 `init.sql` 末尾；选项 B：新建后修改 docker-compose volume mount |

**为什么挂到同一用户**：评委一键登录 `13900139000` 后直接看到 8 份简历，选择任意一份即可体验对应功能。不需要切换账号。

## 四核心功能对示范简历内容的设计要求

| 功能 | 简历内容重点 | 建议 |
|------|-------------|------|
| **岗位匹配**（#1算法/#2后台/#3产品） | skills 与 JD 关键词重叠度；项目描述有量化指标；实习有 tech_stack+achievements | 简历内容要真实可信，与目标 JD 有明显交集 |
| **岗位推荐**（#4迷茫/#5不适合） | skills 面广但无 focus（迷茫）；学术强但缺工程经验（不适合） | 开放展示多种技能/经历，让推荐系统自行判断匹配度 |
| **版本对比**（#6A/#7B） | 两份简历差异点：skills 增加、项目量化、实习更多描述 | A版弱B版强；B版更丰富的 skills+achievements |
| **简历优化**（#8） | 故意留缺口：项目缺量化、技能与 JD 关键词不对齐、实习描述太简略 | 让 AI 自然地给出补量化/加关键词/细化职责等建议 |
