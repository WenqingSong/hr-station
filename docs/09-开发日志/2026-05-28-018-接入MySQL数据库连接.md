# 2026-05-28-018-接入MySQL数据库连接

## 1. 本次任务

为 Go 后端接入 MySQL 数据库连接能力，使用 `database/sql` + `go-sql-driver/mysql`，实现连接初始化、Ping 验证、连接池配置、Close 释放。在 main.go 中最小接入数据库初始化与关闭。

## 2. 修改范围

- `server/internal/database/mysql.go`：新建
- `server/cmd/server/main.go`：修改（接入数据库初始化与关闭）
- `server/go.mod` / `server/go.sum`：修改（引入 MySQL Driver）
- `docs/`：更新相关文档

## 3. 新增内容

- **database 基础设施包** `server/internal/database/mysql.go`：
  - `MySQL` 结构体（包装 `*sql.DB`）
  - `NewMySQL(cfg config.DatabaseConfig) (*MySQL, error)`：从 DSN 创建连接，DSN 为空时返回明确错误
  - `Ping(ctx context.Context) error`：带 context 的连接验证
  - `Close() error`：关闭连接释放资源
  - 连接池参数：MaxOpenConns=10、MaxIdleConns=5、ConnMaxLifetime=30m、ConnMaxIdleTime=10m
- **MySQL Driver 依赖** `github.com/go-sql-driver/mysql v1.10.0`

## 4. 修改内容

- `server/cmd/server/main.go`：
  - 新增 import：`context`、`time`、`database` 包
  - 加载 config 后初始化 MySQL：`database.NewMySQL(cfg.Database)`
  - 5s 超时 Ping 验证：`context.WithTimeout(context.Background(), 5*time.Second)`
  - 连接失败 `log.Fatalf` 终止启动
  - `defer mysqlDB.Close()` 确保退出时关闭连接
  - 启动日志输出 `[offer-catcher-server] MySQL connected`

## 5. 删除内容

- 无

## 6. 关键决策

1. **使用 database/sql + MySQL Driver**：不引入 GORM / sqlx，阶段 2 只需连接和 Ping
2. **连接池参数写死**：参数先写死在 database 包中，后续如需要再配置化
3. **DSN 为空返回明确错误**：避免 `sql.Open` 静默失败
4. **启动时 Ping 验证**：确保 MySQL 可达才启动 HTTP Server
5. **连接失败终止启动**：`log.Fatalf` 确保不会在数据库不可用时运行服务
6. **不把 DB 传入 Router**：当前阶段不需要在 handler 中使用数据库
7. **不把数据库状态接入 /healthz**：这留到 2-6
