## 根因判断

**`/login` 路由指向旧 `LoginPage`，该页面没有"评委一键体验"按钮。**

K8-5-31-B 只在 `AuthDialog` 中新增了按钮。当用户访问受保护路由 → RequireAuth 检测无 token → 重定向到 `/login?redirect=...` → 命中 `LoginPage` → **没有一键体验**。

## 修复方案比较

| 方案 | 做法 | 优点 | 推荐 |
|------|------|------|:---:|
| **A** | LoginPage 也加一键体验按钮 | 最小改动，1 文件 | ✅ |
| B | /login 路由改为打开 AuthDialog | redirect 和弹窗状态复杂 | ❌ |
| C | 删除 LoginPage + RegisterPage | 改动大，redirect 处理难 | ❌ |

## 推荐方案：A

**在 `LoginPage.tsx` 中复用与 `AuthDialog` 相同的一键体验逻辑。**

改动（最小）：
```
LoginPage.tsx:
  1. import { login } from "../../api/auth";
  2. 新增 demoLoading state + handleDemoLogin 函数
  3. 登录按钮下方新增 "🎯 评委一键体验" 按钮 + "或" 分隔线
  4. 复用 setAuthToken + navigate(safeRedirect) 登录成功流程
```

不改路由、不改 RequireAuth、不改 AuthDialog。

## 是否也需要给 RegisterPage 加？

**不建议**。RegisterPage 是注册流程，评委不需要注册。只需给 `/login` 页面补齐一键体验即可。
