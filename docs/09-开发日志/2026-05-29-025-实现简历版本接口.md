# 2026-05-29-025-实现简历版本接口

## 1. 本次任务

实现阶段 3-4 简历版本接口，包括：
- POST /api/resumes — 新增简历版本
- GET /api/resumes/current — 获取当前最新版本
- GET /api/resumes/detail — 获取简历详情（同 current）
- GET /api/resumes/versions — 获取版本列表
- GET /api/resumes/versions/{versionNo} — 获取指定版本

## 6. 关键决策

1. **单主简历**：不设计 resumes 多简历表，用户只有一份主简历
2. **版本管理**：每次 POST 创建新版本，版本号从 1 开始自增
3. **历史版本只读**：不支持编辑或删除历史版本
4. **所有字段可选**：降低填写压力，JSON 字段默认 `[]`
5. **NULL 处理**：数据库 JSON/TEXT 字段可为 NULL，Repository 使用 sql.NullString 处理
6. **创建后重读**：CreateVersion 后调用 FindByID 获取数据库生成的 created_at
7. **路径参数解析**：VersionDetail 从 URL 路径解析 versionNo（`/api/resumes/versions/` 前缀匹配 + 字符串截取）
8. **detail 等价 current**：GET /api/resumes/detail 返回当前最新版本，与 current 相同
9. **不引入新依赖**：使用已有的 database/sql + json.RawMessage

## 8. 当前风险

- `/api/resumes/versions` 和 `/api/resumes/versions/` 路由边界：Go ServeMux 中两者不同，versions/ 用于匹配版本号，versions 用于版本列表
- 并发创建版本时 version_no 可能冲突（当前未使用事务或锁，Demo 阶段可接受）
- 大字段 JSON 查询在数据量大时可能有性能问题（Demo 阶段不涉及）

## 9. 如何验证

```bash
# 启动服务
cd server && SERVER_PORT=18085 go run ./cmd/server

# 登录获取 token
TOKEN=$(curl -s -X POST http://localhost:18085/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"arthur@example.com","password":"123456"}' \
  | python3 -c "import sys,json; print(json.load(sys.stdin)['data']['token'])")

# 获取当前简历
curl -s http://localhost:18085/api/resumes/current -H "Authorization: Bearer $TOKEN"

# 新增简历版本
curl -s -X POST http://localhost:18085/api/resumes \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"name":"Arthur","target_city":"深圳","skills":["Go","MySQL"]}'

# 获取版本列表
curl -s http://localhost:18085/api/resumes/versions -H "Authorization: Bearer $TOKEN"

# 获取指定版本
curl -s http://localhost:18085/api/resumes/versions/1 -H "Authorization: Bearer $TOKEN"

# 无 token 访问（预期 40100）
curl -s http://localhost:18085/api/resumes/current
```
