# K8-5-34-A：P0 我的简历页不显示示范简历全链路盘点

## 一、本阶段目标

只读盘点：查清 `/resumes` 页面为什么显示"你还没有创建简历"的空状态，而示范账号明明有 9 份 resume_versions。

| 层级 | 当前实现 |
|------|---------|
| 路由 | `routes.tsx:40` → `/resumes` → `RequireAuth` → `ResumeManagementPage` |
| 页面挂载 | `useEffect` → `loadResumeManagementPageViewModel()` |
| loader | `viewModels.ts:101` → `getCurrentResume()` → `GET /api/resumes/current` |
| API | `resumes.ts:40` → `get<Resume>('/resumes/current')` |
| adapter | `resumeAdapter.ts:251` → `toResumeManagementViewModel(resume)` |
| 空状态判断 | `ResumeManagementPage.tsx:107` → `!vm \|\| !vm.hasResume` |
| hasResume 逻辑 | `resumeAdapter.ts:298` → `!!(p.name \|\| resume.name \|\| p.school)` |

| 后端 SQL | `GetCurrentByUserID` → `SELECT ... FROM resume_versions WHERE user_id=? ORDER BY version_no DESC LIMIT 1` |

**关键发现**：`ResumeManagementPage` 只调用 `GET /api/resumes/current`（取最新一条），NOT `GET /api/resumes/versions`。9 份 versions 在 `/resumes` 页面中不被展示。

## 六、空状态触发条件

```tsx
// ResumeManagementPage.tsx:107
if (!vm || !vm.hasResume) {
    return <EmptyState />;  // "你还没有创建简历"
}
```

`hasResume` 计算：
```ts
// resumeAdapter.ts:298
hasResume: !!(p.name || resume.name || p.school),
```

对于 demo 用户 version_no=9 的数据：
- `p.name` = "沈嘉言" (profile.name) → truthy ✅
- `resume.name` = "09-211后台开发-基础薄弱版-简历优化" → truthy ✅
- `p.school` = "湖南师范大学" → truthy ✅

**理论上 `hasResume` 应为 `true`，页面不应显示空状态。**

## 七、发现的关键类型不匹配

后端 `ResumeVersionResponse` 与前端 `Resume` 类型存在多处字段名不一致：

| 后端 JSON 字段 | 前端类型字段 | 问题 |
|---------------|------------|------|
| `version_no` (int) | `version` (string) | **字段名不同** — 前端读 `resume.version` 得到 `undefined` |
| 无 | `status` (required) | **后端不返回** — 渲染时 `STATUS_LABELS[undefined]` = `undefined` |
| 无 | `direction` (required) | **后端不返回** |
| 无 | `direction_label` (required) | **后端不返回** |
| 无 | `completeness` (required) | **后端不返回** |
| `created_at` | `updated_at` | **字段名不同** — 前端读 `resume.updated_at` 得到 `undefined` |

这些是表现层问题（display 显示异常），但不影响 `hasResume` 的判断逻辑。

**另外：当用户无 resume 时，后端返回 `{"code":0,"data":null}` → 前端 `toResumeManagementViewModel(null)` 会因 `null.profile` 抛出 TypeError，被 catch 捕获返回 null → 页面展示 EmptyState。这条路径对"真正无简历的用户"是正常行为。**

## 八、根因判断

通过只读全链路盘点，后端 API (`/api/resumes/current`) 对 demo 用户 (user_id=2) 返回完整有效数据（version_no=9，含 profile/internships/projects/skills 等）。这与"页面显示空状态"矛盾，代码路径分析 `hasResume` 应评估为 `true`。

**最可能的原因（按可能性排序）**：

### 场景 A：浏览器 localStorage 残留旧 token（可能性最高）

```
如果用户之前用其他手机号注册或登录过，localStorage 中的旧 token 指向非 user_id=2 的账号。
虽然 Navbar 显示"退出"（有登录态），但实际 user_id 可能不是 2。
该用户可能没有任何 resume_versions → getCurrentResume 返回 null → toResumeManagementViewModel(null) 抛出 TypeError → 页面展示 EmptyState。
```

**验证方式**：在浏览器 DevTools → Application → Local Storage → 查看 `offer_catcher_auth_token` 的值。退出后重新点击"评委一键体验"登录。

### 场景 B：前端 Vite dev server 热更新未生效

Nginx 配置（`nginx/conf.d/default.conf`）将 `/` 代理到 Vite `:5173`。如果 Vite HMR cache 不一致或服务端代码修改后未触发客户端刷新，可能导致前端页面仍使用旧逻辑。

**验证方式**：在浏览器中 Ctrl+Shift+R 硬刷新，或清空浏览器缓存。

### 场景 C：toResumeManagementViewModel 内部运行时异常

虽然表面上 `hasResume` 逻辑可以走通，但某些 V2 字段的类型转换（如 `expected_cities: '""'` 是双引号字符串）可能在别处引发未被注意的异常。

**验证方式**：在 `loadResumeManagementPageViewModel()` 的 try/catch 中加 `console.log` 观察。
