## 2. "推荐失败"复现结果

| 场景 | API 状态 | 前端状态 | 顶部显示 | 结论 |
|------|----------|----------|----------|------|
| Fast (resume_id=1) | 200, ready, 5 jobs | fast_done | 快速推荐 · 规则推荐 | ✅ |
| Quality (resume_id=1) | 200, **pending**, 0 jobs | deep_error | 推荐失败 · 已保留快速结果 | ❌ |
| Quality (resume_id=2-5) | ready | — | — | ✅（其他简历正常）|

**根因**：resume_id=1 的 quality profile 状态为 `stale`，`EnsureProfile` 返回 `pending`（异步生成 quality），前端轮询 10 次（20 秒）后超时进入 `deep_error`。

## 3. Fast / Quality API 对比

| 项 | Fast | Quality (resume_id=1) |
|----|------|----------------------|
| HTTP 状态 | 200 | 200 |
| profile_status | ready | pending |
| jobs count | 5 | 0 |
| generated_by | mock_agent | — |
| pipeline_mode | fast_rule | — |
| profile_dominant | algorithm_research | None |

**结论**：Fast 和 Quality 在后端是同一套 mock 引擎（tagMatrix + V3 builders），字段完全一致。Quality 的区别仅在于 `qualityMode=true` 触发 Judge + rerank，但 LLM disabled 下和 Fast 几乎相同。

## 4. 前端状态机诊断

| 状态变量 | 当前用途 | 问题 |
|---------|---------|------|
| `phase` | RecPhase（fast_loading/deep_loading/deep_done/deep_error 等） | deep_error 触发"推荐失败" |
| `deepResult` | Quality API 返回的 ViewModel | 当 profile=pending 时为空 |
| `fastResult` | Fast API 返回的 ViewModel | deep_error 时作为 fallback 显示 |
| `activeResult` | `phase=="deep_done" ? deepResult : fastResult` | deep_error 时用 fastResult ✅ |
| `headerLabel` | 从 phase 派生 | deep_error → "推荐失败 · 已保留快速结果" ✅ |

**问题链**：
1. Quality profile `stale` → `EnsureProfile` 返回 `pending`
2. `recommendWithMock` 检测 profileStatus≠ready → early-return 空 jobs
3. 前端 `pollQuality` 收到 `profileStatus="pending"`，进入轮询
4. 10 次轮询后超时 → `setDeepOverlayStatus("error")` + `setPhase("deep_error")`
5. `headerLabel` 从 `phase="deep_error"` 派生 → "推荐失败 · 已保留快速结果"

**结论**：前端逻辑正确，问题在后端 Quality profile 未及时生成。

## 5. Fast / Deep 展示密度诊断

| 区域 | Fast 当前展示 | Deep 当前展示 | 问题 |
|------|-------------|-------------|------|
| 左侧卡片 | whyRankedHere + evidence + risk | 同 Fast | Fast 已展开展示，无简化模式 |
| 中间详情 | 6 区块（完整） | 同 Fast | 无差异化 |
| 顶部 headerLabel | "快速推荐 · 规则推荐" | "深度推荐 · 规则兜底" | 仅文案不同 |

**根因**：页面未根据 `phase` / `profileType` 区分展示密度。Fast 和 Deep 共用同一个 JSX 渲染逻辑。

**期望**：Fast 应简化（仅卡片 + 简短详情），Deep 应完整（当前 6 区块）。

## 6. recommendation_results 表诊断

| 字段/能力 | 当前状态 | 是否满足持久化目标 |
|-----------|---------|:--:|
| `id` | bigint PK | ✅ |
| `user_id` | FK to users | ✅ |
| `resume_id` | FK to resumes | ✅ |
| `result_json` | JSON（推荐结果） | ✅ |
| `created_at` | datetime | ✅ |
| `generation_tier` | ❌ 缺失 | ❌ 无法区分 fast/quality |
| `generated_by` | ❌ 缺失 | ❌ 无法判断生成来源 |
| 最新结果查询 | ❌ 无 API | ❌ 没有 GET latest 接口 |
| 结果复用 | ❌ 只存不读 | ❌ 页面每次 POST 重新生成 |

**实际表结构**：
```sql
CREATE TABLE recommendation_results (
  id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  user_id BIGINT UNSIGNED NOT NULL,
  resume_id BIGINT UNSIGNED NOT NULL,
  result_json JSON NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  KEY idx_rec_user_created (user_id, created_at),
  KEY idx_rec_resume (resume_id)
);
```

**缺失字段**：`generation_tier VARCHAR(20)`, `generated_by VARCHAR(50)`.

## 7. 推荐结果保存与读取链路

**当前实际链路**：
```
页面进入 → POST /api/jobs/recommend → 重新生成 → 保存 recommendation_results
页面再进入 → POST /api/jobs/recommend → 重新生成 → 又保存一份（重复）
```

**目标链路差距**：
```
1. ❌ 无 GET /api/jobs/recommend/latest?resume_id=X 读取最新结果
2. ❌ 无 upsert 策略（每次 INSERT，不覆盖旧结果）
3. ❌ 无 generation_tier 区分
4. ❌ 页面进入时无法判断是否已有结果
```

## 8. ResumeProfile 生成链路

**当前已支持**：
- ✅ `EnsureProfile` 在推荐 API 调用时按需生成
- ✅ Fast profile 同步生成（毫秒级）
- ✅ Quality profile 异步生成（goroutine）
- ✅ profile stale 检测与 MarkStale

**当前不支持**：
- ❌ 保存简历后触发 profile 生成（需手动调 /profile/regenerate）
- ❌ 启动时 Backfill 缺失 profile（需按需调用）
- ❌ Quality profile 异步生成没有完成通知机制（只能轮询）
- ❌ Quality profile 异步生成可能因 goroutine 问题未完成

**quality profile stale 问题**：resume_id=1 的 quality profile 为 stale，异步重新生成未完成 → pending → 前端超时。

## 9. 根因结论

| 级别 | 问题 | 证据 |
|:--:|------|------|
| **P0** | Quality API 对 resume_id=1 返回 pending/空 → 前端超时显示"推荐失败" | quality profile stale, async generation not completing |
| **P0** | 推荐结果每次 POST 重新生成，不读取历史 | recommendation_results 只存不读 |
| **P1** | Fast 和 Deep 展示密度完全相同，无差异化 | 页面共用同一套 JSX，不区分 phase |
| **P1** | recommendation_results 无法区分 fast/quality | 表缺少 generation_tier 字段 |
| **P2** | Quality profile 异步生成无完成通知 | 前端只能盲轮询直到超时 |
| **P2** | 保存简历后不触发 profile 生成 | 依赖手动 regenerate |
