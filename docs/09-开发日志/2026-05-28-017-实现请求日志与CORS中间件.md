# 2026-05-28-017-实现请求日志与CORS中间件

## 1. 本次任务

实现 Go 后端的基础中间件能力，包括 RequestLogger、CORS、Recover 三个中间件，并在 HTTP Router 中接入中间件链。

## 3. 新增内容

- **RequestLogger 中间件** `server/internal/middleware/logger.go`：
  - 自定义 `responseWriter` 包装器，捕获 `WriteHeader` 的状态码
  - 记录 method / path / status / duration / remote / user_agent
  - 日志格式：`method=GET path=/healthz status=200 duration=123µs remote=127.0.0.1:12345 user_agent=curl/8.0`
  - 不打印请求 body、Authorization、Cookie、敏感信息
- **CORS 中间件** `server/internal/middleware/cors.go`：
  - 允许 `http://localhost:5173` 和 `http://127.0.0.1:5173`
  - 本地开发便利：`isAllowedOrigin()` 函数允许所有 localhost/127.0.0.1 端口
  - OPTIONS 预检返回 204 No Content
  - 设置 Access-Control-Allow-Methods / Allow-Headers / Allow-Credentials / Max-Age
  - 动态设置 Access-Control-Allow-Origin 为请求 Origin（如匹配允许列表）
- **Recover 中间件** `server/internal/middleware/recover.go`：
  - 使用 `defer` + `recover()` 捕获 panic
  - 使用 `log.Printf` 记录 panic 值和 `debug.Stack()`
  - 返回统一错误响应 `{code:50000, message:"internal server error", data:null}`
  - 复用 `apperror.ErrInternal` 和 `response.Error()`

## 4. 修改内容

- `server/internal/http/router.go`：
  - 在 `NewRouter()` 中组装中间件链
  - 包装顺序：`handler := RequestLogger(mux)` → `handler = CORS(handler)` → `handler = Recover(handler)`
  - 执行顺序：Recover → CORS → RequestLogger → mux
  - 新增 import `offer-catcher/server/internal/middleware`

## 5. 删除内容

- 无

## 6. 关键决策

1. **中间件链在 NewRouter() 组装**：不修改 main.go，中间件链完全在 http 包内完成
2. **执行顺序 Recover → CORS → RequestLogger**：Recover 最外层捕获所有 panic，CORS 其次处理预检，RequestLogger 最内层记录实际请求
3. **OPTIONS 不记录日志**：CORS 短路返回 204，不经过 RequestLogger，避免冗余日志
4. **CORS 开发环境宽松策略**：`isAllowedOrigin()` 允许任何 localhost/127.0.0.1 端口，方便不同端口的前端开发
5. **Recover 复用 AppError 和 response**：保持统一错误格式一致性
6. **responseWriter 默认状态码 200**：如果 handler 未调用 WriteHeader，记录默认值 200
