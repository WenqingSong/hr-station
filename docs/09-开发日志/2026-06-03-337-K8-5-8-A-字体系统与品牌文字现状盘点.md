## 六、三套字体策略建议

### 方案 1：零依赖系统字体栈（推荐渐进式第一步）

```css
font-family:
  "HarmonyOS Sans SC",
  "MiSans",
  "Source Han Sans SC",
  "Noto Sans SC",
  "PingFang SC",
  "Microsoft YaHei",
  "Inter",
  system-ui,
  sans-serif;
```

| 维度 | 说明 |
|------|------|
| 适用范围 | 全局 body 字体（取代 Tailwind 默认） |
| 优点 | 零依赖、零文件体积、零维护成本、跨平台兼容 |
| 风险 | 字体效果不可控，完全依赖用户系统安装的字体 |
| 是否推荐 | **推荐作为基线**，不改代码即可通过 theme.css 全局声明 |

---

### 方案 2：品牌字单独字体栈（当前已部分实现）

```css
font-family:
  "Alimama ShuHeiTi",
  "HarmonyOS Sans SC",
  "MiSans",
  "Noto Sans SC",
  system-ui,
  sans-serif;
```

| 维度 | 说明 |
|------|------|
| 适用范围 | 仅 Navbar 品牌文字 + Banner 标题等少量展示文案 |
| 优点 | 品牌字有差异化视觉，不与正文字体混用 |
| 风险 | "Alimama ShuHeiTi" 用户安装率极低，实际效果可能回落到 HarmonyOS/MiSans/Noto |
| 是否推荐 | **可保留当前方案**，但需接受 fallback 即实际效果 |

---

### 方案 3：npm 开源字体包方案（不推荐现阶段实施）

使用 `@fontsource/inter` 或 `@fontsource/noto-sans-sc`：

```bash
npm install @fontsource/inter
```

然后在入口文件 `import '@fontsource/inter'`。

| 维度 | 说明 |
|------|------|
| 适用范围 | 全局正文（Inter）+ 中文正文（Noto Sans SC） |
| 优点 | 字体效果可控，跨平台一致性高 |
| 风险 | 中文字体包体积大（Noto Sans SC 约 10MB+），首屏加载慢；不提供中文品牌 / 标题专用字体 |
| 是否推荐 | **不推荐现阶段引入**，除非确需可控中文标题字体且接受首屏体积代价 |
