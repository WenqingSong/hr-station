# 2026-05-29-038-腾讯招聘信息接入方案

## 1. 本次任务

阶段 4-1.2.1：腾讯招聘信息接入方案。基于 4-1.2.0、4-1.2.0.1、4-1.2.0.2 三个探测阶段的结论，编写正式的腾讯招聘信息接入方案文档。

本次只做方案设计，不写同步脚本，不改数据库，不改后端接口，不创建 data 目录。

## 2. 方案依据

| 依据文档 | 关键结论 |
|---------|---------|
| 腾讯招聘公开接口探测报告（4-1.2.0） | 岗位列表接口和字典接口确认可用 |
| 腾讯招聘岗位详情接口探测报告（4-1.2.0.1） | 5 个候选路径全部 404，后由 4-1.2.0.2 修正 |
| 腾讯招聘必要接口确认报告（4-1.2.0.2） | 详情接口已确认（getJobDetailsByPostId），返回完整 JD |

4-1.2.0.1 的"未发现详情接口"结论已被 4-1.2.0.2 修正。本方案以 4-1.2.0.2 为准。

## 3. 接入范围

| 接口 | 优先级 | 是否接入 |
|------|--------|---------|
| 岗位列表接口 | P0 | ✅ 必须 |
| 岗位详情接口 | P0 | ✅ 必须 |
| 字典接口 | P1 | ⬜ 可选 |
| 岗位族接口 | P2 | ⬜ 可选 |
| 项目映射接口 | P2 | ⬜ 可选 |

明确不接入：登录、投递、收藏、用户中心、应聘进度、简历上传、验证码等接口。

## 4. 最小接口决策

- **最少需要 2 个接口**：岗位列表 + 岗位详情
- **必须接入**：列表接口（获取 postId）+ 详情接口（获取完整 JD）
- **可选接入**：字典接口
- **数据同步策略**：先列表后详情的两步方案
- **字段映射核心**：desc→description, request→requirements

## 5. 同步策略

采用**低频同步 + 本地缓存**策略：

1. 前端不直接请求 join.qq.com
2. 后端业务接口不实时代理 join.qq.com
3. 每次推荐/匹配/前端展示全部读取本地 jobs 表
4. 列表接口间隔 ≥ 2 秒/页
5. 详情接口间隔 ≥ 3 秒/条
6. 出现 403/429/验证码立即停止

## 6. 字段映射方向

| 腾讯详情字段 | 内部字段 | 映射方式 |
|-------------|---------|---------|
| title | title | 直接映射 |
| desc | description | 直接映射 |
| request | requirements | 直接映射 |
| tidName | category | 直接映射 |
| intentionBGDList[0].showTitle | department | 取第一个 |
| workCityList | city | 逗号拼接 |
| projectName | job_type | 直接映射 |
| postId | external_id | 直接映射 |
| 完整响应 | raw_json | JSON 存储 |

后续 jobs 表适配方向：新增 external_source、external_id、raw_json、data_quality、is_featured、synced_at 等字段。**本次不改 SQL。**
