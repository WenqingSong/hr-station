## 4. Makefile 方案

### 命令语义

| 命令 | 行为 | 清 volume | 需 CONFIRM |
|------|------|----------|-----------|
| `make restart` | 软重启 = stop + up | ❌ | ❌ |
| `make restart-soft` | 同 restart | ❌ | ❌ |
| `make reset` | 停止 + 清 volume | ✅ | ✅ |
| `make reset-up` | 停止 + 清 volume + 重启 | ✅ | ✅ |

### 主推荐

- `make restart` = 软重启，不清 volume（行业惯例）
- `make reset` / `make reset-up` = 清 volume（破坏性，需确认）

### make up 标准流程

ensure-env → doctor → init → infra-up → db-check → backend-up → web-up → health → 专业输出

### 新增命令

- `make restart-soft`：软重启
- `make reset`：停止并清 volume（需 CONFIRM=yes）
- `make reset-up`：清 volume + 重启（需 CONFIRM=yes）
- `make nginx-logs`：Nginx 日志
- `make frontend-logs`：前端日志（= web-logs 别名）

## 5. Docker Compose 方案

### 文件结构

- `docker-compose.yml`：基础服务定义
- `docker-compose.dev.yml`：开发环境覆盖（源码挂载、调试端口）
- `docker-compose.prod.yml`：生产环境覆盖（构建镜像、不挂载源码）

### 服务清单

- mysql：现有，保留
- nginx：新增，反向代理
- backend：远期目标（当前保持本地进程）
- frontend：远期目标（当前保持本地进程）

### 渐进策略

B.3 先接入 Nginx 到 docker-compose，前后端仍本地进程管理。后续可选容器化。

## 6. Nginx 方案

### 统一入口

`http://localhost/`

### 代理策略

- `/` → frontend:5173
- `/api/` → backend:8080
- `/healthz` → backend:8080/healthz

### 关键配置

- proxy_set_header 标准四项
- Vite HMR WebSocket 支持
- SSE / 长连接预留
- 开发/生产 Nginx 配置区分

## 7. CORS 方案

### 当前问题

- allowedOrigins 硬编码 localhost:5173
- isAllowedOrigin() 允许任何 localhost 端口（宽松）

### 标准化方向

- 新增环境变量 CORS_ALLOWED_ORIGINS（逗号分隔）
- 开发环境允许 localhost
- 生产环境只允许正式域名
- Nginx 同源后 CORS 可收紧但仍保留

## 8. dev/prod 环境区分

| 维度 | 开发 | 生产 |
|------|------|------|
| APP_ENV | development | production |
| compose 文件 | docker-compose.dev.yml | docker-compose.prod.yml |
| CORS | localhost | 正式域名 |
| MySQL 端口 | 暴露 | 不暴露 |
| reset 命令 | 可用 | 禁用 |
| 日志级别 | debug | info |

### .env.example 安全修复

| 变量 | 当前值 | 修复 |
|------|--------|------|
| LLM_API_KEY | sk-kpy... | 清空 |
| LLM_BASE_URL | https://tokenhub... | 清空 |
| LLM_ENABLE | true | 改为 false |
