## 2. 背景

4-3.5.B 已完成战略差异化确认，项目定位从"岗位推荐工具"升级为"投递前决策与简历初筛优化系统"。三个核心杀手锏中，**投递边界与优化停止条件**是杀手锏一，也是本项目与官网 Offer捕手 最核心的差异化能力。

学生真正需要的不只是"继续优化简历"的建议，而是知道**什么时候可以停止优化并开始投递**。

## 3. 核心设计

### 3.1 核心原则

- 优化不是无底洞
- 投递边界只针对当前岗位，不评价用户整体能力
- 投递判断必须基于 JD 和简历证据
- 区分"短期投递优化"和"长期能力提升"

### 3.2 apply_readiness 枚举

| 值 | 定义 | 投递建议 |
|---|------|---------|
| `ready_to_apply` | 核心能力已覆盖，可以投递 | 建议投递 |
| `quick_fix_before_apply` | 有匹配基础，存在 2-3 个短时可修复问题 | 快速修复后投递 |
| `not_ready_for_this_role` | 与岗位关键要求差距明显 | 不建议投递该岗位 |
| `insufficient_information` | 信息不足，无法稳定判断 | 先补充信息 |

### 3.3 optimization_stop_signal 枚举

| 值 | 定义 | 对应 apply_readiness |
|---|------|---------------------|
| `stop_and_apply` | 停止优化，开始投递 | ready_to_apply |
| `fix_top_3_then_apply` | 修复 Top 3 后投递 | quick_fix_before_apply |
| `needs_more_evidence` | 需要补充经历证据 | not_ready_for_this_role / insufficient_information |
| `target_role_mismatch` | 目标岗位方向不匹配 | not_ready_for_this_role |

### 3.4 映射关系

- ready_to_apply → stop_and_apply
- quick_fix_before_apply → fix_top_3_then_apply
- not_ready_for_this_role → needs_more_evidence 或 target_role_mismatch
- insufficient_information → needs_more_evidence

禁止矛盾输出（如 ready_to_apply + needs_more_evidence）。

### 3.5 Top 3 快速优化项

每个优化项包含：issue / why_it_matters / action / example_reference / self_check_question / estimated_effort。

estimated_effort 枚举：within_10_min / within_30_min / within_60_min / long_term。

quick_fix_before_apply 状态下，top_fix_items 中不应出现 long_term 类型作为主要投递前动作。

### 3.6 长期提升项

long_term_improvement 与 top_fix_items 分开展示，附带固定提醒：

> 以下内容属于长期提升方向，不建议因为这些点延后当前投递。
