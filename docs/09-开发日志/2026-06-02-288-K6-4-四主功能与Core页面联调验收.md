## 5. 发现的问题与修复

### 问题 1：jobs 列表接口 500（阻断）

- **根因**：jobs 表 `summary` 列为 NULLABLE（`text YES NULL`），但 Go model `Job.Summary` 为 plain `string`，`database/sql` 扫描 NULL → string 时报错 "converting NULL to string is unsupported"。
- **影响**：`GET /api/jobs`、`GET /api/jobs/{id}` 均返回 500，导致岗位列表/详情不可用，推荐和匹配分析也无法获取岗位数据。
- **修复**：`server/internal/repository/job_repository.go` `scanJobRow()` — 使用 `sql.NullString` 扫描 `summary` 列，再赋值 `j.Summary = summary.String`。
- **修复范围**：仅 1 个文件，+8 / -3 行。无其他列受影响（slogan 为 NOT NULL，description/requirements 当前数据非 NULL）。
- **是否最小必要**：是。只修复了阻塞 API 调用的明确 bug，未改模型、API 契约或业务逻辑。

### Core 模式前端缺失说明

当前前端 `ResumeOptimizationPage.tsx` 使用 `loadResumeOptimizationViewModel()` → `runResumeOptimization()` → `POST /resumes/optimize`，**未传入 `mode` 参数**。`agents.ts` 的 `ResumeOptimizationRequest` 类型不包含 `mode` 字段。

**影响**：目前 `/resume-optimization` 页面只走标准优化模式，不能从 UI 触发 core 模式。core 模式仅可通过 curl/API 触发。

**建议后置处理**：K6-3 将"前端未接入"标记为 P2，建议在后续业务阶段补充。
