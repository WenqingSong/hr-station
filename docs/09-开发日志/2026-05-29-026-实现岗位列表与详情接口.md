## 6. 关键决策

1. **keyword 使用 LIKE 匹配**：匹配 title / department / description / requirements 四个字段
2. **city / category 精确匹配**：简单筛选，不做模糊匹配
3. **limit 默认 20 最大 50**：防止一次查询返回过多数据
4. **offset 不能小于 0**：非法值默认为 0
5. **SQL 拼接安全**：使用占位符，动态条件只拼接固定 SQL 片段，用户输入作为 args 传入
6. **列表返回 total**：先 COUNT 再 SELECT，支持前端分页展示
7. **路径参数解析**：Detail 从 `/api/jobs/` 前缀截取 ID，与简历版本路径解析模式一致
8. **错误码 43001**：岗位不存在，与岗位模块范围 43000-43999 一致
9. **不引入新依赖**：使用已有的 database/sql + json.RawMessage

## 8. 当前风险

- `/api/jobs` 和 `/api/jobs/` 路由边界：Go ServeMux 中两者不同，jobs/ 用于匹配岗位 ID，jobs 用于列表
- keyword LIKE 匹配在大数据量时可能有性能问题（Demo 阶段 8 条种子数据不涉及）
- count + select 不是原子操作，数据频繁变动时 total 可能不准确（Demo 阶段不涉及）

## 9. 如何验证

```bash
# 启动服务
cd server && SERVER_PORT=18086 go run ./cmd/server

# 登录获取 token
TOKEN=$(curl -s -X POST http://localhost:18086/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"arthur@example.com","password":"123456"}' \
  | python3 -c "import sys,json; print(json.load(sys.stdin)['data']['token'])")

# 获取岗位列表
curl -s http://localhost:18086/api/jobs -H "Authorization: Bearer $TOKEN"

# 带筛选的岗位列表
curl -s "http://localhost:18086/api/jobs?keyword=Go&city=深圳&limit=10" -H "Authorization: Bearer $TOKEN"

# 获取岗位详情
curl -s http://localhost:18086/api/jobs/1 -H "Authorization: Bearer $TOKEN"

# 非法岗位 ID
curl -s http://localhost:18086/api/jobs/abc -H "Authorization: Bearer $TOKEN"

# 不存在的岗位
curl -s http://localhost:18086/api/jobs/999 -H "Authorization: Bearer $TOKEN"

# 未登录访问（预期 40100）
curl -s http://localhost:18086/api/jobs
```
