## 推荐 UI 方案

**方案 A：复用 CertificateDraft 类型**

```tsx
// 语言考试也作为 certificateDrafts 的一项，通过 type="language_exam" 区分
// 只需在 UI 上新增"添加外语考试"按钮，将考试以 CertificateDraft 形式加入列表
```

| 方案 | 优点 | 缺点 | 推荐 |
|------|------|------|:---:|
| **A: 复用 CertificateDraft** | 代码量小，复用已有 CRUD helper；payload 自然合并 | 考试 UI 与证书略有不同（无需 issuedAt、type 自动设为 language_exam） | ✅ 推荐 |
| **B: 独立 LanguageExamDraft** | UI 专属字段，考试类型支持自由填写 | 需新增 state + helper + payload 合并逻辑；两套列表管理 | 过度设计 |

**推荐实现结构：**

```
外语考试 / 等级
[考试类型 Input] [分数 / 等级 Input] [删除]
+ 添加外语考试

证书
[证书名称] [类型 Select] [级别] [分数] [时间] [删除]
+ 添加证书
```

- "添加外语考试"自动设置 `type="language_exam"`，`name` 为考试名称（自由输入）
- "添加证书"维持现有逻辑
- 外语考试与普通证书合并到 `certificateDrafts[]` 统一管理
- 空列表提示："暂无外语考试，可添加 CET-4、CET-6、雅思、托福、日语等级等"

## 推荐 payload 方案

**后端已兼容，无需后端改动。** 多条 `type="language_exam"` 证书自然存在于 certificates 数组：

```json
"certificates": [
  {"name":"CET-4","type":"language_exam","level":"CET-4","score":"503","issued_at":""},
  {"name":"CET-6","type":"language_exam","level":"CET-6","score":"585","issued_at":"2025-06"},
  {"name":"阿里云 ACP","type":"cloud_certificate","level":"ACP","score":"","issued_at":"2026-05"}
]
```

payload 构造只需将 L618 的单条 `langExamCert` 改为多条 `certificateDrafts.filter(c => c.type === "language_exam")`。
