## 5. "怎么补强"字段链路诊断

| 环节 | 字段 | 当前结果 | 问题 |
|------|------|---------|------|
| 后端 Go MatchEvidence | `Risk` | **不存在** | 只有 Requirement/ResumePoint/Judgement/ResumeModule |
| DB result_json | `evidence_chain[0].risk` | **null** | 后端不生成 |
| API 返回 | `evidence_chain[0].risk` | **null** | |
| TS EvidenceItem | `risk_note` | **undefined** | 后端无对应数据 |
| Adapter 映射 | `riskNote: item.risk_note` | **""** | 空 |
| 组件渲染 | `ev.riskNote \|\| "—"` | **"—"** | 全部显示"—" |

### 根因

**后端 `MatchEvidence` 结构体缺 `Risk` 字段**。`buildMatchEvidenceChain()` 不设置 risk/fix action。

### top_fix_items 数据可用但未关联

`top_fix_items[0]` 包含丰富字段：
```json
{ "issue": "...", "action": "补充Go/MySQL/Redis...", "why_it_matters": "...", "estimated_effort": "15-30分钟", "example_reference": "...", "self_check_question": "..." }
```

但这些项未按 `requirement` 关联到 evidence_chain 行，前端无法自动匹配。

## 11. 推荐修复方案

### A. 最小可落地方案 (纯前端)

| 项 | 内容 |
|----|------|
| "怎么补强" | `ev.riskNote \|\| topFixItems[行号]?.action \|\| gapPoints[行号] \|\| "补充与该要求直接相关的项目证据"` |
| JD 关键词 | 隐藏模块或显示 `jobRequirements.slice(0,4).join(" / ")` |
| 右侧栏 | 展示 resumeEvidence.slice(0,3) 列表 |

**优点**: 只需改前端，无需重启服务
**缺点**: 补强内容按行号关联，不够精准

### B. 推荐方案 (后端+前端)

| 项 | 内容 |
|----|------|
| 后端 MatchEvidence | 加 `Risk string` + `FixAction string` |
| 后端 buildMatchEvidenceChain | 补 evidence risk action (从 top_fix_items/gap_points 提取) |
| 前端 EvidenceItem | 加 `risk_note?: string` + `fix_action?: string` |
| 前端证据链渲染 | `ev.fix_action \|\| ev.risk_note \|\| "—"` |
| JD 关键词 | 后端加 `job_keywords` 或前端从 `jobRequirements` 截取 |
| 右侧栏 | 独立组件展示 resumeEvidence/skillTags/projectCount |

**优点**: 精准关联，冲奖级质量
**缺点**: 需修改 4-5 个文件

### C. 不建议现在做

| 项 | 原因 |
|----|------|
| 完整三栏 CSS 重构 | 宽度已有 flex-1 + 320px/300px，结构可用 |
| 右侧简历全文展示 | 右侧已有限空间，正文放中间更合理 |
| top_fix_items 按 requirement 精确关联 | 需要后端加 requirement 字段在 top_fix_items 上，复杂度高 |
