## 4. 方案选择

### 方案 A：全容器开发模式（已放弃继续）

```
Docker Compose：
- MySQL + Nginx + Backend + Frontend

所有服务容器化：
- Backend: Dockerfile + air 热重载
- Frontend: Dockerfile + Vite HMR
- node_modules volume
- Go module cache volume
```

放弃原因：
1. 对当前 Demo 阶段过重
2. 后端容器调试困难
3. 前端容器 HMR 响应慢
4. 配置复杂度高（volume 管理、文件监听、缓存映射）
5. 开发效率不如本机运行

### 方案 B：混合式开发环境（最终采用）

```
Docker Compose：MySQL + Nginx
本机进程：Backend (go run/air) + Frontend (npm run dev)
Nginx：通过 host.docker.internal 代理宿主机服务
```

选择原因：
1. Demo 稳定交付优先，不需要云原生架构完备性
2. Go 后端本机运行更利于调试
3. Vite 本机运行 HMR 更快
4. MySQL/Nginx 容器化收益高成本低
5. make up 仍然是一键启动
6. 生产部署后续单独设计

## 5. 最终开发环境架构

```
Docker Compose：
  MySQL :3306     → 数据库服务
  Nginx :80       → 统一反向代理

Host 本机后台进程：
  Backend :8080   → Go 服务（go run / air）
  Frontend :5173  → Vite 开发服务器

Nginx 代理规则：
  /          → host.docker.internal:5173
  /api/      → host.docker.internal:8080
  /healthz   → host.docker.internal:8080/healthz
```

## 6. make 命令契约

### 用户语义冻结

| 命令 | 语义 |
|------|------|
| `make up` | 启动完整混合式开发环境 |
| `make down` | 关闭完整混合式开发环境，不清 volume |
| `make restart` | 软重启，不清 volume |
| `make restart-soft` | 同 restart |
| `make reset` | 清 volume，必须 CONFIRM=yes |
| `make reset-up` | 清 volume 后重启，必须 CONFIRM=yes |
| `make status` | 查看完整开发环境状态 |
| `make logs` | 查看完整开发环境日志 |

### make up 内部实现

```
1. ensure-env
2. doctor
3. init
4. infra-up（Docker Compose: MySQL + Nginx）
5. db-check
6. backend-up（本机后台进程）
7. web-up（本机后台进程）
8. health
9. 专业输出（含 http://localhost/）
```

**命令语义不变，只调整内部实现。**

## 7. Nginx 代理方向

### 代理规则

```nginx
/          → http://host.docker.internal:5173
/api/      → http://host.docker.internal:8080
/healthz   → http://host.docker.internal:8080/healthz
```

### 关键约束

1. `/api/` 不 strip `/api` 前缀，后端收到的路径保持 `/api/...`
2. Vite HMR WebSocket 支持（Upgrade + Connection headers）
3. SSE / 长连接预留（proxy_buffering off + proxy_read_timeout 300s）
4. Linux 需要 `extra_hosts: host.docker.internal:host-gateway`

## 8. CORS 后续方向

### 推荐方式（Nginx 同源代理）

```
http://localhost/ → /api/ → host.docker.internal:8080
→ 同源请求，无需 CORS
```

### 开发直连方式

```
http://localhost:5173 → http://localhost:8080/api
→ 需要 CORS 支持
```

### 后续 R.3 实现

- CORS_ALLOWED_ORIGINS 环境变量
- CORS_ALLOWED_METHODS 环境变量
- CORS_ALLOWED_HEADERS 环境变量
- CORS_ALLOW_CREDENTIALS 环境变量
