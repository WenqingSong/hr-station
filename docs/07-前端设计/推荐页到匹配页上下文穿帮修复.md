# 推荐页到匹配页上下文穿帮修复

> 阶段：5-8.1 | 状态：已完成 | 日期：2026-05-31

## 1. 本阶段目标

修复 P1 穿帮点 R-2：推荐页"进行岗位匹配分析"按钮跳转到 `/match` 时仅传 `resumeId`，不传 `jobId`。

## 2. 原问题

`RecommendationDetail.tsx` L110：

```typescript
navigate(`/match?resumeId=${encodeURIComponent(currentResumeId)}`)
```

影响：
- 用户从推荐页点击某条推荐岗位的"进行岗位匹配分析"
- 匹配页因缺少 `jobId`，fallback 到默认岗位 `mockSelectedJob`
- 演示时出现上下文断裂：用户看的是推荐岗位 A，匹配页显示的却是默认岗位 B

## 3. 修复范围

**仅修改 1 行代码**：`web/src/app/components/RecommendationDetail.tsx` L110。

## 4. 修改文件

| 文件 | 变更 | 说明 |
|------|:--:|------|
| `web/src/app/components/RecommendationDetail.tsx` | 修改 1 行 | L110 navigate 参数添加 jobId |

## 5. jobId 来源

`RecommendedJobViewModel` 已有 `jobId` 字段：
- `types/agent.ts` → `RecommendedJobItem.job_id`
- `mocks/recommendation.ts` → 每条 mock 推荐结果有 `job_id`
- `adapters/recommendationAdapter.ts` → `RecommendedJobViewModel.jobId = job.job_id`
- `RecommendationDetail.tsx` L17 → `const firstJob = recVm.recommendedJobs[0]` → `firstJob.jobId` ✅

**无需修改 types/mocks/adapters。**

## 6. 修复前后对比

| 项目 | 修复前 | 修复后 |
|------|------|------|
| 跳转 URL | `/match?resumeId=xxx` | `/match?jobId=job_backend_001&resumeId=xxx` |
| 匹配页 jobId | `null` → fallback 默认岗位 | `job_backend_001` → 展示对应岗位 |
| 演示连续性 | ❌ 上下文断裂 | ✅ 上下文一致 |

## 7. resumeId 保持

修复后 `resumeId` 仍然通过 `encodeURIComponent(currentResumeId)` 传递，与原逻辑一致。
